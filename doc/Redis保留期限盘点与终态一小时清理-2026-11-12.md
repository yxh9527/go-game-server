## 终态快照代码行为

- SETTLED／VOIDED 以原 Settlement.CompletedAt 起计；EXPIRED 以原 Reservation.ExpiresAt 起计，满 3600 秒即过期。缺少上述旧字段时使用原 UpdatedAt，后续保存不会刷新其后备时间。
- 不再因 ReportsIndexed=false、原流水未写完或终态附带待处理字段延长此快照期限。已存入 MySQL 的原文和 ES 历史不随快照删除。
- 活跃 BETTING／RESERVED 不能仅因创建超过 1 小时被误删；原预留到期处理仍负责推进为 EXPIRED。
- 查询会即时判断过期，不读取旧 Redis 归档。过期后查询返回 ROUND_NOT_FOUND，不能再按该快照取得历史回执；服务没有新增永久 tombstone 或另一个 Redis 归档。
- 后台沿用 5 秒循环分批删除，每轮最多尝试 100 条，整体最多 1 秒，避免故障时逐条超时长时间持锁。物理清理由轮询分批执行，并非 Hash 每个字段有原生 TTL；积压或 Redis 不可用时可能延迟，访问时仍检查期限。
- Redis Lua 在删除前再次核对当前状态和原终态时间，避免旧实例依据过期内存删除当前较新的活跃状态。删除同一局的原快照重试集合项；不改玩家余额、带入或其他局。
- 旧归档原本在 7／30 天后才写入，均已超过新的一小时期限。加载及原定时循环用 UNLINK 移除固定旧归档键，后台释放内存，不用同步 DEL 大 Hash。
- 本轮不额外执行线上 Redis 清理命令、不重启服务；实际部署配套 Go 后由代码处理。

用户已明确选择一小时保留。超过该窗口的旧请求不能再假定原结算快照或原重试结果还存在；长时间故障中尚未持久保存、又仅存在该快照里的原文，会随到期删除，不能同时宣称无限保留与固定一小时缓存。
