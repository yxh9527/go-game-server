# 百人街机旧局详情查询修复

本轮开始时核验实际后端：上一批刮刮乐回执精简和比赛确认凭证的 7 文件合并包全部应用，0 个待应用。本轮仅修改 Node 原生回顾查询，不改资金、统一注单外层、go_gp_settlement.log 来源或三分钟缓存期限。

## 问题与修改

原 queryHundredHistory 获取最近 100 条回顾后，只在该列表中寻找指定局号。旧局即使存在于 ES，也不会继续请求，游戏可能退回列表而打不开详情。

- 百人／街机公共详情查询向 gameHistoryRecords 传入指定 inningNum，最新页未包含该局时，公共层以原 inning 精确查询同一资金历史源。
- 指定局不在最近列表时都会查询一次原详情；包括最近列表为空或缓存结果较旧的情形，避免把“最近列表没有”当作“原注单不存在”。
- 无效局号在 Redis／RPC 前返回原 null 语义；详情不存在仍保持原行为，不造记录。
- 指定局原查询继续隔离代理、玩家、币种、玩法和房间。返回的其他玩家／房间记录仍被过滤。
- 最近列表和每份指定详情分别使用原规范化缓存键，固定 180 秒、命中不续期；并发相同请求合并。单局查询不会覆盖最近列表缓存。
- 普通桌也复用改进后的明确局号分支；原回顾总局数保留最近已知值，并在精确源返回较新局时更新，避免旧缓存头部小于本次实际局号。

影响公共路径覆盖百家乐、龙虎斗、百人德州／金花／牛牛／二十一点／麻将，以及奔驰宝马、森林舞会、飞禽走兽、满金之轮、趣味捕鱼。比赛和刮票资金处理不变，没有新增 Redis 历史副本或永久缓存。
