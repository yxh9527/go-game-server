# 真实源码热更新与连接内存验证

本轮补充可重复运行的隔离测试，验证连续真实源码变化时，处理器替换、旧请求依赖与常驻连接是否正常。此前 unchanged-content 导入测试不能代表这一场景。

## 新增工具

test/performance/hot-source-change-load.mjs 在 cache 下创建临时入口和版本依赖，实际修改临时依赖源码，每次经生产 importHotModule 和源码绑定 hook 加载新内容，并调用真实 createHandler 重建处理器。HTTP／WebSocket 监听仅使用 127.0.0.1 随机端口，连接与 registry 在本隔离进程常驻。

每次版本变化后验证新处理器取得新版本、旧延迟调用保持旧依赖、不变源码复用原模块命名空间，全部连接继续完成实际 1200 心跳；每 25 次加入一次语法错误，确认旧处理器仍可服务，然后修复该源码继续运行。版本号只来自实际加载结果，不能只累计“发起 reload”次数。

增加 hotImportStats，只返回源码缓存、版本条目、兼容依赖映射数量和容量等纯数字，不暴露模块命名空间、源码路径、业务运行对象或敏感配置，也不引入新的长期引用。

测试在独立 Node 进程使用 --expose-gc，每次采样执行 GC，记录 heap、RSS、external、连接／会话数量、心跳数和导入计数；退出时关闭全部套接字、核对会话清零、移除临时源码。输出仅允许命名的 cache/*.json 文件，不修改真实游戏业务文件或常驻服务，不连接数据库、不下注。

## 本轮实测

命令：

```powershell
node --expose-gc test/performance/hot-source-change-load.mjs --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-source-change-600.json
```

| 成功的真实临时源码变化／处理器替换 | 600 次 |
| 故意语法错误并保留旧处理器 | 24 次 |
| 持续连接 | 128 条 |
| 成功心跳 | 80000 次 |
| 隔离运行时长 | 约 11.52 秒 |
| 每次采样的会话及连接 | 均为 128 |
| 退出后的残余会话 | 0 |
| 测试捕获的异常 | 0 |
| 堆增长 | 7228960 字节，约 6.89 MiB |
| 每个真实版本的平均堆增长 | 约 12048 字节 |
| 事件循环 P99／最大延迟 | 约 29.93／34.67 ms |

原始数据 cache/hot-source-change-600.json，运行日志 cache/hot-source-change-600.log。修复后的冒烟结果为 cache/hot-source-change-smoke.json。

## 结论与限制

新旧依赖隔离、错误源码回退、常驻连接和会话释放检查通过。虽然本次兼容依赖映射没有增长，堆仍随真实新版本增长，说明不能把 Map 有界等同于 Node 旧 ESM 已完整回收。关闭全部连接后堆仍约 21.17 MiB；完整运行时卸载尚未实现，清单保持未完成。

本工具修改的是临时版本依赖，真实 game-server 业务源码不改、被替换处理器仍使用既有业务实现；也未创建带入或下注责任。它是短时隔离测试，不能代表多日生产负载、所有游戏版本图变化或八小时房间生命周期验收。
