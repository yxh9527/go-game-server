2026-11-17。继续 Redis 收尾，保留全部前批修改。没有预建中奖票库，没有改变转轴／水池决定奖项的规则，不改原客户端协议。

## 先判奖再出票

玩家购买时，游戏服按已确认的转轴配置生成候选结果，统一资金服务按水池决策确定采用哪个结果，再将本次付费对应的票面与奖项固定。未付费候选号只是 60 秒的展示，不是预先发行、永久占用的完整票库。单张即时玩法购买后直接揭晓；整本购买仍有已付款、尚未刮开的票。

允许先判断中奖档位，再生成符合该奖项的票面；关键是同一已付款请求固定原结果，重试不能再随机或重复派奖。本批处理的是已付款票的归属与终态 Redis 保留，不能把玩家尚未使用的票当历史查询缓存删除。

## 本批修改

原 gogame:scratch:sold:<agent>:<gameId>:<serial> 同时是票号已售保护，不能只把 7 天改成一小时，否则缓存消失后候选查询可能重新发售旧票号。

复用已有 fg_game_storage 及 uk_game_storage，不新增表、索引、资金流水或回放队列。在保留的 user_id=0、currency_symbol=* 命名空间，storage_key=scratch-sold:<agent>:<serial>，仅保存 version、agent、gameId、userId、currency、serialFull、roundId。该已售归属不含牌面、奖项、钱包、完整注单、log 或金融快照，是持久业务身份，不是 Redis 缓存。

最少已售归属与原玩家票据保存使用同一 MySQL 事务：插入冲突不覆盖，读取原归属加行锁，必须仍属于同一玩家／币种／原局号；任一步失败均回滚。事务成功且 Redis 原快照写入成功后才确认 soldMirrored。Redis 保存失败会恢复本地确认标记，避免下次误跳过。

候选号查询和实际购票前都检查已售归属。Redis 已有映射则继续原原子防重，Redis 缺失时按市场查询原表，批量最多 100 个票号，覆盖该市场所有玩家及币种。使用原完整唯一索引的固定前缀／票号键查询；数据库故障或损坏记录明确失败，不能当成未售。查询不创建新的 Redis 正／负缓存。

确认票据和市场归属都已持久保存后，SETTLED 且已兑奖、VOIDED 且已退款的 sold 键只保留到原 settlement.completedAt + 3600 秒，旧兼容参考时间为原 updatedAt。更短 TTL 不续期，已超时直接删除，缺失键不重建，不覆盖其他原局号。相应 pending 集合只移除本票，兑奖累计奖金只记一次。

旧存量缺少 soldMirrored 时不能直接缩短。仍有原快照并经过合法状态查询／结算重试的票，会先确认最少市场归属，再执行一小时清理；失败保留原映射和未完成状态。不是全库历史回填或背景重放。已无可信快照的遗留映射、未确认付款／未交付权益及其他剩余 Redis 项未整体完成。
