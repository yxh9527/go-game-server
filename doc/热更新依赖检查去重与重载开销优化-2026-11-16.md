# 热更新依赖检查去重与重载开销优化

本轮按清单继续第二项，降低热更新校验的重复文件系统访问。可回收白名单仍为 30 个模块，主体业务类与引擎继续原生 ESM；本轮不把完整业务模块回收或长期验收标为完成。

## 修改

shared/hot-loader.js 对同一源码中重复的相对依赖路径去重，并增加仅在当前校验周期有效的文件存在性结果缓存，包含存在及不存在两种结果。多个入口共享同一依赖时，可以复用这一周期内的存在性检查。

新重载 token、环境模式变化、显式 invalidate 和编译前 readSource 复核都会开始新周期，同时清除存在性缓存。因此下一轮仍会发现文件新增、删除或等长修改；源码仍按原规则重新读取、计算哈希，旧地址不能执行当前磁盘的新源码。

存在性缓存最多 4096 条，达到上限先清空再继续检查，避免诊断优化自身变成持续增长点。stats 增加 presenceEntries／maxPresenceEntries 两个纯数字，不暴露路径、源码、模块命名空间或运行对象。它是 Node 内存中的短期校验结果，不写 Redis。

本轮没有改变版本指纹算法、原源码复核、弱引用保留、并发依赖循环保护、实例复用或房间状态归属。

## 文件系统访问对比

在相同参数的独立进程中顺序执行 50 次真实目录副本变化，32 条连接、每 25 次采样。计数在隔离进程临时包装 fs.readFileSync／fs.existsSync，覆盖该进程启动及测试期间的同步调用；没有修改常驻服务或生产文件系统实现。

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 源码等同步读取调用 | 39966 | 39966 |
| 文件存在性检查调用 | 168936 | 41924 |
| 成功目录变化／心跳 | 50／1696 | 50／1696 |
| 隔离运行时间 | 6.76 秒 | 4.55 秒 |
| 事件循环 P99 | 145.88 ms | 111.94 ms |

存在性检查减少约 75.18%，同步读取数保持一致。数据及计数分别在 cache/hot-graph-cost-before.json／.log 和 cache/hot-graph-cost-after.json／.log，日志末尾的 FILESYSTEM_COUNTS 保存调用总数。

这组观测支持减少重复路径检查，没有通过省略每轮源码哈希核对换取提速；它是本机单次对照，不是跨机器性能保证。

## 600 次目录变化验证

```powershell
node --expose-gc test/performance/hot-source-change-load.mjs --loader=collectible --entry=catalog --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-graph-presence-600.json
```

| 项目 | 结果 |
| --- | --- |
| 成功目录变化／处理器重建 | 600 |
| 故意语法错误并保留原处理器 | 24 |
| 持续连接／成功心跳 | 128／80000 |
| 驻留房间保留检查 | 600 次通过 |
| 每次复用的原游戏实例 | 21 |
| 结束后的残余会话／房间／捕获异常 | 0／0／0 |
| 采样时 pendingEntries／dependencyWaits | 均为 0／0 |
| 采样时存在性缓存最大数量／上限 | 175／4096 |
| 运行时间 | 56.79 秒 |
| 事件循环 P99／最大延迟 | 158.33／187.30 ms |
| 堆增长 | 22661264 字节，21.61 MiB |
| 后 300 次堆增长 | 约 2.77 MiB |

此前同参数记录为 83.18 秒、P99 204.08 ms；本次约减少 31.72% 的运行时间和 22.41% 的 P99 延迟。两次不是同一时刻的严格受控测量，数据只作为本机隔离结果。源码复核、解析及编译仍有开销，不能宣称重载无卡顿；堆也仍有增长和 GC 波动，长期稳定性尚未验证。

原始结果 cache/hot-graph-presence-600.json，日志 cache/hot-graph-presence-600.log。测试包含原驻留房间／座位／手牌／筹码／生命周期时间检查，没有执行真实下注、资金划转或数据库操作，不代表多日及八小时房间生命周期验收。
