# 比赛休息与结束回收

日期：2026-11-11。本批修改 Node 比赛、游戏服及大厅逻辑；保留全部原修改，没有重启服务、提交代码或执行数据库迁移。后端最新 4 文件应用包仍为 0 个待应用，本批无新增 Go 补丁。

## 比赛休息

共享 shared/tournament-blinds.js 负责校验及解释盲注计划；match 和 game-server 使用同一规则。支持已有 BlindItem 的 type=1 普通级别和 type=3 休息级别。最多 512 级，时长及金额为安全整数；开头、结尾必须是普通级别。中间级别和休息必须有正时长。type=2“准备暂停”仍明确拒绝，不猜测它与休息相同。

到达休息时间后，全场禁止发下一手，正在进行的手牌继续正常结算。等待所有桌的手牌和结算动画结束，再从最后一桌完成时起计算完整休息时长。延迟的手牌或 tick 不会把休息跳过、缩短；休息之后的升盲时间相应顺延。休息结束先由 match 处理既有排名/淘汰检查点，再恢复下一手，不漏记刚结束的牌局。

一个比赛的各桌共用常驻 clock，热更新不重置倒计时；每轮外部 tick 只扫描比赛一次，不在每个钱包桌任务中重复全场扫描。休息内的盲注沿用上一普通级别，下一档取下一普通级别，不使用休息项的零值发牌；级别号保留配置 level 或原数组编号。

原版 static/client/2.0.1279/assets/main/index.88f4e.js 定义 20013 COMPETITION_WAIT_TO_FINISH_ALL_TABLE、20014 COMPETITION_RESTING；Holdem/index.55219.js 的 onPushCompetitionResting 直接读取秒数。服务端等待时推 20013，开始休息推 20014 数值秒数；重连补发剩余秒数，下一手沿用原客户端发牌流程关闭提示。原始客户端未修改。

game-server 的状态查询携带固定的级别及截止时间，match 在时钟状态改变时持久化并通过原 match_snapshot 广播。hall 读取内存缓存，在详情中显示 rest、剩余时间及当前盲注，不逐次访问数据库。没有使用此时钟的旧场次仍使用原兼容字段。

## 比赛结束回收

比赛结束与奖励发放仍是两个阶段。全部奖金/门票经权威资金确认后，match 才发送全名单最终奖励通知；game-server 校验全名单、名次范围和非负安全金额，保存只读最终结果并确认。重复相同通知不会重复发送，改变内容拒绝。

最终结果在回收前保留于常驻比赛对象，重连可补发 20010。热更新接管已结束的旧场次时使用 deliveryVersion=2 的通知请求重新确认服务端状态，绕开旧短期缓存中的确认响应；这只补通知，不再次付款。

match 收到奖励通知确认后调用签名 cleanup。默认保留 60 秒供查看结果，game-server 配置 tournament_cleanup_delay_ms 可设置 0 至 3600000 毫秒；到期时没有在局手牌及未完成离房任务才回收。派奖失败或通知失败时不安排回收，不把比赛积分换成现金。

回收清除比赛桌、roomManager 索引、比赛常驻 Map、成员/旁观者、房内历史、公正码/玩家面板缓存及最终结果引用。连接收到既有 ROOM_DISSMISS 并离开房间，鉴权连接不因回收被踢。match 确认 released 后将持久化分桌列表置空；回执丢失可重复 cleanup，不能因为短期缓存的旧 released=false 永久停在待清理。

生产端收到创建比赛桌请求还会经 RPC 核对比赛归属和状态，仅报名中/进行中可创建。结束后，旧请求在缓存过期后不能重新建立比赛桌。用户后续确认不做崩溃恢复，改为记录异常作废并全额退款，见《比赛异常作废-2026-11-11.md》。
