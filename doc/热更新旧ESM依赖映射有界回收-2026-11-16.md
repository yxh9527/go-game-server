# 热更新旧 ESM 依赖映射有界回收

> 最新实测：600 次真实临时源码变化下，兼容依赖 Map 为 0，但堆增长约 6.89 MiB，证明有界映射不等于完整卸载。原始数据和可复测工具见《真实源码热更新与连接内存验证-2026-11-16.md》，Node 最新 1301 项通过。

> 后续修复补齐参数求值、局部作用域及动态依赖 hashbang 兼容；Node 最新 1299 项通过，详见《热更新参数求值与局部作用域修复-2026-11-16.md》。下文 1291 项为当时结果，完整运行时卸载仍未完成。

本轮按清单第三项推进。此前 `shared/hot-import.js` 用全局 Map 按每个旧父模块 URL 保存依赖映射，真实源码持续热更新时该 Map 会无限增长。

## 修复

- 新增 `shared/hot-source-pins.js`，使用 Acorn 解析热加载源码，把字面量 `rel(import.meta.url, './module.js', version)` 绑定为当前内容版本的直接 `import()`。旧处理器继续引用旧 URL，新处理器使用新内容，不通过可变全局依赖表切换。
- 动态依赖仍通过兼容路径处理，但旧依赖 Map 设为最多 1024 个父模块，超过上限淘汰最早条目，避免无限累积。
- hall、game-server、match 的热加载入口安装源码 pin hook；常驻连接、registry、房间状态、RPC 客户端不进入回收范围。
- `acorn` 作为根依赖锁定为 `8.15.0`，只用于解析模块语法，未执行源代码。

## 边界

旧 ESM 模块本身仍由 Node 模块缓存和运行中的闭包引用；本轮消除无限增长的依赖映射，未宣称可以强制卸载仍被连接、定时器或房间引用的模块。完整运行时垃圾回收需要长期真实热更新和内存压测，不能通过清空 Map 强行破坏旧任务。
