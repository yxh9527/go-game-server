# 智能投注原退款责任收尾

上一批“记录存储故障背压与队列保护”9 个 Go 文件已由用户应用，实际目录摘要校验为 0 待应用。本轮继续扩展任务收尾的事实依据：除正常已结算结果外，允许按原已完成的取消退款或 VOID_REFUND 全退结束任务，不执行任何新资金操作。

## 本轮实现

- 新的任务执行身份包含原 areaId；实际金融下注的 areaId 携带 `smart:<attemptId>:<原区域>`。此标识来自服务端已登记的执行身份，不取客户端随意传入的区域字符串。
- 游戏侧和客户端继续使用原数字区域、原金额和赔率，不把金融关联标识发成新的玩法区域；金融 roundId、betId、防重与派彩口径沿原逻辑。
- data-center 登记执行时验证 areaId 与原任务一致。旧 activeAttempt 没有该字段的记录仍可按之前的正常结算报告确认，但不能据模糊的旧投注认定退款完成。
- 取消退款收尾必须找到该玩家／币种在原牌局的已接受投注，区域关联原 attemptId，总金额等于原任务投注金额；每笔状态为 CANCELED。
- 对应 cancelRequests 必须 COMPLETED、success=true、walletRefunded=true，且包含合法账后余额、完成时间、精确 canceledBetIds 与全额 refundAmount。重复覆盖、其他投注混入或部分退回拒绝确认。
- VOID_REFUND 收尾必须是原牌局 VOIDED、原 settlement.mode=VOID_REFUND、status=COMPLETED，具有已确认账号结果及完成时间。原最终金融报告的玩家／代理／币种／roundID、bet 和 win 必须证明本金全退、净额为零。
- 确认通过后，在原任务行锁事务中停止任务、清理 activeAttempt／pendingInning，记录 refundCount、refundedAmount、lastRefundedInning 和 resolutionKind=REFUNDED；不计入正常 completedCount、totalBetAmount、profit、winCount、loseCount 或 profitTrend。
- 重复确认已停止任务直接返回原结果，不重复计退款次数、不再次累计退回金额，不执行钱包变化。
- 仍使用任务页原“确认结果并结束”操作；同一入口只确认原结果，不会发起 CancelBet、VOID_REFUND、扣款、退款或派奖。

## 证据不足时继续保留责任

没有原投注、仅预留过期、当前余额相同、取消仍处 CLAIMED、部分退款、不同玩家／币种／区域／attemptId、原快照或最终报告缺失，都不能因此释放责任。

旧执行没有金融区域关联标识时不补造关系；原游戏服在未结算时退出，不会因这项功能自动退款或重开牌局。多实例写入归属、Redis 持久性和真实故障演练仍需验收。
