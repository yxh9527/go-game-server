# 特殊投注入口记录存储保护

> 后续用户要求删除 Luck5，本说明中的 Luck5 部分已取消，相关入口及测试已从源码和补丁中删除。刮刮乐部分继续保留。当前应用包已被《移除Luck5-2026-11-12.md》所述 9 文件包替代，不再应用本文原 4 文件包。

本轮开始时，上一批智能投注退款收尾的 3 个文件已全部应用，只读校验为 0 待应用。继续检查独立扣款路径，本批补 Luck5 首次扣注及刮刮乐首次购票的记录存储预检。

## 行为

- Luck5 先读取并校验原 roundId 的扣注结果。已有相同请求仍返回原回执，改金额的重试仍被拒绝；首次扣注才检查原记录存储，失败时在钱包和奖池变更前返回 `recordStorageUnavailable`。
- 刮刮乐先读取原购票请求的回执。首次购票检查原记录存储，最多等待 1 秒，随后仍需通过已有票据归属表结构检查。记录库不可用或此前原输出尚未持久接收时，拒绝新购票，不扣款、不占用票号、不产生购票回执。
- 预检复用已有 FinalRecordStorageReady，包含进程内原记录积压检查及短期 SQL 健康缓存。不新增表或协议字段。
- 不给 Luck5 原结算、刮刮乐兑奖或原退款增加这道新投注限制。已接受的资金责任继续沿用原处理路径。

只读预检不能保证探测之后 SQL 永不故障，也不验证 SQL 写权限。SQL 尚未提交前进程退出的记录丢失窗口仍未消除，不据此将整个记录持久保障标为完成。

## 文件

- `lottery/rpc/service_luck5.go`：原回执读取后、首次资金操作前增加预检。
- `lottery/rpc/special_record_storage_admission_test.go`：新扣注失败无资金变更，原请求重试仍成功，改金额重试拒绝。
- `lottery/unified/scratch.go`：首次出票的记录存储预检及 1 秒期限。
- `lottery/unified/scratch_test.go`：新购票失败无扣款／归属／回执，原购票回执在记录库故障时仍可重取。

源码先在当前可写目录 `cache/backend-integration/gogames` 完成；对比实际后端后打包到 `doc/待应用/线上后端对接`。实际后端已有修改保留，不提交代码、不重启服务、不操作真人资金。
