## 问题与修复

原退款票据清理直接移除 pending 成员，并从每次清理时起给 sold 票号映射重新设置 7 天期限。它没有原子核对原票据状态、归属和 SQL 镜像确认。兑奖完成清理也只核对 SETTLED，没有把调用方传入的玩法和中奖额与原票据逐项比较。

现在兑奖和退款清理在同一个 Lua 操作中核对原金融快照、玩家、代理、游戏、币种、完整票号和局号。兑奖要求 SETTLED、claimed、mirrored，玩法与中奖额必须等于原票据；退款要求 VOIDED、refunded、mirrored。mirrored 沿用原 SQL 保存成功后写回快照的确认，不新增外部确认记录。

票号映射仍指向原局时才可清理；若已指向另一局，拒绝并保留全部原状态。原金融快照缺失或时间不可信时，不猜测处理完成。缺失映射不会重新创建，未处理票据不会因本轮修改设置到期期限。

sold 的现有 7 天上限改为从原 settlement.completedAt 起算；旧记录缺少有效原完成时间时沿用不会因终态保存而更新的 updatedAt。重复调用不能延长期限，原剩余期限更短时也不延长。已超原期限的匹配映射直接删除。兑奖重复仍只清理，不再次累加 accumulated。

## Redis 影响

| 键 | 本轮影响 |
| --- | --- |
| gogame:scratch:sold:<agent>:<gameId>:<serial> | 核对当前映射后，最多保留至原完成时间加 7 天；重复不续期，缺失不补建 |
| gogame:scratch:pending:<agent>:<gameId>:<userId>:<currency> | 仅在原终态、归属及镜像确认通过后移除原局成员，其他票据保留 |
| lottery_finance_rounds | 读取原完成与归属；兑奖继续沿用既有 historyRecorded 更新，不延长原终态一小时期限 |
| gogame:scratch:accumulated:<agent>:<userId>:<currency> | 继续使用原玩法和中奖额，拒绝参数不符，不重复累计 |

本轮没有新增 Redis 键、永久归档或独立幂等流水。购票回执、未处理票据和其余资金 marker 的期限没有整体收尾，不能宣称所有 Redis 数据已是一小时以内。

sold 还参与票号防重复出售。现有按日期和后缀生成票号的方式可能再次生成同一票号，SQL 票据镜像目前不作为全市场售票时的原子唯一领取依据。因此本轮没有直接把 sold 缩短为一小时。用户已经确认的一小时规则继续适用于金融终态快照；其历史仍读 go_gp_settlement.log，查询缓存仍为 180 秒。
