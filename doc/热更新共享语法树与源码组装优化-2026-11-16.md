# 热更新共享语法树与源码组装优化

本轮继续处理重载延迟，默认可回收范围仍为 71 个模块，没有扩大业务白名单。优化依赖绑定和入口转换的重复解析、遍历与字符串组装；源码版本复核、常驻对象、旧请求和房间状态保护保持。

## 定位与修改

先对真实引擎更新的隔离测试进行 CPU 采样，发现除同步文件访问外，入口转换中的 AST 遍历、依赖绑定遍历和重复解析也占有明显开销。原流程先解析原文并生成绑定源码，再解析生成后的 JavaScript 转换 import／export 和 import.meta。

shared/hot-source-pins.js 增加 planHotSourcePins，允许与入口转换共享原始 AST。字面量 rel 调用只改调用标点边界，保留参数表达式的原始范围，后续同一 AST 可以处理其中的 import.meta、动态 import 和嵌套调用。原 pinHotSource 接口仍负责普通原生模块的源码输出。

shared/hot-entry-factory.js 直接在这份 AST 上合并依赖绑定和模块转换；对整段替换的导入／再导出语句，以及已处理的 import.meta.url 子树直接停止遍历，去掉每个节点扫描全部编辑范围的重复工作。

增加 applySourceEdits，按原始位置一次分片组装源码，替代每次编辑都重新切片拼接整份文本。它保持相邻替换和同位置插入的顺序，发现重叠、越界或非法范围时明确失败，由原热更新流程保留旧处理器。

本轮不减少源码哈希复核，也不跨版本常驻缓存 AST 或源码文本。语法树和编辑计划只用于当前转换，生成的模块继续沿原弱缓存和依赖持有规则管理。

## 回归

新增 test/shared/hot-source-plan.test.js 三项：

- 源码编辑的相邻边界、同位置插入及非法／重叠范围拒绝。
- 通过 Acorn 的实际解析入口计数，确认带 rel 依赖的工厂源码只解析一次，未再解析生成源码。
- 对照原生源码输出及工厂路径，核对括号／注释、嵌套 rel、await、动态 import、import.meta、参数副作用顺序、动态路径及旧延迟调用保持原依赖。

旧参数求值、局部同名绑定、hashbang、默认导出、原生配置／RPC 单例、源码变更拒绝、类／引擎 GC 等用例继续通过。
