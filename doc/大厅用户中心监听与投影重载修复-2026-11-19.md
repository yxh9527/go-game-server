# 大厅用户中心监听与投影重载修复

2026-11-19，Asia/Shanghai。继续热更新依赖图收尾，修复大厅用户中心检测到文件变化却可能仍使用旧投影，以及旧请求可能恢复旧版本的问题。保留全部已有修改，未重启服务、提交代码或操作真实余额。

## 已复现的问题

hall/src/user-center.js 原文件监听将 runtime.userCenterProjection.dirty 设为 true 后，仍通过 rel() 加载共享投影。在真实可回收／版本绑定路径中，rel() 用于保留调用者原依赖，不能用它读取刚编辑的当前源码。结果可能是“文件事件已到达，但用户中心展示仍使用旧版”。

原版本选择仅比较 state.version 与请求处理器的 version；新处理器已使用新投影后，原处理器上尚未完成的请求又会将 state.project 改回旧投影。两项均已用真实大厅源码副本、真实工厂和文件监听复现失败，cache/hall-projection-before.log。

另有原 fs.watch 回调由首个业务版本创建，常驻监听器可能继续保留该版本的运行环境。需要把监听器和业务投影的更新职责分开。

## 修改

- hall/src/projection-watch.js 是新增的常驻传输辅助，加入 shared/hot-loader.js 的常驻名单。只维护本进程单调模块代次并创建文件监听；监听回调保留原 state 和 logger，不持有用户中心命名空间或业务导入闭包。
- hall/src/user-center.js 按模块代次选择 runtime 当前投影；旧请求不能恢复旧版。文件变化时使用 importHotModule 解析当前文件，保留 rel() 对普通旧调用者绑定原依赖的语义。
- 加载结果提交前核对原代次和文件变化序号；期间发生编辑则继续读取当前版本，旧加载结果不能覆盖新处理器已选投影。只有原任务仍拥有 loading 字段时才清除该字段。
- 原格式监听首次使用时关闭并替换一次；后续代码代次复用同一个监听。监听报错后关闭、标记需刷新，后续请求可重建。无 filename 的文件事件按可能变化处理，其他明确文件名不触发重载。
- 语法错误不覆盖原正常投影，当前请求明确失败；随后修正文件可恢复，不重启大厅。

将 hall/src/user-center.js、hall/src/room-pool.js 两个业务模块加入工厂白名单，总数从 147 扩至 149。room-pool 的 WebSocket、超时及响应状态本来属于单次请求，其协议、连接和金额规则未改。监听辅助有意保持常驻，不把它计入可回收业务数量。

没有增加 Redis key、数据库、资金操作、报告重试或额外用户消息。原身份校验、历史查询三分钟缓存、展示格式、头像规范化及战绩数据不变。
