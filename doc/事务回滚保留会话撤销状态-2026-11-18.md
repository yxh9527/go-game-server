# 事务回滚保留会话撤销状态

2026-11-18，Asia/Shanghai。继续核查回滚与登录互斥边界，修复资金操作失败后可能重新激活旧会话标记的问题。保留已有修改，不重启服务、不提交代码。

## 问题

权威资金事务执行前捕获房间／成员／session 等本地对象，失败后恢复原对象。资金 RPC 等待期间，分布式登录验证／租约撤销可能已经将原 session.superseded=true、authenticated=false。原恢复会把这两个标记恢复成事务开始前的值，导致本地旧会话重新显示为已认证。

连接本身已经关闭或分布式后端会继续拒绝旧租约，但不能依赖下一次验证再纠正本地权限，游戏状态回滚也不应撤销已发生的登录撤销事件。

## 修复

只修改 game-server/src/wallet/transaction-state.js：捕获原连接对应的 session 身份，在恢复该对象的属性之前记录它此刻是否已被 superseded，或是否从已认证转为未认证。恢复牌局及其余原属性后，保留 superseded=true／authenticated=false 的撤销结果。

恢复仍保持原对象身份、座位／手牌／筹码、数组／Map／Set 和原描述符。新设置的撤销标记即使事务开始时尚不存在，也不能被清除；只设置 superseded 时仍按失效会话处理。没有已认证变失效的其他 session 保持原逻辑，初次登录从未认证到已认证若失败，仍恢复未认证。

不扩大为整个 session 不回滚，不引入另一个登录状态库，也不更改资金结果、退款、派奖或防重。原分布式 lease 和 socket 关闭逻辑保持；资金结果不确定时原账户暂停保护保持。
