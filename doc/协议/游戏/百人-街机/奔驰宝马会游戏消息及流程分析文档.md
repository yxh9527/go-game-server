## 4. 轨迹和状态字段

该玩法不是牌局数组协议，ENTER_RESPONSE 里没有 bankerCards、playerCards 等牌面字段，而是维护两套轨迹：

- defaultOuter：长度 24 的外圈结果序列，元素主要为 1、2、3、4；
- defaultInner：长度 24 的内圈结果序列，元素为 1、2、3；
- outerIndex：当前外圈位置；
- innerIndex：当前内圈位置；
- ways.1：外圈走势统计；
- ways.2：内圈走势和 winCountMap；
- consecutiveWinCounts：连续命中次数。

例如：

~~~json
{
  "defaultOuter": [1, 4, 2, 4, 3, 4, 2, 4, 3, 4, 3, 4],
  "defaultInner": [1, 1, 1, 1, 1, 1, 1, 1, 2, 2, 2],
  "outerIndex": 17,
  "innerIndex": 9
}
~~~

日志没有出现转盘图片、动物名称或额外开奖结果字段，客户端应根据 areaId、winningAreas 和索引字段渲染结果。

- state=10：本局结果同步完成，等待下一轮。

该状态解释依据日志时序归纳，正式实现应以服务端最新状态为准。

- winningAreas：本轮命中的区域；
- lostAreas：本轮未命中的区域；

- nextInner：下一轮内圈轨迹。

本日志没有出现独立的 MB_ROOM_BET_SETTLE，街机奔驰宝马使用 SHOWDOWN_POKERS 直接公布区域结果和积分。

## 6. 一轮游戏流程

1. HTTP op=45 获取 roomType=53 的街机入口。
2. SEND_JOIN_ROOM 进入具体 roomId。
3. ROOM_TYPE_RESULT 返回 bcbm 配置、30 个区域和赔率。
4. ENTER_RESPONSE 返回人数、积分、局号、轨迹和历史下注。
5. state=2 开放下注，客户端发送 BET。
6. BET_RESPONSE 返回个人下注是否成功，BET_BROADCAST 持续更新 30 个区域总下注额。
7. 6212 DEAL_CARDS_AND_ODDS 推送新轮赔率。
8. state=4 进入开奖，6208 SHOWDOWN_POKERS 返回 winningAreas、lostAreas、积分和下一轮轨迹。
9. state=6/10 更新走势图、连续统计和索引。
10. 下一轮重新进入 state=2。

## 7. 与森林舞会的差异和文件命名说明

当前日志的服务端玩法是“奔驰宝马”，其协议特征是 30 个下注区域、外圈/内圈轨迹和奔驰宝马赔率。森林舞会通常需要独立的 roomType、gameName 和结果字段；本日志没有这些标识。

因此本文件按用户指定名称保存，但协议内容应被视为“百人街机奔驰宝马”分析。若后续提供真正森林舞会日志，应重新确认房间类型和开奖区域，不要复用本文件的 areaId 解释。

## 8. 实现建议和限制

- 使用 roomType + roomId + inning 作为轮次唯一键。
- allPlayerBets 的顺序不固定，必须按 areaId 映射。
- 每轮收到 6212 时覆盖 areaOdds，不能永久使用登录时赔率。
- 只有 state=2 且倒计时有效时允许 BET。
- roomId=0 的 SHOWDOWN_POKERS 需要结合当前 inning 和最近房间快照归属。
- winningAreas、lostAreas 可能同时包含多个区域，不能假设只有一个中奖区。
- defaultOuter、defaultInner 和 ways 是走势数据，不是下注结果本身。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
