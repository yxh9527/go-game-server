# 游戏内换场

2026-11-06。范围为原版 `roomListInside` 场次选择面板：全部/棋牌/百人、游戏标签、玩法标签和底注档位；不同于 3381 快速换同档桌，本次不新增快速换桌协议。影响 hall、game-server 和本地 client-web 页面适配。原始 static 文件不修改，服务常驻热更新。

## 客户端流程

1. 游戏内“换场”调用 `roomListInside`，RateRoom 类型。
2. HTTP op=49 获取俱乐部上下文。原 ClubListPageModel.resolveClubIdForRoomList 只在上下文有正数 clubId 时发出场次查询；零值会停留在占位卡片。hall 从登录 profile 的 clubId（无独立字段时为 agentId）填充 op=49、op=53；请求带已有 clubId 时沿用展示值，实际房间与资金隔离始终只用认证得到的 agentId。dev 无网关时使用本地上下文 1。
3. op=38 返回已有真实配置场次及动态人数。游戏和玩法过滤、底注、可见牌、carryMin、forceShowCard、playMode、straddle 等继续由现有配置接口处理，不添加另一套场次列表或修改客户端。
4. 点场次后原 clubInfoListItem.joinRoom2 发送 op=45；gameType 字段可能是目标 roomType，与大厅分类 gameType 不同，以配置身份和实际 roomType 匹配。响应包含 roomId、roomType、domain、shield、hundredDomain、配置及档位字段。WebSocket 使用 domain，原切房方法还检查 shield 非空；优先取行 shield 或 config.game_shield，普通 Web 场景未配时以 domain 作为相同目标的标识，不额外引入盾牌网络服务。
5. 原 GameProcessHelper.leaveCurrRoomChangeToOtherRoom 发送 2110 `{isLeaveMultiRoom:false}`，等待旧房 2205 后连接目标，再发送 2102 `{roomId,roomType,isOb:true,changeRoom:true,...}`，收到 2201 确认目标房间。新场默认旁观，仍须主动占座并带入。
6. 目标场景准备后通过既有 2111 LOGIN_ROOM 获取 2206 及本人授权牌局恢复；刮刮乐沿用 3702 状态请求。

## 服务器切换与资金

2102 按常驻 session.roomJoinTask 串行处理；若同一连接仍在不同旧房，先完成公共 leaveTable 再改 session.roomId/gameId，避免幽灵座位或重复旁观。重复加入同房不重复退款，不重置座位或本局牌。目标不存在/到期时先拒绝，不先移除有效旧房。

leaveTable 按常驻 session.roomLeave 保存旧房引用、已移除、待退款额、已入账及已持久化状态，session.leaveTask 合并并发执行。拒绝入账或持久化失败时不能确认离房，也不能进入新房；热更新、重复请求或 tick 重试沿用进度。已入账后只重试持久化，不重复返还筹码。断线未完成任务保留在 registry 至成功，随后清理连接引用。

德州、炸金花沿用原弃牌离场规则。牛牛、十三水、三公、麻将、二十一点已有本局责任时仍由 SeatGame.holdSeatUntilRoundEnd 保留 funded member、departureSession 和 pendingDeparture，原局正常结算后通过公共 afterRound 返还剩余筹码，不提前退款或用新场钱包重复覆盖。八小时房间时钟、旧房统计、机器人和无人三局规则不重置。百人已受理投注及刮刮乐票据仍由原有结算/队列完成。

2201 同时返回 clubId、playerClubId、exchangeRate，保持原客户端的有效场次上下文。

## 场景准备

带 changeRoom 的新房间先发 2201，session.roomHydrating 暂缓游戏快照，至新场景发 2111（刮刮乐为 3702，独立 Hundred 场景为当前目标房的 6105）后恢复正常推送。百人副连接选择浮层不能提前解除普通主房间的准备标记。这样旧场景不会消费新游戏的 2206、牌型或按钮字段。服务端不发新消息号，也不在静态客户端中改协议。

独立 dev 启动跳过原 loading 页面，cache/client-web/dev-patch.js 原有 loading/over 桥接只支持初次 entry 的 sceneReady。现扩展为同一 iframe 收到不同 module/scene 的原准备通知时建立新的加载代次，旧异步回调不能覆盖新场景；同场景重复通知不重置牌桌。此处仅本地适配，生产依然使用原版加载流程。

原客户端 Cancelble 在成功切场时会取消竞争的风控/超时等待，并产生字符串 `Promise manually interrupted!!` 的拒绝通知。浏览器回归单独记录这些原生取消，仍对所有 TypeError/ReferenceError 等实际脚本错误作失败检查，不在产品中全局屏蔽异常。
