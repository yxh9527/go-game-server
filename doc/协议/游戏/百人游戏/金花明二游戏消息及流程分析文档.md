# 金花明二游戏消息及流程分析

## 1. 分析范围

- 日志文件：C:\Users\Administrator\.codex\attachments\69029285-8815-4bd8-be89-701e859a13e4\Pasted text.txt
- 用户命名：金花明二
- 百人房间类型：roomType=51
- 进入模式：playMode=2
- 运行态配置标识：gameRoomConfigId=5102
- 运行态返回名称：百人金花

本日志同时连接 roomType=25 的传统金花桌和 roomType=51 的百人金花服务。本文只分析 RoomSocket-222 的百人协议。传统金花的桌内下注、手牌和 pot 消息不属于百人下注区协议。

## 2. 进入百人模式

大厅先通过 HTTP op=38 拉取 gameType=1000、roomType=51 的百人玩法列表，再通过 op=45 打开常规金花房间并开启百人连接。百人连接的消息顺序：

~~~text
RoomSocket-222 ROOM_LOGIN(1105/1205, openHundredGame=true)
 -> ENTER(6105, roomType=51, playMode=2)
 -> MB_REG_ROOMS_REQ(6123)
 -> MB_REG_ROOMS_RES(6224)
 -> MB_REGED_ROOM_INFOS(6227)
~~~

ENTER 请求：

~~~json
{
  "roomType": 51,
  "playMode": 2
}
~~~

服务端返回多个可观察 roomId；后续每桌状态应独立维护。

## 5. 多房间快照

6227 的 roomInfos[] 中每项代表一张百人桌，关键字段包括：

~~~json
{
  "roomType": 51,
  "state": 2,
  "playerId": 49380451,
  "playerNum": 278,
  "points": 9993,
  "countDown": 0,
  "roomId": 39244558,
  "inning": 25112,
  "totalBetsByArea": {
    "1": 15374600,
    "2": 12128900,
    "3": 33245500,
    "4": 8568000,
    "5": 9139200,
    "6": 1332800,
    "7": 190400,
    "8": 81600
  },
  "winningAreas": [1, 3],
  "tieAreas": [],
  "lostAreas": [2, 4, 5, 6, 7, 8],
  "playMode": 2
}
~~~

- roomId：百人桌 ID；
- inning：该桌当前局号；
- state、countDown：阶段和倒计时；
- playerNum：当前房间人数；
- points：本账号百人积分；
- totalBetsByArea：8 个下注区的全桌累计下注；
- winningAreas、tieAreas、lostAreas：当前快照中可见的结算区域；
- ways：走势历史，元素包含红黑和牌型字段。

多个监听桌会同时更新，必须以 roomId 分桶。

## 6. 红黑牌面与走势

百人金花牌面是 hong 和 hei 两方各三张，不是德州扑克的庄家、闲家和公共牌：

~~~json
{
  "showdownPokers": {
    "hong": [37, 51, 44],
    "hei": [24, 46, 6]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  }
}
~~~

发牌阶段未公开的牌可能为 -1。开牌和最终结算以 showdownPokers 为准。

ways 走势示例：

~~~json
{
  "max": 100,
  "targetValue": [],
  "ways": [
    {"heiHong": true, "paiXing": 1},
    {"heiHong": false, "paiXing": 3},
    {"heiHong": true, "paiXing": 2}
  ]
}
~~~

heiHong 表示走势中的红黑侧，paiXing 为牌型枚举；日志没有给出完整牌型映射，应保留原值。

## 8. 阶段和结算

### 8.1 6228 MB_SNC_ROOM_STATE

日志观察到 state=0 至 7。根据字段上下文可归纳：

| state | 可见字段 | 阶段推断 |
| ---: | --- | --- |
| 0 | roomId、inning、cardColor | 空闲或局间 |
| 1 | dealPokers、areaOdds | 发牌与赔率 |
| 2 | areaOdds | 下注阶段 |
| 3 | 基础状态字段 | 阶段过渡 |
| 4 | showdownPokers、showdownTypes | 红黑开牌 |
| 5 | 局号和 cardColor | 结算过渡 |
| 6 | systemTodayTotalScore、systemInningScore、ways | 统计和走势更新 |
| 7 | 局末状态 | 本局收尾 |

这份映射来自日志行为推断，解析时仍应保留原 state 数值。

### 8.2 6229 MB_ROOM_BET_SETTLE

结算样本：

~~~json
{
  "roomType": 51,
  "roomId": 39244558,
  "showdownPokers": {
    "hong": [41, 23, 44],
    "hei": [46, 34, 25]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  },
  "winningAreas": [2, 3],
  "tieAreas": [],
  "lostAreas": [1, 4, 5, 6, 7, 8],
  "areaWinningScores": {},
  "points": -1,
  "realScore": 0,
  "customData": 2
}
~~~

winningAreas、tieAreas、lostAreas 是区域结果依据；牌面和牌型来自 showdownPokers、showdownTypes。points=-1 是该百人消息上下文里的值，不能视为钱包余额。

## 9. 单局流程

~~~text
ENTER(playMode=2)
 -> MB_REG_ROOMS_REQ/RES
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(6228, 发牌/下注)
 -> BET_BROADCAST(6202, 8区总下注)
 -> MB_SNC_ROOM_STATE(state=4, hong/hei开牌)
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204) / MB_SNC_ROOM_STATE(state=6/7)
 -> state=0 / 下一局
~~~

本日志中的单桌状态按 state=2、4、5、6、7、0 流转；同时订阅的其他桌可处于不同阶段。

## 13. 结论

本日志的金花明二百人模式可按以下字段识别：

~~~text
roomType=51
playMode=2
gameRoomConfigId=5102
运行态名称=百人金花
~~~

核心消息链：

~~~text
ENTER(6105)
 -> MB_REG_ROOMS_REQ/RES(6123/6224)
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(6228)
 -> BET_BROADCAST(6202)
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204)
 -> MB_UNREG_ROOMS_REQ/RES(6124/6225)
 -> EXIT(6106)
~~~

客户端应使用 roomId 和 inning 管理多桌局状态，维护 8 个下注区的 totals/odds，并使用 hong、hei、showdownTypes 和中奖区结果更新开奖与走势。
