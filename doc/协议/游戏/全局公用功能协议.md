# 房间公用功能：公正码、旁观列表、实时排名

更新日期：2026-10-24。事实来源为 static/client/2.0.1279 的原始 main/index.88f4e.js、Holdem/index.55219.js 及 Holdem 排名界面 prefab。本次未修改客户端静态文件。

## 1. 实现范围

- 机器人行为、房间排行榜、旁观者列表为全项目公共能力，后续游戏必须复用公共实现。复用代码不等于合并各房间的数据：统计对象、机器人状态和旁观名单始终按真实房间隔离。
- game-server/src/core/robot.js：统一概率入离桌、带入等待、冷却、模拟余额及旁观清理，由 SeatGame.tick 自动调度。具体游戏 robot.js 提供玩法决策；通用生命周期不再复制。
- game-server/src/core/room-features.js：普通座位游戏的旁观列表、累计带入/带出、手数、输赢和实时排名；目前德州与炸金花接入。
- game-server/src/core/fair-code.js：dev 房间内存验码记录、密文、可见牌密钥、权限和过期淘汰；德州与炸金花引擎已接入开局/结算钩子。
- hall/src/fair-code.js：现网 HTTP op=29 的 dev 详情适配；通过已认证的只读房间 WebSocket 查询，连接不加入牌桌。
- 原客户端已自动化核对的完整验码界面为德州现金桌 roomType=19，包括点击验码、手牌分组、公共牌位置及隐藏对手牌。原通用验码页面没有发现 roomType=25（炸金花）或 101（德州比赛）的对应布局分支；不能把这两个类型改成 19 冒充兼容。本次只保证它们的公共后端查询结构，未声称其验码页面已完整接入。
- 百人游戏和 slots 尚未接入本轮统计/验码钩子，需要分别按原客户端协议处理，不能套用德州牌序。
- prod 不生成本地证明；op=29 返回业务码 501，说明正式公正码数据源尚未接入。仓库现有 data-center proto 没有对应的公证详情接口，也未提供权威 lottery 证明协议；不能编造 RPC 或外部证明。

### 新游戏的公共接入约定

1. 座位类继承 SeatGame，复用 createTable/roomInfo/onJoin/onSitDown/onCarryScore/onStandUp/onLeave/onLoginRoom/tick。onMessage 先调用 super.onMessage；1144 排名请求、1130 排名按钮、座位与旁观变动均由公共入口处理。
2. 开局把真实参与者交给 beginHandStats；派彩后把本局结果交给 finishHandStats。它们负责共同的统计口径和重复结算保护；游戏本身只映射真实 uid、净盈亏 score、下注 xiaZhuData。
3. 游戏发送自己的结算消息后调用 room-features.pushRanking({ table, io })，公共层生成并推送排名，不发送会重置结算动画的 ROOM_INFO。成员/旁观变化由 pushObservers 统一先推完整排名再推旁观列表。游戏内不得自行维护另一份排行/旁观缓存或复制排序、去重、推送结构。
4. 仅游戏动作策略、结算数据和客户端协议差异需要适配。不同类型在公共层扩展适配入口，不为每个游戏重做这三项功能。百人类及 slots 的实际接入状态仍以本节范围说明为准。

## 2. 消息号

| 方向 | 消息 | ID | 载荷 |
| --- | --- | ---: | --- |
| C→S | SEND_GAME_RANKING_REQ | 1144 | 当前已进入房间的排名请求 |
| C→S | DATA_REPORT | 1130 | 原通用排名按钮的 buttonCode=realtime_rank_main_btn；服务端同时刷新完整排名 |
| S→C | DZPK_PUSH_RANKINGLIST | 1244 | 排名对象 |
| S→C | DZPK_PUSH_WATCHGAME | 2219 | 旁观者数组 |
| C→S | SEND_BLOCKCHAIN_VERIFY | 2455 | gameRoomId、roomType |
| C→S | SEND_BLOCKCHAIN_INFO | 2456 | gameRoomId、currentInning，可选 roomType |
| S→C | DZPK_PUSH_BLOCKCHAIN_NOTIFY | 3456 | 当前局公正码通知 |
| S→C | DZPK_RESULT_BLOCKCHAIN_VERIFY | 3457 | 可见局的验码列表 |
| S→C | DZPK_RESULT_BLOCKCHAIN_INFO | 3458 | 验码详情 |

原客户端详情主要经 HTTP GET /api/internal/v1/do（同时支持 /internal/v1/do）请求 op=29，再在客户端触发 3458 事件。param 是 Base64 编码查询串，包含 gameRoomId、currentInning；userId 和 token 仍需传入。开发适配复用现有 WebSocket 2456/3458，不新增或重启常驻 HTTP 监听。

## 3. 旁观列表

房间快照字段是 OBmemberList；排名对象中是 obMemberList；2219 的载荷直接是数组，不再包一层对象。每个元素至少包含：

~~~json
{
  "uid": 10001,
  "name": "玩家昵称",
  "userName": "玩家昵称",
  "userIcon": "/avator/90024.png",
  "userInfo": { "uid": 10001, "name": "玩家昵称", "icon": "/avator/90024.png" },
  "winLostScore": 0,
  "totalHands": 0,
  "point": 0
}
~~~

示例仅表示结构；真实值来自玩家资料和房间状态。头像沿用 static/avator 的 ID 映射。玩家入座后从旁观列表排除，站起后重新加入，离开后删除。断线和显式离开共用房间生命周期。纯旁观者的手数及盈亏为 0；曾参与牌局后站起的旁观者保留本房间累计值。

## 4. 实时排名

原德州专用排名面板约每 8 秒请求一次 1144；当前桌面按钮使用 main 的 CommonRankUI，onRankingClick 直接打开缓存并发送 1130 DATA_REPORT，buttonCode=realtime_rank_main_btn，没有主动发送 1144。服务端同时支持这两个入口，返回完整 1244 后再发 2219；其他按钮上报不触发排名响应。

进房、LOGIN_ROOM 重连、入座/带入/站起/离开和旁观变化也先发完整 1244，再发 2219。原客户端 SetRankObUser 会创建或修改 Data_CommonRankData 并 ForceUpdate；若先只发旁观名单，缓存缺失 lastTime，CommonRankUI.UpdateRestTime 会显示 NaN:NaN:NaN。这是数据下发顺序问题，不能靠替换客户端时间格式化方法处理。结算完成后仍广播 1244，不发送会重置结算动画的额外 ROOM_INFO。

userList 每行包含 uid、userName、userIcon、userInfo，以及以下数字：

| 字段 | 含义 |
| --- | --- |
| totalPoint | 本房间累计成功带入；机器人初始筹码按带入登记一次 |
| carryOutPoint | 本房间累计带出 |
| totalHands | 本玩家已结算手数 |
| totalStream | 本玩家在该房间累计已结算下注，含底注、盲注；新统计对象从创建开始累计 |
| winLostScore | 已结算净盈亏；不含带入、带出 |
| onTableFlag | 1=当前在座，0=已经站起或离开 |
| point | 当前桌上可用筹码；不在座为 0 |

顶层字段：

| 字段 | 含义 |
| --- | --- |
| userList | 所有曾在本房间入座的玩家，含离桌历史 |
| obMemberList | 当前旁观列表 |
| totalHands | 房间已结算局数 |
| totalStream | 已结算牌局实际投入的总筹码，含底注、盲注和动作下注 |
| totalTakeIn | 所有玩家累计带入之和 |
| averagePot | 已结算底池平均值，内部积分整数 |
| currentActivePoint | 活动积分；当前引擎未累计此业务值时为 0，不能用座位筹码之和代替 |
| gameTime | 普通房间固定生命周期 28800 秒（8 小时），不是已运行时长 |
| lastTime | 从创建时间计算的剩余秒数，向上取整且最低为 0；到期等待当前局结算时为 0 |
| taxType / taxPercent | 当前游戏启用的税费配置，现有德州为 0 / 0 |
| insuranceProfit | 保险盈亏；现有引擎未启用保险，返回 0 |

原客户端对金额除以 100 显示；服务端保留内部积分单位，禁止重复缩放。排序为当前在座优先，再按净盈亏降序。统计按局号防止重复结算；途中离开的玩家保留本局下注引用，在结算时计入损失。

房间创建即初始化 roomFeatures，players 按 uid 关联该房间所有曾入座玩家（真人和机器人），从创建到销毁持续累计。站起、离开或清空当前座位不删除记录，同一 uid 再进入继续累加；仅旁观玩家留在 obMemberList。排名请求直接读取房间内存，热更新复用同一对象，不以请求时的当前玩家列表重算或覆盖历史，不跨房混榜。到期后等待最后一局结算期间保留统计，带出及解散完成才释放。首次部署到既有房间时，只登记当前可确认的桌上筹码和此后事件，不伪造部署前带入或已丢失的历史输赢。

房间快照 ROOM_INFO 的 leftTime 与排名 lastTime 共用同一创建时间；dzpk.gameTime / dzpkParams.gameTime（炸金花为 ctjh / ctjhParams）均为 28800 秒，原客户端桌面设置、分享和游戏参数直接读取这些嵌套字段，不能只给顶层 gameTime。旧德州快照入口也必须包含有效 leftTime。空房间不提前回收，八小时到期后停止开新局、当前局结算后销毁；详见 房间生命周期与扩容.md。

## 5. 公正码详情

3456 通知：gameRoomId、roomType、currentInning、notarizationCode。每局生成一次，并在底注、盲注和发牌消息之前广播；重新查询或热更新不能换码。

3457 列表按局号倒序，每项为 gameRoomId、roomType、currentInning、status、endTime、handPais、notarizationCode：

- 进行中 status=20，仅显示原密文，handPais 为空，原客户端禁止解码。
- 已结束 status=10，endTime 为结束时间字符串；handPais 仅为请求者自己的手牌，旁观者为空。
- 已结束行的 notarizationCode 留空是原客户端的取详情开关，点击后请求 op=29；详情仍返回开局时的原码。

op=29 成功响应外层为 msgCode=200、errMsg=null、data=详情对象：

~~~text
data = {
  gameRoomId, roomType, currentInning, notarizationCode,
  pokerList: [{ currentInning, position, pokerInfo, encryptedStr, secretKey }],
  roomConfig: JSON.stringify({
    playerIds: [玩家 UID，顺序对应 position],
    playerShowStatus: { 已公开手牌的 UID: true },
    cutCardIndex: 0,
    roomConfig: { forceShowCard: false }
  })
}
~~~

pokerInfo 必须是 JSON 字符串，解析后包含 index（实际牌 ID）、position（从 1 开始的发牌玩家序号，非手牌为 -1）、action（实际座位号加 1 的字符串）、currentInning、gameRoomId，以及 flop/turn/river 标识。position 和 action 不可混同，座位可能不连续。

dev 将真实牌序的 52 张牌逐张以 AES-256-ECB、默认 PKCS#7 填充加密。encryptedStr 为 Base64 密文，每张牌使用独立随机的 32 字节 UTF-8 密钥 secretKey；密文按顺序拼接为 notarizationCode，匹配原页面复制密文和密钥的行为。此记录绑定本地发牌，不构成第三方或链上公证。

进行中 pokerList 不下发真实牌值和密钥。结束后仅对本人手牌、结算已公开的手牌和实际发出的公共牌返回原 pokerInfo 与 secretKey。其他牌只返回原 encryptedStr、空 secretKey 和脱敏 pokerInfo；隐藏手牌使用唯一负 index 供原客户端 getCardByPokerIndex 定位，非手牌隐藏值为 -1。不得把明文或密钥写入普通日志。

德州新局真实发牌包含 flop/turn/river 前各烧一张；公共牌在底牌区域结束后的相对下标为 1、2、3、5、7，与原客户端验码视图相符。热更新前已开始的旧局没有 burnBeforeBoard 标志，继续旧布局并且不补造证明；新局才采用新布局。

## 6. 权限和生命周期

- 按认证资料中的 agentId 查房间，不能信任请求提供的代理。相同房号命中多个游戏且请求未消歧时拒绝查询。
- 每局记录开局时的参与者/旁观者；进行中加入并取得当前公正码的玩家也可查看。局结束后才加入者不能追查不属于自己的旧局。
- 验码只读连接仅认证与查询，inRoom=false，不收游戏广播；关闭连接不调用离桌、不持久化钱包、不改变筹码。
- dev 每房间最多 128 条记录；已结算记录 TTL 为 24 小时，查询或开局时惰性淘汰，房间回收或进程退出后全部释放。
- HTTP 返回业务码：400 参数无效，401 登录失败，404 不存在/过期/无权查看，503 房间服务不可达或超过 3 秒，501 正式数据源未接入。响应设置 Cache-Control: no-store。
- prod 后续必须按真实 lottery/data-center 接口实现，查询 ES 仍只能由 data-center 承担。本次没有新增 ES 直连或生产 Redis 查询旁路。
