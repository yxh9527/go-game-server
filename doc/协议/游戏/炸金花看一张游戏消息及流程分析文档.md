## 5. 看一张流程

### 5.1 底注和发牌

玩家先支付 `ante=10`。`3727 ZJH_DEAL_DI_PUSH` 可能返回：

```json
[
  {"uid":"<uid>","cardList":[-1,-1,-1]},
  {"uid":"<uid>"}
]
```

日志中当前玩家出现 `cardList=[-1,-1,-1]`，表示三张牌均未授权显示。看一张场的关键是客户端逐步获得一张牌的可见权限，而不是直接收到三张完整底牌。

### 5.2 看牌权限

`3260 NIUNIU_INNING_BEGIN_INFO` 和 `ROOM_INFO.memberDeskInfos` 会保存牌面状态。解析器应区分：

| 字段 | 含义 |
| --- | --- |
| `handPais` | 当前已知的三张牌；未知牌使用 `-1` |
| `isLooked` | 玩家是否已经看牌 |
| `isShow` | 是否已经公开展示 |
| `lastOperation` | 最近操作值 |

日志中没有独立的 `LOOK_ONE_CARD` 消息，具体看牌动作应由通用 `ZJH_SEND_ACTION` 的 operation 枚举承载，并通过服务端状态和底牌推送反映结果。不能仅凭单条日志固定看牌操作编号。

### 5.3 轮次和下注

`3756 ZJH_PUSH_ROUND_INFO` 返回当前轮数，`3733` 返回当前玩家和 11 秒倒计时，`3780` 返回可用操作：

- `5001 SEND_CARRY_SCORE`：提交补分。
- `3230 CARRY_SCORE_RESULT`：补分结果。
- `3445 PUSH_CARRYIN_TIPS_USER_LIST`：新玩家补分提示。
- `2208 USER_STATE_CHANGE`：座位状态。
- `3436 USER_STANDUP_ROOM`：玩家离座。
- `2219 DZPK_PUSH_WATCHGAME`：观战列表刷新。
- `6106 <game>EXIT roomType=51`：辅助连接退出。

日志中出现 `SEND_SITDOWN(position=0)`，说明用户可以从旁观状态重新坐入指定座位；进入坐下后，后续牌局快照中的 `uidList`、`memberDeskInfos` 和下注权限会改变。

## 8. 实现建议

1. 使用 `gameType=25`、`roomType=25`、`gameRoomConfigId=2503`、`playMode=5` 识别看一张场。
2. 以 `ctjhParams.ante=10`、`carryMin=100`、`maxRounds=8` 初始化规则。
3. 将 `handPais=-1` 解释为牌面不可见，维护 `isLooked`、`isShow` 和已知牌数量。
4. 不要把看一张动作硬编码为固定 operation；使用服务端 `ZJH_ACTION_BET_PUSH`、`ROOM_INFO` 和底牌消息的组合判断。
5. 使用 `3740` 处理下注结果，`3756` 处理轮数，`3741` 处理亮牌，`3732` 处理结算。
6. 三张牌结构使用 `pokerEnumList`、`handCardList`、`holeCardList`，不能按德州牌型解析。
7. `SEND_SITDOWN` 是旁观者坐入指定位置的生命周期消息，应与牌局状态独立处理。
8. 生产日志不要输出 token、openId、设备 ID、IP 编码值和完整玩家资料。
