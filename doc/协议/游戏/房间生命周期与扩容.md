# 普通房间生命周期与容量扩容

更新日期：2026-10-24。影响 hall、game-server；原始客户端静态包不修改，服务进程不重启。本次按用户确认的“到期结算完当前局”和“完全满座房间比例”实现，替代原先最后真人离开就回收的规则。

## 1. 房间时钟和回收

- 创建时记录 createdAt（毫秒），expiresAt = createdAt + 28800000。空备用房也从实际创建时计时。
- 玩家退出、全部真人离开、只剩机器人、无人旁观，都不会提前删除或重置计时。已启用的机器人仍走原动作/结算入口。
- 满八小时，房间不再接受新分配、入座、带入，不允许 starting 状态发出新一局。
- 若 phase=playing，继续当前牌局的玩家动作、机器人动作及超时处理，正常结算后回收；不截断手牌，不把未决下注当作退注。
- 回收顺序：记录各真人剩余筹码 → 关闭成员动作 → 调用钱包 credit/persist → 推送余额和解散消息 → 清除成员、旁观、手牌、房内回顾/验码及管理索引。机器人积分不写真人钱包。
- 钱包持久化失败时保留 closing 房间供下次 tick 重试；已完成 credit 的玩家不重复入账，房间也不会被再次分配。
- 当前依托常驻进程保存状态；业务热更新保留 createdAt、房号分配进度和未完成带出。旧房间没有 createdAt 时优先采用统计模块 startedAt，两者均无记录时以首次接入生命周期时刻计时，不能编造历史时间。
- 已用房号的分配进度在常驻 registry 上保留。销毁后大厅分配新房号，直接使用旧房号的连接收到房间解散消息，不重建旧房间。

## 2. 扩容口径

池身份为可信 agentId + gameId + roomType + gameRoomConfigId + playMode。不同代理、游戏或配置不能互相填补容量。当前自动分房/扩容接入普通现金桌德州 roomType=19 和炸金花 roomType=25；比赛 roomType=101 由 match 分桌，不参加现金桌自动扩容，百人和 slots 不套用座位满座率。

~~~text
N = 未到期且未关闭的房间总数（包括空备用房）
F = 其中所有有效座位都已占用的房间数
当 N > 0 且 F / N >= 80%：
  新建空房数量 = max(1, ceil(N × 5%))
~~~

座位按合法 pos 去重；真人、机器人和已占座等待带入的成员都占座，旁观者不占座。

| 场景 | 结果 |
| --- | --- |
| 5 间七人桌，每间坐 6 人 | 30/35 座位有人，但满座房数为 0，不扩容 |
| 5 间房，4 间完全满座 | 4/5=80%，新建 ceil(5×5%)=1 间 |
| 100 间房，80 间完全满座 | 新建 5 间 |
| 21 间房全部满座 | 新建 ceil(21×5%)=2 间 |

每次检查只按检查开始时的分组快照扩一批；新增空房立即计入下次的分母。若下次检查仍达到 80%，可继续扩一批。入房/座位动作和周期 tick 都会检查；扩容失败只记录错误，不阻断已有玩家动作或结算。

备用房是已经登记的真实房间，standby=true，members/observers 为空、phase=idle。不调用 onJoin，不生成机器人、不发牌。首次实际 WebSocket 入房后取消 standby，调用既有游戏入房逻辑；真人仍旁观，德州、炸金花机器人由后续 tick 按概率逐个入座，不在进房回调中立即补满。

## 3. 大厅与房间服务衔接

- op=38 保持原客户端配置列表结构；totalPeople 聚合该配置活动房间的在座人数，不含旁观者。仅打开列表不会创建房间。
- op=45 先找请求的未满座活动房间，再找同池其他有空座房间，均无则创建。返回实际 roomId、roomIndex、roomType、gameRoomConfigId、playMode，继续既有 domain 和客户端字段。
- 房号沿用 gameRoomConfigId × 10000 + roomIndex；同池分配进度热更新保留，不复用已销毁房号。索引达到 10000 时停止该配置分配并返回不可用，不覆盖已有房间。
- hall 通过现有 game-server WebSocket 监听发出后端 JSON 查询，type=room-pool，action=list/allocate。allocate 附带配置 ID、roomType 和请求的 roomIndex；响应 type=room-pool-result，code=200 时返回 data。
- 查询必须携带 userId/token，并由 game-server gateway 认证和加载可信 agentId；请求传来的 agentId 不使用。查询不建立游戏 session、不加入旁观/座位、不读写钱包，关闭查询连接不会触发真人离桌。
- 单个查询帧上限 8192 字节；hall 超时 3 秒。无效身份返回 401，找不到启用配置返回 404，分配异常/连接失败返回 503；外层保持 msgCode、errMsg、data。
- 此 JSON 查询属于后端内部适配，不是新增客户端消息号，也不要求修改原始客户端。

## 4. 客户端已有消息

- ROOM_INFO：gameTime=28800，leftTime=max(0, ceil((expiresAt-now)/1000))。
- 房间参数和快照中的 dzpk.gameTime / dzpkParams.gameTime（炸金花为 ctjh / ctjhParams）均同步为 28800，供原客户端设置/分享面板读取。
- 实时排名 1244：gameTime=28800，lastTime 使用同一倒计时。等待最后一局结束时倒计时为 0。
- 排名是该房间整个生命周期的内存累计统计，离桌历史保留至回收。推送旁观列表 2219 前先推完整 1244；原通用排名按钮上报 1130 / realtime_rank_main_btn 时刷新完整排名，避免缓存缺失 lastTime 导致 NaN。
- ROOM_DISSMISS=2204，载荷 { roomId }。原 main 客户端 onPushRoomDissMiss 匹配当前房号，显示房间解散提示，确认后走原 gotoClub 返回入口。
- 当前局先广播正常结算结果，再进行带出和房间解散，禁止用 USER_LEVEL_ROOM 代替整桌解散。

## 5. 入座后的 12 秒带入流程

- 原客户端点击座位发送 SEND_SITDOWN=5003，参数 { position }。服务端立即占座、移出旁观列表，先下发 JOIN_ROOM=2202 和 ROOM_INFO=2206，再发送 CARRYIN_RESULT=3229 打开带入面板；占座不等于参与本局。
- 零筹码新座位保存 carryDeadline=占座时间+12000（毫秒时间戳）。座位快照 carryLeftTime=max(0, carryDeadline-now)；带入面板 leftTime 使用相同剩余毫秒，isByServerSettle=true，原客户端据此显示倒计时。不同于房间剩余时间 leftTime 的秒单位，不能混用。
- SEND_CARRY_SCORE=5001 的 carryIn 是显示单位，乘 100 后校验为有效正整数积分。成功扣款并入账后清除初次带入截止时间，正常参加下一次可加入的牌局。余额不足、金额无效或低于最小带入不重置期限；正常补分、全下或输光筹码不重新触发初次带入超时。
- 常驻 tick 检查到期零筹码座位，广播 USER_STANDUP_ROOM=3436（数值 uid），释放座位并加入本房旁观，继续推送房间快照、完整排名 1244 和旁观列表 2219。原德州客户端站起处理会关闭带入窗口。不发退出房间/解散消息，不对未参局成员执行弃牌或资金带出。
- 每个带入请求在扣款前同步核对截止时间，即使 tick 尚未执行，达到 12000 毫秒也拒绝扣款。5001/5002 不能重新创建座位；超时后重新点击 5003 才可开始下一次占座。重复点击、重新打开面板及登录快照均使用原 deadline，业务热更新保留它。
- 实现位于 SeatGame，德州和炸金花共用；不修改原客户端静态包。未带入座位计入占座率但不加入发牌名单，超时处理不改变正在进行的机器人牌局。仅对有初次带入 deadline 的座位生效，不按 point=0 批量踢人。

## 6. 每局结算后的准入检查

- 普通现金桌按本房配置 carryMin 检查结算后的桌上 point，单位与初次带入一致。point 小于 carryMin 或为零就强制站起；等于门槛可以继续。账户 wallet 充足不代表桌上筹码满足准入，不自动从钱包补分。
- 德州、炸金花共用 SeatGame.afterRound；常驻 handler 在玩家动作、站起/退出、机器人动作及超时 tick 造成的结算后调用，并在开下一局或后续座位操作前完成检查。进行中不检查，因此全下尚未派彩不会提前出局。比赛桌 101 仍走 match 的淘汰规则。
- 首次占座的 12 秒带入截止时间仍独立有效；未超时且尚未带入的座位不因别人的牌局刚结算而被提前移除。已完成带入的玩家结算后筹码不足，直接站起，不再额外保留 12 秒补分机会。
- 检查真人和机器人。真人剩余筹码经现有钱包接口带出、持久化后释放座位，保持当前房间连接并加入旁观，推送 GAME_POINT_UPDATE。机器人剩余模拟筹码移至旁观记录，不写入真人钱包，不在原座位直接补满。后续补充机器人避免重用仍在旁观列表的 uid。
- 消息顺序为本局 SETTLE/结算结果 → USER_STANDUP_ROOM=3436（数值 uid）→ 完整排名 1244 → 旁观 2219。不广播 ROOM_INFO=2206，避免原客户端重新登录快照打断结算；原德州客户端在 SETTLE 时把站起加入离桌队列，待结算动画完成处理。
- 带出量不计作输赢，八小时房内累计手数、输赢、带入/带出保留。roundAdmission 持有本局待带出账本，逐项记录 credited、persisted、removed；失败重试不重复加钱，完成前暂停开新局。admissionTask 挂在常驻房间，热更新、并发 tick 与断线共享同一任务。
- 已到八小时截止时间的房间沿用整桌销毁退款。若带出检查已经开始则先完成，避免与销毁重复退款。全部真人/机器人站起也不提前销毁该房间。

## 7. 机器人概率入桌、离桌

- 公共调度与唯一默认参数在 game-server/src/core/robot.js，由 SeatGame.tick 自动调用，均参与版本化热更新。德州和炸金花不再定义各自 tick/queueStart/入离桌参数；后续新增 SeatGame 子类同样直接继承。持续 tick 驱动，与真人是否在线无关；standby、比赛 101、到期/关闭和结算带出重试中的房间跳过调度。
- 配置优先级为 core/robot.js 的 roomBehavior → 游戏 config.robotBehavior → 房间 cfg.robot_behavior，未设置的参数继承公共值，概率取 0–1，时间单位为毫秒。这些数值是可调整的行为默认值，不代表采集到的真人行为数据。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| joinProbability | 0.6 | 有容量时每次检查的入座概率，每次最多一名 |
| leaveProbability | 0.15 | 每名合资格机器人独立离桌概率 |
| checkMinMs / checkMaxMs | 5000 / 10000 | 周期检查的随机间隔 |
| minStayMs | 45000 | 初次入座后最短停留时间 |
| cooldownMinMs / cooldownMaxMs | 15000 / 45000 | 站起后再次考虑入座的冷却 |
| carryMinMs / carryMaxMs | 1000 / 3000 | 占座到提交带入的模拟思考时间 |
| observerLifetimeMs | 180000 | 持续旁观后退出并释放机器人对象的时长 |
| walletBuyIns | 5 | 新模拟账户初始正常带入份数，范围 1–10 |

- 入座概率为 0 时不新增座位，离桌概率为 0 时不主动离桌；结算筹码不足的强制站起仍正常执行。周期、冷却、带入延迟至少 1 秒，带入延迟最多 10 秒，保留 12 秒超时处理。既有 botTarget 只作为机器人数上限，不再作为立即填满指令；为真人保留至少一个可用空位。
- 机器人先建立模拟 session，调用 watch/onSitDown，立即占位、point=0、carryDeadline=now+12000；延迟后调用 onCarryScore，carryIn 仍按客户端显示单位提交，公共流程转为积分并校验门槛。未成功带入不发牌。新机器人正常带入为 max(carryMin, 大盲×100)（德州）或 max(carryMin, 底注×50)（炸金花），模拟账户余额不足时最多使用余额，仍需满足最低准入。
- 每局结算后，等 startAt 所标记的结算展示时间结束，在下一局发牌前对满足最短停留的机器人抽取一次离桌概率；与周期入座定时器独立，不会因为定时器落在牌局中而漏掉。空闲期间按周期判断。当前局进行中不随机站起或弃牌；中途入座的机器人等下一次发牌参加。
- 站起调用公共 onStandUp：剩余桌上筹码返还同一模拟账户，记入本房带出统计，转旁观并启动随机冷却。强制低筹码站起也返还到同一账户并经过冷却。重入沿用 uid、余额和八小时累计统计，不自动重置资金；观察超时后退出才释放对象，新身份不复用本房历史 uid。旧版本机器人接管时保留原有桌上/旁观筹码，额外模拟余额不补发。
- 座位更新广播 JOIN_ROOM=2202（含 userInfo/pos/point/carryLeftTime）、CARRY_SCORE_RESULT=3230、USER_STANDUP_ROOM=3436，再发完整排名 1244 和旁观 2219；旁观退出发送 USER_LEVEL_ROOM=2205。不会为机器人广播 ROOM_INFO=2206 重新触发客户端 loginSuccess。结算展示期间不新增入座、不主动离桌；低筹码强制站起仍交由原客户端结算队列处理。
- 原德州/炸金花 AllSeat.carryInResult 在 state=0 时只停止倒计时并返回，不更新 point。机器人带入成功时必须先补发该座位最新的 JOIN_ROOM，原 AllSeat.userJoinRoom 会更新同 uid/pos 的筹码，再广播带入成功；不能仅移除 ROOM_INFO 后依赖 CARRY_SCORE_RESULT 更新余额。
- nextCheckAt、最后已做离桌判断的局号、机器人 session/余额、入座时间、冷却与待带入时间均存于 table.robotTraffic。业务热更新保留这些数据；实际八小时销毁后清空，不能重置房间 createdAt/expiresAt。
- 新游戏接入：继承 SeatGame，提供 maxPeople/minPeople、carryMin 等玩法配置，完成 startRound/playTick/动作/结算及自己的 robot.js 策略即可；不要再次调用 core/robot.tickRoom 或复制 tick。正常带入金额由可选 defaultBuyIn(table) 返回，默认按 carryMin，现有德州/炸金花覆盖金额计算，公共 buyIn 统一限制账户余额。结束牌局时维护公共统计、phase/hand/startAt，handler 统一执行 afterRound。旧引擎 ensureBot(s) 仅供遗留直接调用/测试，正常服务不能用它补座。
- 本节桌位规则对所有 SeatGame 子类通用，未使用德州/炸金花 ID 白名单；比赛 101 保持 match 管理边界。百人类和 slots 仍使用各自基类，不收到不适用的座位和带入协议。
