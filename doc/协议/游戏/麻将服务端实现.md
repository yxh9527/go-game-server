## 公共流程

入房默认旁观；主动点击入座立即占座，12 秒内完成带入。房间八小时、无人连续三局后挂起、结算后准入检查、站起带出、下局站起、旁观列表及八小时排名均复用 SeatGame 和 core。

麻将必须达到该模式完整人数才开局。公共机器人调度在真人尚未占座时保留空座；满员开局玩法有真人占座后，可补齐其余座位。机器人仍通过同一入座、带入与出牌校验入口操作，未带入的座位不发牌。旁观真人不会被自动入座。只有旁观、人数不足时等待开局。

已发牌玩家局中离桌/离房不能提前退款或移除责任筹码；标记离场后托管本局，结算再由公共 afterRound 带出，失败重试不得重复记账。额外带入与输赢分开，排名统计使用实际支付的积分。

牌序在开局前固定，牌面编码：筒 0–8、条 9–17、万 18–26。长沙 108 张；血流加八张红中 27，共 116 张；极速四人 124 张，二人只保留万、三种字牌及四张花，共 52 张。极速 27/28/29 是字牌，30 是 GO 花，不能与血流红中混用。

牌序不可在摸尾牌时重排；普通摸牌和杠尾从同一物理牌序的两端消耗。手牌与物理下标一起移动，换三张保持真实物理身份。

血流换牌请求 3653、完成 3862、开始 3859；定缺请求 3652、本人确认 3863、全体完成 3861、开始 3860。提示 3868。血流倒计时为毫秒，极速和长沙为秒。

发牌、动作、重连快照按接收人生成。仅本人获取真实暗手及可选操作，其他玩家/旁观者获取张数或 -1，暗杠对手只见背面。换三张内容、未完成的定缺选择不能向其他人泄露。机器人策略位于 robot.js，只接收自己的手牌和公开信息。

红中血流 `extend.outIndex` 是客户端当前渲染手牌的下标，**不是弃牌堆序号**；服务端不发送该值，让原版客户端按牌面查找。碰杠及胡牌重建手牌时必须补充本人真实 handCards，对手保持遮罩。自摸胡牌后胡牌移到胡牌展示区，暗手张数先减少再推送；点炮牌从弃牌堆移出，公开计牌仍保留该物理牌一次。

红中血流正常出牌轮转必须先发 `3853 type=1` 摸牌状态，再发 `3852` 操作人；庄家定缺后的首次出牌也遵守该顺序。原版手牌组件只在收到 `3852` 时检查当前手牌张数并启用点击，倒序发送会在摸牌前检查，导致轮到本人仍无法点击。碰牌后的副露也须在 `3852` 前更新。浏览器回归通过原版手牌的选牌、再次点击确认流程验证请求被服务端接受，不能只直接发送 `3650` 来替代点击验证。

## 玩法实现

### 极速

五张成牌，一副顺子或刻子加一对；只能自摸，可碰、杠。按原帮助的牌点、普通听/天听、清一色、碰碰胡、字一色、天地胡、杠上开花进行加番。加番牌在本局固定，手牌中每张额外一番。

每摸到一张花，向其余玩家收取一番底分，记为独立补花类别；发牌补花也一样，胡牌不再重复收取。四花触发固定 200 番的花开富贵结算。点杠由放杠者支付四人三番/二人一番，暗杠每人两番，补杠每人一番。余额不足按可支付金额结算。

**用户于 2026-10-28 确认：翻奖花额外奖励概率为 0，详细规则后续提供再开发。** 当前保留原版胡牌后的翻牌展示，fanjiangFan、fanjiangScore 均为 0，不发放额外奖励，不推断中奖公式。

### 长沙

普通胡要求二五八将；特殊大胡按帮助图片识别。支持吃、碰、杠、补；补不锁听、不加杠上开花倍率。真正的杠必须在去除杠牌后可听，杠后锁定摸打，从牌尾取四张；可胡牌逐张计分，未胡的杠尾批量公开弃出，其他玩家可响应胡牌。补杠保留抢杠窗口。杠后不允许吃碰或任意改变手牌。

起手胡等全部玩家选择后统一处理，避免先到消息影响多家宣告的骰子锚点；中途小胡仅由新摸进的牌形成时提供。骰子按帮助重掷 5/6，实际结果在 1–4；单家以赢家、多家以庄家为锚点计算命中与小胡分数。扎鸟从另一副牌取两张，在开局时预定，不消耗主牌墙或海底牌；命中数据与结算分数同时返回。本地公正码目前只验证主牌墙，不包含独立牌副的扎鸟随机结果。

剩最后一张时依次询问是否要海底牌，全体不要则流局。要牌后能胡结算海底捞，否则必须海底打出，仅提供其他玩家胡牌窗口。长沙额外推送庄位 4209、小胡亮牌 4210、听牌概览 4211 与操作确认 4213。

### 红中血流

八红中作赖子，换三张同花色牌，定缺后优先打缺门；不可吃，不能抢杠。普通点炮不胡，仅总番达到 128 才开放接炮。胡后继续摸打到牌墙结束；红中打出作红中杠并补牌。基础番型取最高项，附加番相乘，上限 512；胡牌结构、赖子使用及固定刻子须同时满足，不能重复使用同一张赖子补两个条件。

流局检查花猪与查叫，按实际听牌番值结算。每次胡与最终结算均返回积分变化。转账按同一批请求分配短余额，避免先收到的胡牌响应独占赔款；整数积分、税费及带入分别记账。

## 回顾、公正码与外部依赖

dev 回顾放 `cache/game-server/mahjong-history.js`，按房间保存最多 1000 局/八小时，支持当前局、范围分页、上一局下一局和 HTTP op=46 详情。仅参与者与当局已进入房间的旁观者可读；未在场玩家不能查询。保留原版 playerList、userInfo、handCards、groupCards、huRecord、比分及 JSON 字符串详情。

本地公正码复用公共模块，发牌前提交真实整副物理牌序；结算仅公开已实际揭示的物理牌下标，未摸出的牌即使同牌面也不公开密钥。

**生产边界**：正式回顾存储/查询、lottery 公正码与正式注单仍需既有外部服务合同及联调；本次不连接 ES，不在 game-server 自建查询，也不把 dev 内存历史冒充正式 Redis/ES 回顾。正式部署前必须接通 data-center 查询、Redis TTL 缓存、lottery 与资金注单，不能据本地通过声称生产完整接通。

正式默认数据准备在 `doc/patches/mahjong_seed.go`，注册改动见同目录 `mahjong_seed_registration.patch`，只插入缺少的配置身份，不覆盖管理端已有配置。目标为 `D:/project/gogames/app/tables/gogame`。本次跨目录写入因自动审批工具故障未执行；补丁留在可写仓库供审核，未执行数据库建表或灌库。
