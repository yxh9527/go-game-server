### 2.2 服务端最终配置


| 字段 | 值 | 含义 |
| --- | --- | --- |
| `gameRoomConfigId` | `1928` | 不秀牌暴击房间配置 |
| `playMode` | `3` | 服务端实际暴击玩法 |
| `criticalFlag` | `true` | 开启暴击规则 |
| `criticalAnte` | `100` | 暴击配置前注/基数，具体扣取公式需更多样本确认 |
| `criticalInterval` | `5-8` | 暴击区间配置 |
| `forceShowCard` | `false` | 不强制全员展示底牌 |
| `smallBlind/bigBlind` | `10/20` | 普通盲注结构 |
| `initialBet` | `20` | 普通德州初始下注 |
| `straddle` | `false` | 不开启 straddle |
| `openInsurance` | `true` | 能力开启，但本次强制保险响应为关闭 |

这是“暴击”和“不秀牌”同时开启的组合：暴击由 `criticalFlag/criticalAnte/criticalInterval` 表达，是否秀牌由 `forceShowCard` 独立控制。不能因为 `criticalFlag=true` 就认为结算会全员亮牌。

## 3. 进房和连接流程

客户端先调用大厅 `op=45`，服务端返回房间号和连接域名。随后客户端发送 `1105 ROOM_LOGIN`：

```json
{
  "isAutoLogin": true,
  "userId": "<uid>",
  "openId": "<openId>",
  "userToken": "<token>",
  "version": "<client-version>",
  "cVersion": 20240607,
  "deviceId": "<deviceId>",
  "language": 1,
  "openHundredGame": false,
  "clubId": "<clubId>",
  "packetId": 5,
  "isApiLogin": true,
  "currency": "CNY",
  "plat": 4,
  "roomId": "<roomId>",
  "isInRoom": false
}
```

主连接的流程为：

1. `1205 ROOM_LOGIN`：服务端登录上下文。
2. `2102 SEND_JOIN_ROOM`：申请进入房间。
3. `2219 DZPK_PUSH_WATCHGAME`：观战玩家列表。
4. `2201 ROOM_TYPE_RESULT`：返回暴击不秀牌配置。
5. `2117/2220 SEND_GAME_SETTING/DZPK_PUSH_GAME_SETTING`：游戏设置。
6. `3178/3465 DZPK_FORCE_INSURANCE_CONF_REQ/RES`：强制保险配置，样本返回 `{switch:false,ratio:0}`。
7. `2200/2221 COMMON_SWITCH_REQ/RES`：通用开关。
8. `2111 LOGIN_ROOM`：正式进房。
9. `2206 ROOM_INFO`：同步座位、玩家、旁观者、局号和规则。

日志进入时已经处于 `DEAL_FLOP`，`3260 NIUNIU_INNING_BEGIN_INFO` 提供了翻牌、底池和当前玩家摘要，属于中途恢复，不是新局起点。

## 5. 游戏流程

### 5.1 状态机

日志可观察到的状态序列：

```text
BET_FRONT
 -> BET_BLIND
 -> DEAL_PERFLOP
 -> BET_PERFLOP
 -> DEAL_FLOP
 -> BET_FLOP
 -> DEAL_TURN
 -> BET_TURN
 -> DEAL_RIVER
 -> BET_RIVER
 -> SETTLE
```

日志开始时牌局已经在翻牌阶段，恢复快照中的 `flopPokerList`、`pot`、`roundBetMap` 和 `memberDeskInfos` 用于重建当前局面。

### 5.2 常规下注

客户端动作：

```json
{"uid":"<uid>","operation":7,"operationData":0.1}
```

服务端确认：

```json
{
  "uid": "<uid>",
  "currentBetScore": 10,
  "totalBetScore": 40,
  "operation": 7,
  "point": 460,
  "pot": 160
}
```

本次日志观察到的操作值包括：

| operation | 日志表现 | 说明 |
| ---: | --- | --- |
| 1 | 多名玩家投入 20 | 前置下注 |
| 2 | 小盲/大盲投入 10/20 | 盲注 |
| 3 | 增加到跟注额度 | 跟注或补齐 |
| 4 | 大额增加，底池扩大 | 加注 |
| 6 | `currentBetScore=0` | 弃牌候选动作 |
| 7 | `operationData` 为下注倍数 | 下注/加注 |
| 9 | `point=0` 或投入剩余分 | 全下候选动作 |
| 10 | 不再继续下注 | 弃牌/结束行动候选动作 |
| 12/15 | 特殊加注 | 必须结合客户端枚举确认 |

服务端 `3440 DZPK_ACTION_BET_PUSH` 是动作是否生效的依据。

### 5.3 发牌和不秀牌

`forceShowCard=false`，所以该玩法不会像秀牌或 AOF 那样在结算前统一推送所有人的底牌。`3441 DZPK_ACTION_SHOWCARD_PUSH` 只在特定玩家需要展示时出现，本次日志中只出现少量玩家的亮牌消息。

| 状态 | 消息 | 说明 |
| --- | --- | --- |
| `DEAL_PERFLOP` | `DZPK_DEAL_DI_PUSH` | 发底牌通知 |
| `DEAL_FLOP` | `DZPK_DEAL_FAN_PUSH` | 3 张翻牌 |
| `DEAL_TURN` | `DZPK_DEAL_ZHUANG_PUSH` | 1 张转牌 |
| `DEAL_RIVER` | `DZPK_DEAL_HE_PUSH` | 1 张河牌 |

### 5.4 暴击和保险

暴击部分由房间配置表达：

```json
{
  "criticalFlag": true,
  "criticalAnte": 100,
  "criticalInterval": "5-8"
}
```

本次日志没有独立的 `CRITICAL_*` 消息，也没有明确 `criticalScore` 或暴击倍数字段。暴击实际金额不能仅凭 `criticalAnte=100` 推导，最终仍应观察 `3432` 中的 `score`、`point` 或后续专属字段。

房间配置 `openInsurance=true`，但 `3465 DZPK_FORCE_INSURANCE_CONF_RES` 返回关闭。出现的保险提示或胜率消息应视为旁路能力，购买资格由具体牌局的 `switchOn`、`ratio` 和提示字段决定。

## 6. 补分、回放和退出

房间 `carryMin=500`，补分流程使用：

- `3445 PUSH_CARRYIN_TIPS_USER_LIST`：可补分用户和 12 秒倒计时。
- `3229 CARRYIN_RESULT`：补分范围、账户余额和剩余时间。
- `5001 SEND_CARRY_SCORE`：客户端提交补分，例如 `{carryIn:5}`。
- `3230 CARRY_SCORE_RESULT`：服务端返回实际补分结果。

退出/离座通常包含 `2110 SEND_LEVEL_OUT`、`3436 USER_STANDUP_ROOM`、`2205 USER_LEVEL_ROOM`、积分更新以及辅助连接的 `6106 <game>EXIT`。回放使用 `3167 DZPK_SEND_GameBackReq` 和 `3446 DZPK_PUSH_GameBackMsg`。

## 8. 实现建议

1. 以 `gameRoomConfigId=1928`、`playMode=3`、`criticalFlag=true`、`forceShowCard=false` 识别不秀牌暴击房间。
2. `forceShowCard` 与 `criticalFlag` 是独立开关，不能把暴击房间默认当作秀牌房间。
3. 以 `3263` 驱动状态机，以 `3427` 至 `3430` 驱动公共牌，以 `3440` 驱动服务端动作确认。
4. `3441` 是条件性亮牌事件；未出现的底牌应保持隐藏，不要从结算数组推导未知牌。
5. 暴击金额不要直接用 `criticalAnte=100` 写死，应保留原始结算字段并等待专属结果样本。
6. `3260` 可能从翻牌/转牌等中间状态恢复，优先使用快照而非重放整局。
7. 保险、GTO、宝箱、积分、公证和回放与核心牌局状态机解耦。
8. 生产日志不要输出 token、openId、设备 ID、IP 编码值和完整玩家资料。

## 9. 结论

本次日志确认的是不秀牌暴击德州扑克：

```text
gameRoomConfigId=1928
playMode=3
gameName=暴击德州(不秀牌)0.1/0.2(0.2)
smallBlind=10
bigBlind=20
initialBet=20
forceShowCard=false
criticalFlag=true
criticalAnte=100
criticalInterval=5-8
```

核心流程仍是标准德州：

```text
登录/进房
 -> 房间快照或牌局恢复
 -> BET_FRONT
 -> BET_BLIND
 -> DEAL_PERFLOP
 -> BET_PERFLOP
 -> DEAL_FLOP
 -> BET_FLOP
 -> DEAL_TURN
 -> BET_TURN
 -> DEAL_RIVER
 -> BET_RIVER
 -> SETTLE
 -> 条件性亮牌和结算
```

该玩法的关键组合是：暴击规则开启，但强制秀牌关闭。协议层目前能可靠确认暴击配置，不能仅凭这份日志还原暴击触发和金额计算公式。
