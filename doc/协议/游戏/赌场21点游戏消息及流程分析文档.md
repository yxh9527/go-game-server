```json

  "packet": "PUBLISH",
  "flags": 2,
  "remainingLength": 649,
  "topic": "holdem/room/real-blackjack/update",
  "qos": 1,
  "messageId": 116,
  "payload": {"gameType":31,"roomType":31,"roomId":48365712}

```

客户端确认：

```json
{
  "protocol": "MQTT",
  "packet": "PUBACK",
  "flags": 0,
  "remainingLength": 2,
  "messageId": 116

```

`PUBACK.messageId` 必须对应 `PUBLISH.messageId`。日志同时显示原始 `ArrayBuffer` 和解析后的对象，协议分析应使用解析后的对象。

## 4. 状态和大厅流程

日志中可见的状态值包括 `0、2、3、5、6、7、8、9`。结合持续时间可推测：

```text
空闲
 -> 准备/下注
 -> 发牌或动画过渡
 -> 结果展示
 -> 回到空闲
```

相同 `roomId` 会连续收到状态更新，客户端应覆盖保存房间快照，而不是重复创建桌子。倒计时计算可使用：

```text
elapsed = serverNow - gameStatusStartTime
remaining = gameStatusDuration - elapsed
```

## 5. 房间渲染流程

```text
连接 MQTT WebSocket
 -> 订阅 holdem/room/real-blackjack/update
 -> 接收 PUBLISH
 -> 按 roomId 更新快照
 -> 按 roomIndex 排序桌面
 -> 使用 seatInfoList/displaySeatList 渲染座位
 -> 使用 gameStatus 和时间字段显示状态倒计时
 -> 发送 PUBACK
```

不同房间会同时推送，例如 `roomId=55614308`、`10328842`、`43482186` 等；它们可能有不同的 `roomIndex`、`dealerNo`、人数、座位和状态。

## 6. 与单桌牌局协议的边界

这份日志包含：

- MQTT `PUBLISH` 房间状态快照。
- MQTT `PUBACK` 消息确认。
- 房间配置、人数、座位、状态和倒计时字段。

这份日志不包含：

- 玩家下注请求。
- 庄家/玩家发牌消息。
- 单局牌面和 21 点牌型。
- 玩家输赢和保险结算。

因此不能从本日志还原完整 21 点牌局状态机，只能确认大厅状态推送链路。单桌牌局需要额外采集进入具体桌后的专用 WebSocket 消息。

## 7. 实现建议

1. 过滤 MQTT 主题 `holdem/room/real-blackjack/update` 和 `packet=PUBLISH`。
2. 对 QoS 1 消息发送对应 `PUBACK`，避免重复投递。
3. 以 `roomId` 维护房间快照 Map。
4. 使用 `serverNow`、`gameStatusStartTime`、`gameStatusDuration` 计算倒计时。
5. 使用 `roomIndex` 排序，使用 `seatInfoList` 和 `displaySeatList` 渲染大厅。
6. 保留 `gameStatus` 原始数字，未掌握完整枚举前不要硬编码中文状态名。
7. `bigBlind/smallBlind=0` 是 21 点大厅字段，不能套用德州扑克盲注逻辑。
8. 生产日志不要输出 MQTT 凭据、用户 token、完整用户列表或内部服务信息。


消息流程是：服务端 QoS 1 发布房间快照，客户端按 `roomId` 更新大厅桌面状态并返回 `PUBACK`。这份日志可用于实现 21 点大厅桌面、座位、人数和倒计时，不能替代单桌下注、发牌和结算协议。

## 11. 原版入座后下注失败修正（2026-10-27）

失败日志：`C:\Users\Administrator\.codex\attachments\1651952d-12df-4de0-8140-2f7dafc7fd9c\Pasted text.txt`。第 62 局 17:02:21.926 已进入下注阶段；17:02:24.926 玩家 10001 向 displaySeat=3 下主注 100，服务端返回 BET_FAILED、point=0；17:02:26.923 收到 3436 强制站起。本人没有进入本局 players，问题不是倒计时，而是已占座的真人一直被当作普通场“未完成带入”。

修正后的赌场资金约定：

1. 保持进房旁观、本人主动选择座位；占座只绑定已鉴权会话的实际可用账户，不转走整笔钱包，不生成虚假筹码。余额低于底注时拒绝新占座，返回原版余额不足提示。

3. 主注、保险、分牌、加倍均经过相同的可用余额与金额校验。优先使用本桌实际未投入筹码，不足部分通过现有钱包适配器按本次差额扣款，再进入共享牌局账本；未下注的账户余额继续留在账户中。拒绝不能生成下注、扣款或重复记账。
