## 4. 状态和大厅流程

日志中可见的状态值包括 `0、2、3、5、6、7、8、9`。结合持续时间可推测：

```text
空闲
 -> 准备/下注
 -> 发牌或动画过渡
 -> 结果展示
 -> 回到空闲
```

相同 `roomId` 会连续收到状态更新，客户端应覆盖保存房间快照，而不是重复创建桌子。倒计时计算可使用：

```text
elapsed = serverNow - gameStatusStartTime
remaining = gameStatusDuration - elapsed
```

## 5. 房间渲染流程

```text
连接 MQTT WebSocket
 -> 订阅 holdem/room/real-blackjack/update
 -> 接收 PUBLISH
 -> 按 roomId 更新快照
 -> 按 roomIndex 排序桌面
 -> 使用 seatInfoList/displaySeatList 渲染座位
 -> 使用 gameStatus 和时间字段显示状态倒计时
 -> 发送 PUBACK
```

不同房间会同时推送，例如 `roomId=55614308`、`10328842`、`43482186` 等；它们可能有不同的 `roomIndex`、`dealerNo`、人数、座位和状态。

## 6. 与单桌牌局协议的边界

这份日志包含：

- MQTT `PUBLISH` 房间状态快照。
- MQTT `PUBACK` 消息确认。
- 房间配置、人数、座位、状态和倒计时字段。

这份日志不包含：

- 玩家下注请求。
- 庄家/玩家发牌消息。
- 单局牌面和 21 点牌型。
- 玩家输赢和保险结算。

因此不能从本日志还原完整 21 点牌局状态机，只能确认大厅状态推送链路。单桌牌局需要额外采集进入具体桌后的专用 WebSocket 消息。

### 12.2 资金与轮换

1. 申请成功只排队，不提前扣本金，本局已下注仍能申请并完成当前闲家动作。下一局前先把本人闲家真实剩余桌面筹码按账本带出、站起，再经既有钱包扣实际上庄本金；排队时余额不作预冻结，真正带入时再次验证余额，不足移出并推 990101。
2. 真正上庄后禁入座和下注，不把庄家加入闲家发牌列表。可在排队阶段申请两区，分别持有本金；已在任一区在庄不能再次申请新区域。申请、调额、重复请求、重连均不会重复扣款。
3. 排队调整立即改申请；在庄调次数、调额只预约到下一局。增加金额扣差额，减少金额退差额；带入失败保留原在庄金额并推 100113。申请下庄本局责任仍保留到结算，随后退剩余本金及累计盈亏；不把仍在风险中的本金提前支付。
4. 坐满申请次数或剩余本金 ≤1000（10 元）自动下庄，分别使用 100111/100110 提示。带入成功走 3230，带出走 3680，账户余额走赌场数值 9212。
5. 断线/离房取消排队；在庄标记结算后退出。结算前重新进房可取消仅由断线产生的退出预约，不能覆盖本人主动申请下庄。八小时到期不启新局，当前局按原时序结算；庄家退资账本完成后才允许公共销毁处理闲家筹码。两份账本不重复支付同一本金。
6. 扣款后的持久化、带出信用和带出持久化分开标记，拒绝/失败阻止开下一局并重试，热更新保留状态；不得用重启服务清账。公用旁观、排行榜、机器人进出和八小时/无人三局挂起继续调用公共模块；同一真人在两区坐庄的局数只在排行榜计一次，净盈亏合并。

### 12.3 本实现的责任分摊

原版资源明确字段、金额门槛和局间时序，但没有服务端的具体占比分配算法。当前使用可审计的保守责任池：截止下注前不读牌，开局冻结各庄家 `min(amount,maxWinLoseAmount)`；截止时按本局主注总额、允许的最多两手分牌及加倍和最高 3:2 净赔率，预留常规最大赔付 `6 × 主注`，特殊保险预留 `主注`。本区分母为 `max(本区所有庄家责任上限之和,本区预留赔付)`，单个庄家占比为其冻结上限除以该分母。实际区域净输赢按此比例分配，积分向零取整，未覆盖责任及取整差额由系统庄家承担，不缩减闲家实际赔付；任何庄家单局不会超出已冻结的责任上限。不能将此分配算法宣称为已经对照线上服务端确认的算法。

常规区承担真实主注各手输赢；特殊区目前仅承担已实现的保险输赢。两区独立资金池、独立比例，共用同一副真实牌序；不因庄家变动修改发牌。每区保存最近 10 局最大预留责任均值，未有记录使用原版默认 10000000 供面板估算；结算占比以本局真实锁定值为准。当前房间 taxType/taxPercent=0，所以 take=0；本次没有从展示配置猜测新的抽水基数。
