# 德州玩家头像资料与道具

2026-11-07。使用原版 chatPanel，不重做弹窗，不修改原 static。影响 game-server、hall、client-web 和 gogames data-center。

## 原版协议

- WebSocket 8165 USER_INFO 的 uid 是所点玩家，身份来自现有登录 session；8263 返回 playerId、name、imageUrl、regionCode、remarkName、remarkMessage、mark 及统计对象。
- 9127 SEND_IM_USERREMARK：targetId、可选 remark、remarkMessage、mark；9226 返回 targetUid 及保存后的完整备注。备注名最多 32 字、内容最多 256 字；标签 0 表示清除，1—6 为原版颜色标签。只对备注作者下发，并在其房间快照中按连接映射，不更改公共玩家姓名。
- 8167 USER_EMO 查询的是当前登录玩家的剩余免费次数，8265 是整数，不能信任请求内 uid 改读其他人的额度。
- 2103 SEND_USER_CHAT，type=5、content={toId,propId} 为普通道具。原版普通列表包含 0—14 共 15 种；只有本桌在座玩家可向其他在座玩家赠送，旁观/自己/跨房/冒用 sendUid 均拒绝。2203 广播原版动画消息，8265 更新剩余次数。
- HTTP op=81652：roomId、targetUid、pageNum、pageSize。经现有 room-pool JSON 的 player-records action 认证，按当前连接的实际游戏定位房间；机器人查询该房间存续期间本人实际参与的已结算记录，真人查询真实近七日记录。不建立新的玩家登录或退出真人座位。

## 已确认规则

- 普通道具每人每日免费 20 次，按北京时间 00:00 重置，跨房间共用。第 21 次拒绝，不扣余额、不发成功动画；次数在 MySQL 行锁事务内递增，多个 game-server 不能各自发放 20 次。
- 高级道具暂不开放。client-web 响应层把原版高级标签切回普通道具并提示；伪造 type=6 同样返回未开放，不收费。
- 机器人展示资料随机生成后存入 table.playerPanelBots；实际进房、机器人加入和后续 tick 会为新机器人建立房间资料。相同房间内重复打开、离座后重入和业务热更新都沿用该 UID 的数据，房间销毁后释放；随机值不写入真人统计表或钱包。
- 机器人总手数、基础比例、今日/本周输赢、3B/4B 和同桌率仍采用房间上的随机展示资料，同桌项只引用本房间已知玩家。牌局记录计数不再随机：oneWeekHands/recentRecordCount 使用该机器人在当前房间实际参与的已结算手数，recentRecordScope=room；弹窗入口和列表标题显示“本房间牌局记录”。未参局显示 0，正在进行的局不计入，不补假牌、时间或资金记录。真人 recentRecordScope=seven-days，仍使用真实七日数据。

## 统计及权限

真人基础字段：totalHands、flipManualBetPercent（翻前加注率）、joinPercent（入池率）、tableJoinPercent（本桌入池率）；只按真实已结算手和有效动作计算，盲注和前注不作为主动入池。新增动作记录区分全下跟注与全下加注，旧回顾无法区分时显示 --，不能猜作加注。机器人的展示统计按上文的房间随机资料规则处理。

真人风控字段：todayScore 为北京时间今日净输赢，oneWeekScore 为北京时间本周一至今净输赢，oneWeekHands 为今日及此前六天的真实手数。tableMateRateList 按近七日共同参局手数/目标玩家手数排序，包含原版同桌详情的翻前 3B/4B、翻后 3B 次数/比例；精确动作序列缺失时显示 --。生产的动作细节统计来自已保存的近七日样本，终身总手数、翻前加注率及入池率由 MySQL 全量聚合；样本超过 10000 条时不把截断样本冒充完整比例。机器人的 oneWeekHands 兼容原字段名，但含义为当前房间实际参局手数，与“本房间牌局记录”列表一致。

目标必须属于认证 agentId 的当前座位类房间或该房间已有公开统计，不能通过请求 agentId、sender 或任意 targetUid 探查其他代理。德州/炸金花卡片只返回公开公共牌、公开底牌及查看者本人的牌；其他游戏仅投影已经公开的结算字段，不透传内部状态、对手隐藏底牌、钱包或余额。备注按代理/作者/目标隔离。

## MySQL 持久化

已写入 D:/project/gogames 的 app/tables/gogame/player_panel.go，三张玩家库表由既有 InitMysqlDb 的 gogame.PlayerModels 注册：

- gg_player_panel_hand：真人已结算手的不可变报告、金额及动作统计，按代理/玩家/币种/记录身份唯一写入；重复传输不会重复累计。它不是资金流水，不修改账户余额。
- gg_player_note：代理/备注作者/目标三个字段构成主键，局部修改加行锁，修改标签不覆盖此前备注名或内容。
- gg_player_emoji_daily：代理/真人/北京时间日期主键，保存当天已用次数，事务内 FOR UPDATE 检查并递增到 20。

data-center/dao/player_panel.go 通过现有 GogameStorageService 的固定 operation 分派提供 playerPanelRead、playerPanelRecords、playerPanelWrite、playerPanelNoteGet/Set、playerPanelQuota/Gift。Node 只使用统一 gateway，不直连 MySQL。生产查询和存储失败明确报错，不回退本机随机值或未落库成功。真人结算报告由原有 user-center 投递队列先写 MySQL 再走原 ES 历史存储；只有 roomType=19 的真实用户记录进入此统计表，机器人不入库。

七日列表使用 MySQL 分页并单独查询真实总手数和总输赢，不以当前页数量冒充全部数量。此功能从接入后的实际结算起保存；未导入的历史不补造。开发环境按开发规则仍为纯内存，备注及免费次数在常驻 runtime 上复用；本地模拟不代表已连接生产 MySQL。

源文件已实际应用，校验和/安装包保存在 doc/待应用/player-panel；未执行真实数据库迁移，也未重启或发布 data-center。生产启用前须用既有 InitMysqlDb 建表并部署匹配的 data-center 和 Node 源码。不能仅凭 Go 编译测试声称真实数据库已落表。

## 头像错位、迟到响应及非德州选项修正

原版头像面板会无条件把 USER_INFO 的空参数或其他玩家资料赋给 data；普通道具触摸回调又直接读取 data.playerId，关闭面板后的迟到/重复触摸会抛出异常。client-web 响应适配现在在资料事件分发之前按最新请求 UID 过滤，面板 init/update 再次验证目标；道具点击捕获有效目标并只发送一次，关闭/空资料时不发送。头像异步加载绑定面板版本和 UID，旧回调不能覆盖新玩家头像。名称、头像来自同 UID 的座位资料，不随机器人统计随机生成。

非德州原版 user_info 使用 HTTP op=81651；此前只有德州 8165 WebSocket 实现。hall 已经把 81651 接到现有 room-pool 的 player-profile 只读 action，按当前登录连接的游戏和房间定位目标，不创建新玩家 session。81652 同样按当前游戏寻址，不再写死 holdem。真人非德州输赢及记录通过原有 data-center 历史读取，不使用德州记录冒充。

## 机器人本房间牌局记录修正

公共 finishHandStats 在真实结算完成时调用 player-panel-records.js，按局号去重把报告保存在 table.playerPanelHands；德州、炸金花、牛牛、十三水、麻将、二十一点、三公共用采集入口。记录只属于该常驻房间，业务热更新保留，最终销毁清除；不进入真人 MySQL/ES、钱包或资金流水。麻将额外传入已经广播的公开结算摘要。旧房间可从本房间已有 history/mahjongHistory 恢复已完成的报告，缺失的旧时间显示“未记录时间”，不伪造时间；没有保留下来的历史无法补造。

机器人资料手数、列表分页总数、列表盈亏统一由同一批实际参局报告计算，查询不套用七日时间过滤，也不混入其他房间的同 UID 记录。原版炸金花列表缺少举报数据时默认只显示两张牌，client-web 响应层按 roomType=25 修正为三张；原 static 保持不变。真人七日查询及生产持久化入口继续保持真实数据口径。

非德州头像左上角的选项是 private_option_button/private_option_dropdown_panel，原版只以 isPrivateRoom/createUid 判定显示。现在额外要求 roomType=19，并在显示面板时清除旧下拉状态；非德州不显示，也不能通过旧按钮回调打开。德州原来的私房创建者权限判断保留。
