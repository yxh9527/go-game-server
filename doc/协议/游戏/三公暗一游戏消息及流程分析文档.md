## 4. 开局与牌局状态消息

### 4.1 NIUNIU_INNING_BEGIN_INFO（3260）

核心字段：

| 字段 | 含义 |

| lastOperation | 最近一次操作枚举 |

### 4.2 BRNN_GAME_STATE_PUSH（3263）

三公暗一复用了通用牌局状态推送消息。日志中依次看到：


字段说明：

| 字段 | 含义 |
| --- | --- |
| uid | 操作玩家 |

| totalBetScoreNotMen | “NotMen”类下注累计；本样本为 0 |
| operation | 下注操作枚举，样本为 1 |
| point | 下注后玩家桌内分 |

## 12. 日志中需要特别注意的协议特征

1. 三公暗一的业务消息以 SGAY_ 开头，但牌局阶段消息使用了 NIUNIU_INNING_BEGIN_INFO 和 BRNN_GAME_STATE_PUSH，属于共享后端协议命名。

4. 4406 的 pot 是全桌累计下注，不是单个玩家下注。
5. 4403 的 totalScore、finallyScore、score 需要同时保存，不能只保留一个金额。
6. 本房间 openInsurance=false，4403 中 insuranceBet、insuranceProfit、winInsurance 通常为 0。
7. 2201、2206 可能在新局、坐下、重连和牌局切换时重复发送，应按 roomId 和 currentInning 更新状态。

## 14. 结论

三公暗一可以按以下消息链路实现：

~~~text
ROOM_LOGIN(1105/1205)
 -> SEND_JOIN_ROOM(2102, isOb=true)
 -> ROOM_TYPE_RESULT(2201)
 -> ROOM_INFO(2206)
 -> NIUNIU_INNING_BEGIN_INFO(3260, DEAL_PERFLOP)
 -> SGAY_DEAL_DI_PUSH(4401)
 -> BRNN_GAME_STATE_PUSH(3263, XIAN_RAISE)
 -> SGAY_ACTION_BET_PUSH(4406)
 -> BRNN_GAME_STATE_PUSH(3263, FLOP)
 -> SGAY_ACTION_SHOWCARD_PUSH(4407)
 -> BRNN_GAME_STATE_PUSH(3263, SETTLE)
 -> SGAY_INNING_RESULT_PUSH(4403)
 -> GAME_RECORD(1249) / GAME_POINT_UPDATE(9212)
 -> SEND_LEVEL_OUT / USER_LEVEL_ROOM
~~~

协议实现上应以 roomType=32、roomType=sgya 作为游戏识别条件，使用 currentInning 作为局索引，使用 uid 和 pos 管理玩家，并把 4401、4406、4407、4403 作为三公暗一的核心牌局事件。
