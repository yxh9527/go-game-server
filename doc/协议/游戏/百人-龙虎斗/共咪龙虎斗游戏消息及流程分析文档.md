## 5. 消息协议

### 5.1 状态和路单

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、roomType、inning、ways | 通知阶段 |
| 6205 | ENTER_RESPONSE | dragon、tiger、下注和路单 | 进入快照 |
| 6208 | SHOWDOWN_POKERS | dragon、tiger、showdownTypes、winningAreas | 公布结果 |
| 6210 | PLAYER_BALANCE_UPDATE | points | 更新积分 |

日志中 state=2、3、4、6、7、0：

- state=2：开放下注；
- state=3：停止下注并开始开牌；
- state=4：牌面展示；
- state=6：结算、系统分数和路单更新；
- state=7：本局收尾；
- state=0：下一局切换。

ways.1 的每条记录包含 result 和 winArea：

~~~json
{
  "result": 1,
  "winArea": [1, 4, 6, 9, 11, 15]
}
~~~

result 是龙虎斗结果类型编号，winArea 是本轮命中区域数组。

## 6. 一局共咪龙虎斗流程

1. HTTP op=38 查询 gameType=1003、playMode=1 的 roomType=59 档位。
2. HTTP op=45 选择 roomIndex=4，取得 roomId=19253186。
3. ROOM_LOGIN、SEND_JOIN_ROOM、GR_GET_ALL_ROOMS_REQ/RES 建立和同步房间。
4. ENTER_RESPONSE 返回 state、积分、区域下注、dragon/tiger 牌面和路单。
5. state=2 开放下注，客户端发送 BET。
6. BET_RESPONSE 确认个人下注，BET_BROADCAST 广播区域总下注。
7. state=3 停止下注，服务端发龙牌和虎牌。
8. state=4/6 更新 dragon、tiger、showdownTypes、winningAreas、积分和路单。
9. state=7 收尾，state=0 进入下一局。

## 8. 实现建议和限制

- 使用 roomType + gameRoomConfigId + playMode + roomIndex + roomId + inning 作为唯一上下文。
- allPlayerBets 顺序不固定，必须按 areaId 映射。
- 只有 state=2 且倒计时有效时允许 BET。
- 结算先处理 dragon、tiger、showdownTypes，再处理 winningAreas 和积分。
- result 和 showdownTypes 是编号字段，不能在没有枚举表时直接显示中文名称。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
