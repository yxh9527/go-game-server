## 5. 消息协议

### 5.1 状态和路单

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、inning、ways | 通知阶段 |
| 6205 | ENTER_RESPONSE | dragon、tiger、下注和路单 | 进入快照 |
| 6208 | SHOWDOWN_POKERS | dragon、tiger、showdownTypes、winningAreas | 公布开奖结果 |
| 6210 | PLAYER_BALANCE_UPDATE | points | 更新积分 |

经典档日志可见 state=2、3、4、6、7、0：

- state=2：开放下注；
- state=3：停止下注并开始开牌；
- state=4：牌面展示；
- state=6：结算、系统统计和路单更新；
- state=7：本局收尾；
- state=0：下一局切换。

ways.1 保存最多 180 局结果，每条包含 result 和 winArea：

~~~json
{
  "result": 1,
  "winArea": [1, 4, 6, 9, 11, 15]
}
~~~

### 5.2 下注

6101 BET：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 59,
  "roomId": 55849922
}
~~~

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向龙虎区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points、个人下注 |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播 12 个区域总下注 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 服务端 | 更新人数 |
| 6210 | PLAYER_BALANCE_UPDATE | 服务端 -> 服务端 | 更新积分 |

allPlayerBets 按 areaId 返回 1 至 11、15 的总额，顺序不固定，必须按 areaId 映射。

### 5.3 开牌和结算

SHOWDOWN_POKERS 示例：

~~~json
{
  "roomType": 59,
  "roomId": 0,
  "showdownPokers": {
    "dragon": [51],
    "tiger": [11]
  },
  "showdownTypes": {
    "dragon": 13,
~~~

- dragon：龙牌；
- tiger：虎牌；
- showdownTypes：牌型或牌值类型编号；
- winningAreas：本轮命中区域；
- lostAreas：本轮未命中区域；
- areaWinningScores：个人区域收益；
- points、realScore：积分结果。

## 6. 一局经典龙虎斗流程

1. HTTP op=38 查询 gameType=1003、playMode=0 的 roomType=59。
2. HTTP op=45 选择 roomIndex=3，取得 roomId=55849922。
3. ROOM_LOGIN、SEND_JOIN_ROOM、GR_GET_ALL_ROOMS_REQ/RES 建立和同步房间。
4. ENTER_RESPONSE 返回 state、积分、区域总下注、路单和当前龙虎牌面。
5. state=2 开放下注，客户端发送 BET。
6. BET_RESPONSE 确认个人下注，BET_BROADCAST 更新区域总额。
7. state=3 停止下注，服务端发龙牌和虎牌。
8. state=4/6 更新 dragon、tiger、showdownTypes、winningAreas、积分和路单。
9. state=7 收尾，state=0 进入下一局。

## 8. 实现建议和限制

- 使用 roomType + gameRoomConfigId + playMode + roomIndex + roomId + inning 作为唯一上下文。
- allPlayerBets 顺序不固定，必须按 areaId 映射。
- 只有 state=2 且倒计时有效时允许 BET。
- 结算先处理 dragon、tiger、showdownTypes，再处理 winningAreas 和积分。
- result 与 showdownTypes 是编号字段，不能在没有枚举表时直接显示中文名称。
- roomId=0 的开牌消息需要结合当前 inning 和最近快照归属。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
