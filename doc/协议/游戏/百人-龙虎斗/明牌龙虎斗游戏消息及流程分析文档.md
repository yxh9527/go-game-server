## 5. 消息协议

### 5.1 状态、发牌和赔率

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、inning、areaOdds、bankerShowPoker、otherShowPoker | 推进状态并分段公开牌面 |
| 6205 | ENTER_RESPONSE | playerNum、points、countDown、牌面、赔率、ways | 当前房间快照 |
| 6208 | SHOWDOWN_POKERS | dragon、tiger、showdownTypes、winningAreas | 最终开奖结果 |
| 6212 | 消息名未解析 | bankerCards、playerCards、areaOdds、inning | 本档日志中出现 undefined 名称的牌面消息 |
| 6210 | PLAYER_BALANCE_UPDATE | points | 更新玩家积分 |

6212 的日志消息名为 undefined，但 data 含 bankerCards/playerCards。不能仅凭字段命名把它等同于正式 Dragon/Tiger 协议；本档的明确可见牌阶段来自 GAME_STATE 的 bankerShowPoker 和 otherShowPoker。

日志中的状态时序可归纳为：

- state=0：新局切换；
- state=1：公布庄牌和本局赔率；
- state=2：开放下注；
- state=3：停止下注并公布闲牌；
- state=4：展示最终结果；
- state=5/6：结算动画、积分和路单更新；
- state=7：本局收尾。

状态含义根据当前日志时序归纳，客户端应以服务器推送状态为准。

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向当前开放区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points 和个人下注 |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播可下注区域累计金额 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 服务端 | 更新在线人数 |

BET_RESPONSE.code=0 表示成功。BET_BROADCAST 中 allPlayerBets 的顺序不固定，必须按 areaId 映射。

6208 SHOWDOWN_POKERS 示例：

~~~json
{
  "roomType": 59,
  "roomId": 0,
  "showdownPokers": {
    "dragon": [22],
    "tiger": [8]
  },
  "showdownTypes": {
    "dragon": 10,
    "tiger": 9
  },
  "winningAreas": [7, 8, 1, 9],

  "areaWinningScores": {"1": -100},
  "points": 7877,
  "realScore": -100

~~~

- dragon、tiger：龙牌和虎牌最终牌值；
- showdownTypes：两侧服务端类型编号；
- winningAreas、tieAreas、lostAreas：本轮区域结果；
- areaWinningScores：玩家区域积分变化；
- points、realScore：结算积分结果。

示例中 roomId=0，归属应使用同一 inning 的最近房间状态确认，避免将多房间订阅中的开奖串到错误房间。

## 6. 一局明牌龙虎斗流程

1. HTTP op=38 查询 gameType=1003、playMode=3 的 roomType=59 房间。
2. HTTP op=45 选择 roomIndex=6，取得 roomId=38856508。
3. ROOM_LOGIN、SEND_JOIN_ROOM 和 GR_GET_ALL_ROOMS_REQ/RES 建立房间并同步列表。
4. ENTER_RESPONSE 返回当前 inning、积分、下注池、赔率和最近结果。
5. state=0 后新局进入 state=1，服务端发送 areaOdds 和 bankerShowPoker。
6. state=2 开放下注，客户端发送 BET，并通过 BET_RESPONSE 确认；BET_BROADCAST 更新各区域下注额。
7. state=3 服务端推送 otherShowPoker，结束下注并进入开牌阶段。
8. state=4 通过 SHOWDOWN_POKERS 公布 dragon/tiger、showdownTypes 和 winningAreas。
9. state=5/6 更新积分、ways 和连续统计；state=7 收尾。
10. 新 inning 到来后重复上述流程。

## 8. 实现建议和限制

- 使用 roomType + gameRoomConfigId + playMode + roomIndex + roomId + inning 作为唯一上下文。
- 分别保存 bankerShowPoker、otherShowPoker 和最终 dragon/tiger，不要在下一阶段到来前覆盖为最终值。
- 只有 state=2 且倒计时有效时允许 BET。
- areaOdds 可能每局变化，收到 state=1/6212 后更新本局赔率。
- 6208 的 roomId=0 需结合 inning 和最近房间快照归属。
- showdownTypes 是编号，未经枚举表确认不要硬编码中文牌型。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
