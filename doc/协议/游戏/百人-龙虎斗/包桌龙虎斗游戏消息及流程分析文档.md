## 4. 龙虎牌面和结算

进入快照直接返回：

~~~json
{
  "showdownPokers": {
    "dragon": [16],
    "tiger": [8]
  },
  "showdownTypes": {
    "dragon": 4,
    "tiger": 9
  }
}
~~~

SHOWDOWN_POKERS 结算字段包含：

- dragon：龙牌；
- tiger：虎牌；
- showdownTypes：龙、虎类型编号；
- winningAreas、lostAreas：本轮命中和未命中区域；
- points、realScore：玩家积分结果；
- ways：历史路单。

包桌模式下，牌面结构与普通龙虎斗一致，区别在于房间上下文、入口参数和在线人数。

## 5. 消息协议

### 5.1 状态

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、inning、ways | 通知本轮阶段 |
| 6205 | ENTER_RESPONSE | dragon、tiger、下注和路单 | 进入快照 |
| 6208 | SHOWDOWN_POKERS | dragon、tiger、showdownTypes、winningAreas | 公布结果 |
| 6207 | PLAYER_NUM_CHANGE | roomType、playerNum | 更新包桌在线人数 |

日志可见 state=4 的当前结果阶段，随后 PLAYER_NUM_CHANGE 持续返回 playerNum=1。具体下注阶段仍按服务端 state 驱动。

### 5.2 下注

6101 BET：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 59,
  "roomId": 54515366
}
~~~

包桌下注的请求和响应字段与普通龙虎斗相同：

- 6101 BET：提交一个或多个区域；
- 6201 BET_RESPONSE：返回 code、points、myBets、myTotalBets；
- 6202 BET_BROADCAST：广播各区域累计下注；
- 6210 PLAYER_BALANCE_UPDATE：更新积分。

包桌中 allPlayerBets 顺序可能变化，必须按 areaId 映射。当前快照显示 areaId=1 有 100 积分，其余区域为 0。

## 6. 一局包桌龙虎斗流程

1. HTTP op=38 查询 gameType=1003、playMode=4、gameRoomConfigId=5971。
2. HTTP op=45 选择 roomIndex=2，取得 roomId=54515366。
3. ROOM_LOGIN、SEND_JOIN_ROOM、GR_GET_ALL_ROOMS_REQ/RES 建立和同步房间。
4. ENTER_RESPONSE 返回 playerNum=1、积分、区域下注、龙虎牌面和路单。
5. 进入下注状态后发送 BET，使用 BET_RESPONSE 确认。
6. BET_BROADCAST 更新包桌房间的区域总下注。
7. 状态进入开牌阶段，服务端公布 dragon、tiger、showdownTypes。
8. winningAreas 和 lostAreas 确定区域结果，points、realScore 更新玩家积分。
9. PLAYER_NUM_CHANGE 继续维持包桌在线人数。
10. 下一局使用新的 inning 重复。
