## 规则和赔率

单副52张牌、无大小王，每局先龙后虎各一张。A=1，J/Q/K=11/12/13，主注只比较点数。同点和局，龙/虎主注退本金一半，和注及其他边注独立结算。整数积分派彩向下取整；奇数积分主注的一半退款也向下取整，此最小单位约定尚无线上奇数样例核对。

经典、共咪、包桌使用12区。表中为净赢倍率，不含退回本金。

| 区域 | 含义 | 净赔率 |
| ---: | --- | ---: |
| 1 / 2 | 龙 / 虎 | 1 / 1 |
| 3 | 和 | 8 |
| 4 / 5 | 龙单 / 龙双 | 0.81 / 1.11 |
| 6 / 7 | 龙红 / 龙黑 | 0.95 / 0.95 |
| 8 / 9 | 虎单 / 虎双 | 0.81 / 1.11 |
| 10 / 11 | 虎红 / 虎黑 | 0.95 / 0.95 |
| 15 | 不和 | 0.07 |

明牌仅使用1、2、3、12、13、14、15七区：12总点2–9、13总点10–18、14总点19–26。原抓包 ROOM_TYPE_RESULT 中百家乐形状的初始赔率不能直接作为实际区域规则。

明牌先公开龙牌。原版将增量 bankerShowPoker 转为 longPoker，重连另读取 bankerCards；两字段均只含已公开龙牌，不下发隐藏虎牌或牌靴顺序。动态价格枚举排除公开龙牌后的剩余牌组成，不读取隐藏虎牌位置，逐局冻结。当前为开发公平条件报价：主注计入和局半输，其他区域全输，报价保留两位小数向下取整，零赔率禁投。线上运营返奖率及精确定价尚未确认，不能宣称逐值一致。

## 原版字段契约

- 龙虎斗原版读取区域对象 odds（十进制倍率），不能只提供百家乐 oddsList。本实现同时保留 oddsList（倍率×100整数），供公共账本和上庄风险计算；两者必须一致。热更新从存量冻结价格投影 odds，不重定价。
- showdownPokers 为 {dragon:[card],tiger:[card]}，每方一张；showdownTypes 为1–13点数。主桌6205/6208保留 showdownPoints 的 dragon/tiger 单元素数组，供原版桌主咪牌读取。好路/多台面板的6230发现、6227注册、6228状态、6229结算不下发 showdownPoints，统一由 multiRoomSnapshot 投影，使用 showdownTypes 的 dragon/tiger 点数分支。原版 HundredHaoluRoom 对任何非空 showdownPoints 都按百家乐 other/banker 数组解析，混用会出现 undefined.length。不能全局删除主桌点数，也不能修改原版客户端绕过。
- 经典 winningAreas 顺序：主胜负区、龙单双、龙红黑、虎单双、虎红黑、不和；原版按位置显示牌型，不能任意排序。明牌为主胜负区、总点区、不和。
- ways[1] 为 {max:180,ways:[{result,winArea}]}，result 为1龙/2虎/0和，最新在前。ways[9] 使用 {type:16384,roundNum:0} 无好路对象，尚未实现独立好路荐注检测。
- 6205 含 playerId、points、countDown、ownBets、累计下注和hostPrivilege；6204倒计时为毫秒。个人结算6208/6210，6229保留公共快捷面板适配。
- 6221提供有权限的局号列表；6222含dragon/tiger、showdownTypes、winAreaIds和个人betDetailTableMap。每区记录 areaId、betScore、realScore、score、tax、odds。上一局/下一局由原版利用列表导航，不发虚构 prevInning/nextInning。

## 共用实现

games/dragon-tiger 仅维护配置、规则、公开信息定价、牌靴和状态适配。与百家乐共同继承 core/CardShoeGame → HundredGame，共用 hundred-card-payout、hundred-card-history、hundred-table-owner、hundred-banker、hundred-subscriptions、core/robot.js。百家乐原路径保留薄转发层，旧桌主字段和重试状态不重置。

下注6101/6201/6202校验整数金额、单区累计限额、房间身份、真实阶段截止时间及余额，整批通过后扣款。结算保留逐玩家 credited/persisted/notified 进度；失败/并发/热更新不重复派彩，成功前不换局或丢弃下注。断线玩家保留本局责任；机器人通过相同入口真实下注，用独立模拟钱包，不调用真人资金RPC。

上庄复用6133–6135/6240–6244，两组分别覆盖主注/不和及其他边注。托管扣退、局边界生效、风险限额和失败重试均由公共模块处理；包桌不开放多人上庄。

包桌 vipTableMode=0申请桌主、1普通进入；余额门槛按原版大厅500元，不虚构费用。下主注后可提前开牌，超时自动开牌；飞牌已有其他玩家下注时正常结算。原版帮助允许成为桌主后选择荷官，不套用百家乐10分钟等待；单副牌不套用百家乐30局换靴限制。外观范围荷官301–330/401–420/501–520，背景51–66。时间与外观设置次局生效。允许其他玩家继续下注，依据本游戏帮助“桌主开牌前都可继续下注”和“有其他下注正常结算”。公共模块通过游戏配置区分这些策略。

## 阶段和开发配置

2下注 → 3停注 → 4开牌/咪牌 → 6结算 → 7收尾 → 0换局；明牌增加1公开首牌，换靴插入8。经典/共咪/明牌15秒下注及共咪10秒咪牌分别对齐原版 LHD_BETING_COUNT_DOWN、LHD_MIPAI_TIME；包桌默认20秒下注、10秒咪牌，面板可修改。

其余开发默认值集中在 config.js：cutIndex=50，单副连续发牌每手2张，不足2张/达到切牌位后换靴；洗牌16秒、结算10秒。开牌、发牌缓冲及这些牌靴/动画时间未获得完整线上时序，属于可调整开发配置，不宣称线上精确值。牌靴、当前局、截止时间、冻结价格和重试标记保存于常驻房间；热更新不重发牌、不延长当前截止时间。

## 数据边界

dev 回顾按需使用 cache/game-server/hundred-history.js 房内内存，最多100局、8小时，含旁观授权和个人下注。prod先Redis再gateway/data-center查询ES，验证代理、玩家、roomType=59和房间；合并并发请求，列表30秒、详情300秒缓存。game-server不直连ES。

正式记录写入、注单及权威lottery发牌/公证仍依赖外部契约，本轮未接入尚未提供的接口；不得把本地内存回顾或洗牌冒充生产联调完成。systemInningScore/systemTodayTotalScore沿用公共快照占位，不作为正式全平台账务统计。

规则测试覆盖2652种合法双牌组合、区域边界、半退、冻结及暗牌隔离、非法批量下注、失败重试、断线结算与回顾授权。浏览器从大厅真实点击进入原版lhd，核对赔率标签、下注、个人结算、回顾及返回大厅。机器人入口及多房隔离复用公共回归验证。所有测试留在test/。

2026-10-30首轮主桌验证结果：龙虎斗17项专用测试通过；全仓656项通过，包含真实剔除test/cache后的生产副本加载。原版浏览器0/1/3/4四模式均通过实际赔率标签、下注、个人结算、回顾和退出，未捕获脚本异常；包桌特权次局生效通过。经典模式另完成上庄托管、上庄结算、庄家回顾、下庄退款。实测包桌出现和局，100积分龙主注净输50，客户端显示与半退规则一致。服务未重启。
