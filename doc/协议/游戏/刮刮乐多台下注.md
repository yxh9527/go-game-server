# 刮刮乐多台下注

2026-11-06。影响 hall、game-server、client-web。依据原版 2.0.1279 的 MultyBet/index.4816c.js、gglmj/index.1cb0a.js、gglsj/index.97aa3.js。抓包中只出现 3702/3711 不能代表多台没有协议；多台使用以下独立消息，仍复用同一票务和资金服务。

## 注册与展示

客户端点击 MultyBetEntrance，选择分类 GGL=3 后发送 6123：

```json
{"mulRoomTypeList":[{"roomType":61},{"roomType":63}],"customData":1}
```

公共 core/hundred-subscriptions.js 同时支持百人与声明 multiRoomSnapshot 的刮刮乐游戏。返回 6224 的 mulRoomTypeList（每项含 roomType/roomId）及 6227 的 roomInfos，并原样返回 customData。刮刮乐快照包含 roomType、roomId、gameRoomId、roomIndex、playMode=0、maintenance、denominations、winMultipliers 和 gglParams。原版按 denominations 生成面额行，积分除以 100 显示。

6126/6230 可按 roomType 发现同样的房间列表。6124/6225 取消指定上下文；空请求取消所有附加订阅，保留原有百人主桌。刮刮乐注册只记录订阅，不创建座位、带入、百人访客或机器人，不改变主连接 roomId/gameId、已选百人桌或正常游戏状态。配置的目标房间由可信 agentId 分隔。

hall 对独立刮刮乐 61/63 的 op=45 返回 hundredDomain=domain，供原版多台模块复用已经连接的主房间 Socket；刮刮乐自身不会为了打开面板另行建立百人副连接。普通宿主和百人浮层继续保留各自的连接配置。

## 下注与结果

原版 MultyGglItem.buyOneTicket 发送 6127 MB_GGLE_BET_REQ：

```json
{"revealMode":"RANDOM_BUY_REVEAL","serialFull":"","faceValue":100,"kind":"ggl1","roomId":61010026}
```

kind 为 ggl1（61 麻将胡了）或 ggl2（63 赏金女王）。请求不包含 customData，faceValue 已是积分，不再乘 100。一次请求购买并揭晓一张票。接收 6231 MB_GGLE_BET_RES，包含 code、目标 roomId、gameRoomId、roomTypeCode/roomType、faceValue、serialFull、huCount、multiplier、winAmount、prizeTier、huMask、walletAmount、gglKind 以及累计中奖字段。

响应只发起请求的连接。服务端同步发送数值型 9212，既有多台组件在刮开动画结束时也会按 walletAmount 更新显示。错误响应仍回传 roomId、faceValue 和余额，让对应 BUYING 面额行退出等待。未注册、类型不符、维护/关闭或跨代理目标返回 95041；非法面额、票种、模式或票号返回 99400；余额不足 99048；票务/持久化失败 100085。无论当前主桌是哪款游戏，6127 均按已注册目标解析，不能把参数转发到当前主桌。

多台复用 ggl-core/engine.scratchRequest 的 reveal，不新增钱包扣款或另造开奖结果。原有串行队列按代理/用户共用，因此多面额、两款游戏及独立页面的请求不会凭旧余额重复消费。未结算票、已派彩标记、历史和任务保留在常驻对象，热更新不清空。错误导致的已付款待刮票可以通过独立页面 3702/3711 恢复，再用 SPECIFIED 揭晓，不重复扣款。无请求唯一号的 RANDOM_BUY_REVEAL 每次成功调用均代表新票，不承诺网络重发永久去重。

自动刮票沿用原版 autoCount/自动停止按钮，每张完成动画后再次发 6127；服务端不创建后台自动购买任务。断开或关闭面板后不再接受该订阅的新下注，已受理购票/派彩继续完成。6125 百人下注不能对刮刮乐目标生效。

## 同面额结果隔离

原版 MultyBetGglRoomItem.onResponse 监听全局 6231，只按 faceValue 分发行，两个游戏同时刮同面额会互相接收结果。client-web/src/scratch-multi-response.js 在响应资源时给此方法增加 roomId 匹配，再按原逻辑分发；原始 static 文件不改，字段、金额及开奖逻辑不改。client-web 的带版本和根路径 MultyBet 脚本均使用该适配，生产资源经 client-web 服务时同样生效。若另用 Nginx/CDN 直接托管原始 static，此响应适配不会自动生效，应将 MultyBet 脚本请求交给 client-web。

## 生产边界与验证

多台与独立刮票共用 runtime.scratchTickets 正式适配器。现有 dev 使用 cache 的票库和模拟开奖；生产缺少权威票务适配器时明确失败，不扣款、不回退随机开奖。此次接入消息及页面流程不代表正式发行、中奖概率、资金事务和注单服务已完成对接。

- `node --test test/game-server/games/ggl-core/multi.test.js`：注册、同面额并发、票种与金额校验、跨代理、维护、退订、热更新、断线完成和已付款失败恢复。
- `node --test test/client-web/scratch-multi-response.test.js test/hall/scratch-multi.test.js`：原客户端方法的房号隔离及 hall 连接地址。
- `node test/browser/check-scratch-multi.mjs`：实际页面点击多台入口，两款游戏同面额单次刮票、自动两张、动画完成和关闭退订。
- `npm test`：全量及真实剔除 cache/test 的生产模块加载。
