# 棋牌带入保留额度与五分钟租约

2026-11-07 用户确认。影响 game-server 公共座位层、钱包门面、shared RPC；不修改原始客户端，不重启常驻服务。

## 金额定义

- `wallet` 为账户当前总余额；`carryAmount` 为棋牌桌独占的带入保留额度，包含在账户余额中；`availableBalance = wallet - carryAmount` 为其他游戏可扣款金额。三者使用既有积分单位。
- 入座本身不带入资金。5001 的 carryIn 沿用原版显示单位并乘 100；确认带入和追加带入只增加保留额度，不减少账户余额，累计保留额度不能超过当前余额扣除其他保留后的可用金额。
- 牌局中原有 `member.point` 的增减经过公共绑定同步到总余额与 carryAmount。下注减少二者，退回下注或结算支付增加二者；不能在 finishHandStats 或离座时再重复增加账户余额。
- 站起、离房、部分带出、低筹码淘汰以及八小时回收释放对应保留额度，不把本金再次加回账户。未结算投注已经从余额扣除，不能因离座或租约过期额外退款。
- 离开仍有牌局责任的座位，先完成既有牌局结算再释放。可弃牌玩法离开后，剩余可用保留可以释放，但零额度所有权保留到本局清算，防止未匹配投入等迟到退回与新桌冲突。
- 机器人继续使用独立模拟账户；比赛积分由 match 管理；原版 LiveBlackJack 无带入面板，沿用其按实际投注扣款的流程。这些分支不创建普通棋牌带入记录。

## 逻辑互斥与多桌

1. 账户身份来自鉴权后的 agentId、userId 和币种；登录请求不能靠修改 currency 绕过保留。
2. hall 内部 cash allocation 与 WebSocket 2102 普通进房前检查已有带入；其他棋牌桌拒绝进入。原桌重连保留；实际 reserve 再次验证独占，两个请求不能同时取得两个带入。
3. 百人订阅、下注和 slots 多台入口不受棋牌进房锁限制；所有普通钱包 debit 使用总余额扣除有效 carryAmount 后校验，不能花掉棋牌桌保留资金。
4. 带入余额为零但牌局未结算时，仍然保留所有权。仅判断 amount > 0 不足以确定玩家已经离桌。
5. 没有业务请求序号的重复 carryIn 仍属于追加额度请求，但累计额度受余额上限保护，不发生重复钱包扣款。

## 五分钟租约

- `CARRY_TTL_MS = 300000`。每次带入值改变续约五分钟；正常活跃牌桌每 60 秒检查并续约，长局或等待操作不应导致正常记录误过期。
- Redis 键为 `gogame:cash-carry:{agentId}:{userId}:{currency}`，内容包含 tableKey、随机 token、amount 和 revision；写入使用 PX 300000。只读查询返回真实剩余 PTTL，不延长过期时间。
- reserve 不能覆盖另一 token；update 检查递增 revision；renew 只续约已有相同 token；release 只删除相同 token。过期的 update/renew 不能重新创建旧记录。
- 停止续约五分钟后 Redis 自动删除租约；本地开发等效模型在读取和变更时检查同一到期时间。旧牌桌检测凭证过期后停止资金动作，不能提交旧结算、复活旧额度或删除后来获得的新租约。
- 五分钟 TTL 只应用于座位保留记录，不代表自动退款。本次按用户最终指示不新增幂等流水、未结算记录、重启对账、特殊暂停或自动重试机制。

## 热更新与生产边界

开发模式不连接真实 Redis，仍遵守开发规则使用本地等效模型。状态与 token 保存在常驻钱包/RPC 对象上，热更新不会重新初始化额度或延长读取的 TTL。热更新前已经扣款的旧标量筹码继续按旧账本清算；不允许直接覆盖为新 reservation，也不允许未经迁移向旧筹码追加。

两端代码已接通：gogames/data-center/dao/gogame_cash.go 在既有认证 GogameStorageService.Call 上实现 cashRead 和 cashApply，使用 app/cashwallet/scripts.go 的 Redis Lua 一次校验并更新余额、带入值和当前版本号。金额统一使用 Redis 现有的整数分。

cashApply 先验证全部账户与操作，再集中写入；任一账户余额、代理、币种、带入 token 或版本不匹配则整批不写。带入/追加只改保留额度，carryDelta 同步改余额与额度，离座 release 只释放额度。版本号是当前账户字段，不生成逐笔历史。

Node wallet/authoritative.js 保持现有引擎的同步计算接口，在业务调用边界统一提交原子批次；提交确认后才发送成功响应，失败时还原该次内存变更。直接覆盖余额快照继续禁止。

既有 data-center、lottery、open-api、web-api 的余额扣减遵守相同保留额度约束；lottery 批量扣减复用该入口，Luck5 资金更新对玩家和带入键使用 WATCH，避免覆盖并发变化。玩家缓存刷新不再以旧资料中的余额覆盖实时余额。

**最终范围（用户明确要求）**：不新增幂等流水或未结算记录，不做重启自动对账、特殊暂停或自动重试。只保留当前余额、当前保留额度、租约和并发版本等必要状态。

部署使用原有 data_center/data_center_token 配置及 x-gogame-storage-token 鉴权，需配套发布两端。未重启任何现有进程；Go 常驻服务不会因源码修改自动加载新接口。
