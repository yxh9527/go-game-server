## 5. 看二张游戏流程

### 5.1 底注和发牌

每名玩家先支付 `ante=100`：

```json
{
  "uid": "<uid>",
  "currentBetScore": 100,
  "totalBetScore": 100,
  "totalBetScoreMen": 0,
  "totalBetScoreNotMen": 0,
  "operation": 1,
  "point": 2440,
  "pot": 100
}
```

`3727 ZJH_DEAL_DI_PUSH` 中的牌面可能是：

```json
[
  {"uid":"<uid>","cardList":[-1,-1,-1]},
  {"uid":"<uid>"}
]
```

`-1` 表示当前客户端没有获得完整牌面权限，并不表示发牌失败。

### 5.2 看牌状态

`ROOM_INFO` 和 `3260 NIUNIU_INNING_BEGIN_INFO` 中会记录：

```json
{
  "uid": "<uid>",
  "handPais": [-1,-1,-1],
  "isLooked": true,
  "isShow": false,
  "lastOperation": 7
}
```

看二张模式应至少维护三种状态：

| 字段 | 含义 |
| --- | --- |
| `handPais` | 当前客户端可见的三张牌，未授权时为 `-1` |
| `isLooked` | 玩家是否已经执行看牌行为 |
| `isShow` | 牌面是否已经公开展示 |

日志没有出现独立的看牌消息 ID，说明看牌动作可能由通用 `ZJH_SEND_ACTION`/`ZJH_ACTION_BET_PUSH` 的操作枚举承载，并通过 `isLooked` 反映结果。实现时应保留原始 operation，不要根据单条日志硬编码看牌操作编号。

## 7. 补分和生命周期

- `5001 SEND_CARRY_SCORE`：提交补分。
- `3230 CARRY_SCORE_RESULT`：返回补分结果，例如 `carryIn=100`、`carryBalance=3000`。
- `3445 PUSH_CARRYIN_TIPS_USER_LIST`：新玩家补分提示。
- `3436 USER_STANDUP_ROOM`：玩家离座。
- `2219 DZPK_PUSH_WATCHGAME`：离座后刷新观战列表。
- `2205 USER_LEVEL_ROOM`、`2208 USER_STATE_CHANGE`：用户座位状态。
- `6106 <game>EXIT`：辅助连接退出，不等同于主房间结算。

## 8. 实现建议

1. 使用 `gameType=25`、`roomType=25`、`gameRoomConfigId=134`、`playMode=2` 识别看二张场。
2. 以 `ctjhParams.ante=100`、`carryMin=1000` 初始化规则。
3. 将 `handPais=-1` 解释为牌面不可见，将 `isLooked` 和 `isShow` 分开维护。
4. 不要把看牌操作硬编码成单一 operation，保留 `ZJH_SEND_ACTION` 原始枚举并以服务端状态更新为准。
5. 使用 `3740` 处理下注结果，`3756` 处理轮数，`3741` 处理亮牌，`3732` 处理最终结算。
6. 三张牌的 `handPais`、`holeCardList` 和 `pokerEnumList` 不应按德州五张牌逻辑解析。
7. 生产日志不要输出 token、openId、设备 ID、IP 编码值和完整玩家资料。
