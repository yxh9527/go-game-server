# 棋牌牛牛服务端实现

## 范围与原版依据

大厅 `gameType=20/subGameType=0`，房间 `roomType=24`，配置名 `qznn`，原版场景名 `Qznn`。普通抢庄看三张、看四张、全暗（playMode=0）、七癞牛（playMode=7）共用 `game-server/src/games/niuniu`；不包含百人牛牛。

协议来源为 `assets/Qznn/index.134d5.js` 的 Qznn_DataNotify、Qznn_NetWork、Qznn_Start、Qznn_HistoryItem；玩法来源为原版 `holdemGame_zh_cn_Qznn` 中的 qznn_rule_desc、qznn_rule_card_type（普通、all_blind、7）规则图片。不得修改原客户端来兼容服务端错误数据。

## 房间与操作

全部 14 档配置保留原 cfgId、底注、看牌数、准入和分类，key 为 `24/playMode/ante/seeCardNo/roomClassification/carryMin`。开发默认数据在 cache/rpc/seed.js；正式初始化补丁为 doc/patches/niuniu-room-tiers.patch，应用到 gogames 的 app/tables/gogame。正式已有运营配置不得覆盖。

继续使用 SeatGame：进房旁观，5003 占座，12 秒内通过 5001 带入，超时释放座位；带入金额请求单位为积分除以 100。房间八小时、无人三局后挂起、满房比例扩容、机器人进出、排行榜与旁观列表均使用公共实现。机器人牌局决策集中在本游戏 robot.js，只接收自己已知的牌。

牛牛没有弃牌，发牌后离桌或离房不能清除本局负债。请求离房可以返回大厅，但该座位的本局筹码保留至真实结算；结算后通过公共带出账本退款与持久化，失败重试，不重复记账。下局站起使用公共 5007/2225。每局后按公共 carryMin 准入检查剩余筹码。

## 消息顺序与隐私

1. 2201：conf.qznnParams；2206：qznn、memberList、剩余时长。
2. 3261：currentInning、uidList；3618：毫秒时间配置。
3. 七癞场 3625：本局癞子牌值；3606：数组，自己最初可见 3/4 张（全暗 0 张），其他玩家 cardList=[]。
4. 3405 抢庄，3617 广播 playerId/count 数组；3616 定庄数组。
5. 3608 私发 bankerId、bettingMultiples、doublePoint、gameStatus；随后 **3263="XIAN_RAISE"** 才会打开原版下注按钮。只有 3608 不会切换操作阶段。
6. 3407 闲家下注，3615 广播 playerId/multiple/multipleAnte/point。
7. 3622：私发 niuInfo（含 playerId）；3412 拼牌，3604 uid/pingPaiDone；3410 亮牌，3623 公布该玩家五张牌。
8. 3610：结算数组，包含 uid、score、point、banker、grabBankerPoint、raiseMultiple、multipleAnte、handPais、niuType、niuJi、combinationsCard、handCardListWithLaiZi。保留结算动画时间后才开新局。

重连 3260 恢复原阶段、剩余时间、本人操作状态与可见牌。成员保留顶层 remarkName（无备注为空字符串），否则原版座位会将 undefined 当作备注名显示。未公开的他人 cardList、handPais 使用空数组，不能用五个 -1；原客户端会把长度为 5 的数组判定为已经亮牌。不能在中途广播完整逻辑牌。入房后的短暂资源初始化窗口发送 3260 代替 3261 开局动画，避免原版场景异步动画资源尚未加载时出错。公正码复用公共实现，目前仍沿用公共模块的 dev 证明边界。

## 判牌与金额

### 旁观座位与发牌坐标

原 `Qznn_SeatLayer.TryRotateSeats` 仅在本人入座时旋转；纯旁观的底部默认为消息座位 0。真实座位可随机分布，不能通过让旁观者自动入座或移动真实玩家修复空底座。公共 `core/seat-view.js` 在消息编码前按连接循环映射真实座位，选已带入在桌玩家为底部锚点。2206 memberList、3260 memberDeskInfos、2202 pos、3606 pos、3610 pos 使用同一映射，5003 position/pos 还原为真实座位后再调用公共入座流程。uid、牌面及其授权、金额不变；记录与回顾仍用真实座位。

视角保存在常驻 session，热更新不重置。局中人员进出保持坐标稳定；底部玩家离桌后，下一局开始前按需仅给受影响旁观连接补 2206，避免中途重播结算。旁观期间手牌继续为空数组，不能因映射获得锚点玩家的私牌。原客户端保持不变。回归：`test/game-server/core/seat-view.test.js`、`test/game-server/seat-view-flow.test.js`；浏览器脚本 `--observe` 连续观察两次新发牌并检查每张牌的目标玩家、有限坐标与底部成员，再可接 `--play` 验证主动入座。

普通与全暗用 52 张牌。七癞使用 55 张：0..51 普通牌，52 小王、53 大王、54 天牌；每局随机 A..K 中一个点数，其四张牌加三张王共七张百搭。55..67 是原客户端癞子替换 A..K 的显示编号。原始五张牌、用于拼牛的原牌、替换后的五张逻辑牌分别保存。

普通 niuJi=0..10 为无牛至牛牛，11 银牛、12 顺子、13 五花、14 同花、15 葫芦、16 炸弹、17 五小、18 同花顺。全暗只启用四花、五花、四炸、五小，倍率与普通独立。七癞 niuJi=11..31 依次为小王、大王、天牌、银牛、顺子、同花、金牛、葫芦、炸弹、五小、地龙、天龙、同花顺、火箭、火星、金星、皇家地龙、皇家天龙、霸王、星王、天王；天王 35 倍。

庄闲分别比较；同牌型按原版最大牌点数及黑桃、红桃、梅花、方块顺序比较，七癞同型比较忽略百搭牌，天龙 A 最大。闲家理论分为底注×庄倍×下注倍×胜方牌型倍数。输额不超过开局携带分，赢额同样受开局携带分限制；庄家不足时按赢家牌力从大到小赔付。全部金额为整数积分，结算总和为零，追加带入不能扩大已开始牌局的责任限额。

3411 提供查询、设置、停止自动操作；策略、止盈止损保存在常驻座位，热更新不丢失。

3378/3680 部分带出使用原始积分，限于局间操作且必须保留最低准入筹码；共享账本保存入账和持久化进度，重试期间不允许开新局。每局保存开局规则副本，热更新不会改变正在进行中的可见牌数、倍数或结算规则。

## 回顾与上线边界

3404/3605 对接原版 QznnHistoryModel/HistoryPanel。请求为 roomId、beginNum、endNum、excellentGame；beginNum 从 0 起，-1 查询最新一局，同时兼容旧 Qznn_History 的 inningNum 请求。响应 dataInfo.firstGameList 含 userName/userIcon、posType（庄=1）、cardTypePokers（仅五张）、grabBankerPoint、raiseMultiple、niuJi、score；dataInfo 包含 playMode、endTime。顶层 seeCardNo 与每行 seeCardNo 按记录当局配置返回，控制三张/四张布局；普通和全暗的 handCardListWithLaiZi 必须为空数组，七癞才返回五张逻辑牌，否则原客户端会误用七癞牌型图标。blind 为包含 ante、seeCardNo 的 JSON 字符串。页码使用真实局号；仅本局在房间的参与者/旁观者可读取本局记录。

dev 记录在 cache/game-server/niuniu-history.js，八小时期限、最多 1000 局，随既有 cache/game-server 监听热更新，生产包排除。现有 data-center 的 GetRecords/GetRecordDetail 为通用注单结构，缺少棋牌房间/局号查询与牌局写入契约；生产棋牌回顾和上链公正码需要接通现有外部服务后验收，不能用本地回顾冒充 ES。game-server 禁止直接查询 ES。

测试在 test/game-server/games/niuniu、test/hall/niuniu.test.js；真实原版客户端回归脚本 test/browser/check-niuniu-entry.mjs（--tier=0/4/8/12 --play）。
