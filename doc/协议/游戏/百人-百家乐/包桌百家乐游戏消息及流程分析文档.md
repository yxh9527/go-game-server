## 5. 消息协议

### 5.1 状态

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、inning、supplyState、牌靴计数 | 通知阶段变化 |
| 6205 | ENTER_RESPONSE | 包桌状态、积分、赔率、路单 | 进入快照 |
| 6208 | SHOWDOWN_POKERS | other、banker、showdownPoints、winningAreas | 公布庄闲牌面 |
| 6243 | 庄家管理消息 | normalBankerDataList、specialBankerDataList | 同步庄家状态 |

日志中可见 state=2、3、4、6、7、0：

- state=2：下注阶段；
- state=3：停止下注并开始开牌；
- state=4：牌面展示；
- state=6：积分、路单和牌靴更新；
- state=7：本局收尾；
- state=0：切换下一局。

## 6. 一局包桌百家乐流程

1. HTTP op=38 查询 gameType=1002、playMode=4、gameRoomConfigId=5895。
2. HTTP op=45 选择 roomIndex=1，取得 roomId=27044585。
3. ROOM_LOGIN 和 SEND_JOIN_ROOM 建立普通会话。
4. ENTER 使用 vipTableMode=1 进入包桌房间。
5. ENTER_RESPONSE 返回 playerNum=1、积分、9 区域快照、路单和牌靴。
6. state=2 开放下注，发送 BET 并等待 BET_RESPONSE。
7. state=3 停止下注，服务端发牌。
8. state=4 发送 SHOWDOWN_POKERS，公布庄闲牌面、点数和 winningAreas。
9. state=6 更新积分、路单和牌靴；6243 更新庄家状态。
10. state=7 收尾，state=0 切换下一局。

## 8. 实现建议和限制

- 使用 roomType + gameRoomConfigId + playMode + roomIndex + vipTableMode + roomId + inning 作为唯一上下文。
- 只有 state=2 且倒计时有效时允许 BET。
- 结算先处理 other、banker、showdownPoints，再处理 winningAreas 和积分。
- playerNum=1 代表包桌当前在线人数，不代表协议只有一个下注区域。
- allPlayerBets 按 areaId 映射，不依赖数组顺序。
- 6243 列表可能为空，客户端要兼容空庄家列表。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
