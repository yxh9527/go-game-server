## 5. 消息协议

### 5.1 状态和牌靴

| 编号 | 消息 | 关键字段 | 作用 |

| 6204 | GAME_STATE | state、inning、supplyState、牌靴计数 | 通知阶段变化 |
| 6205 | ENTER_RESPONSE | 房间快照、赔率、路单、牌靴 | 进入时同步 |
| 6208 | SHOWDOWN_POKERS | banker、other、showdownPoints、winningAreas | 公布庄闲牌面和结果 |
| 6210 | PLAYER_BALANCE_UPDATE | points | 更新玩家积分 |

日志中同一局 state 依次出现 3、4、6、7：

- state=2：下注阶段；
- state=3：停止下注并开始开牌；
- state=4：牌面展示；
- state=6：结算、系统分数和路单更新；
- state=7：本局收尾并准备下一局。

### 5.4 开牌和结算

6208 SHOWDOWN_POKERS：

~~~json
{
  "roomType": 58,
  "roomId": 35530591,
  "showdownPokers": {
    "other": [50, 27, 26],
    "banker": [39, 41]
  },
  "showdownPoints": {
    "other": [2, 3],
    "banker": [4]
  },
  "winningAreas": [2, 9],
  "areaWinningScores": {"1": -100},
  "points": 7907,
  "realScore": -100,
  "remainCardsNum": 245,
  "cutIndex": 326
}
~~~

- other：闲家牌，示例中为三张；
- banker：庄家牌，示例中为两张；
- showdownPoints：服务端点数或牌型相关编号；
- winningAreas：本局命中区域；
- areaWinningScores：玩家在区域上的积分变化；
- points：结算后玩家积分；
- realScore：本局实际积分变化；
- remainCardsNum、cutIndex：结算时牌靴进度。

本例 winningAreas=[2,9]，玩家在 areaId=1 下注 100，realScore=-100，points 从 8007 变为 7907。

## 6. 一局经典百家乐流程

1. HTTP op=45 获取 roomType=58、roomIndex=1 的入口。
2. ROOM_LOGIN 建立会话，SEND_JOIN_ROOM 进入 roomId=35530591。
3. GR_GET_ALL_ROOMS_REQ/RES 获取并维护百家乐房间列表。
4. ENTER_RESPONSE 返回牌靴、积分、9 个区域下注和 104 局路单。
5. state=2 开放下注，客户端发送 BET。
6. BET_RESPONSE 确认个人下注，BET_BROADCAST 持续广播各区域总下注。
7. state=3 停止下注并开始发牌。
8. state=4 发送 SHOWDOWN_POKERS，公布庄家、闲家牌面和 winningAreas。
9. state=6 更新积分、牌靴统计、庄家盈亏和路单。
10. state=7 完成本局，下一轮重新进入 state=2。

## 7. 路单和结果字段

ways.1 保存最近最多 104 局的结果，每个元素包含：

- winArea：本局命中区域数组；
- isLiPai：路单特殊标记。

ways.9 保存当前路单类型和轮数，例如：

~~~json
{
  "9": {
    "type": 16,
    "roundNum": 5
  }
}
~~~

路单是展示数据，不能代替 SHOWDOWN_POKERS 的本局结果，也不能用于客户端自行计算积分。

## 8. 实现建议和限制

- 使用 roomType + roomId + inning 作为一局唯一键。
- allPlayerBets 顺序不固定，必须按 areaId 映射。
- 牌靴字段以服务端为准，不要前端自行推算剩余牌。
- 只有 state=2 且倒计时有效时允许 BET。
- 结算先处理 showdownPokers、showdownPoints，再处理 winningAreas、积分和路单。
- roomId=0 的开牌消息需要结合当前 inning 和最近房间快照归属；本日志的目标消息带 roomId=35530591。
- areaOdds 的 oddsList 可能包含多个赔付档位，不能简单当作单一倍数。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
