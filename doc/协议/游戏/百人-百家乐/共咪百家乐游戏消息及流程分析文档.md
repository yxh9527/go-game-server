### 5.3 庄闲开牌和结算

共咪档位的快照直接返回 banker、other 和 showdownPoints：

~~~json
{
  "showdownPokers": {
    "other": [19, 30, 51],
    "banker": [45, 44, 44]
  },
  "showdownPoints": {
    "other": [2, 3],
    "banker": [4]
  },
  "winningAreas": [2, 9],
  "lostAreas": [1, 3, 4, 5, 6, 7, 8]
}
~~~

字段说明：

- other：闲家牌；
- banker：庄家牌；
- showdownPoints：服务端点数或牌型编号；
- winningAreas：本轮命中区域；
- lostAreas：本轮未命中区域；
- points、realScore：玩家积分结果；
- ways：最多 104 局路单及 liPai 标记；
- ways.9：特殊路单类型和轮数。

roomId=0 的 SHOWDOWN_POKERS 需要结合当前 inning 和最近的 ENTER_RESPONSE 归属；目标日志中 ENTER_RESPONSE 已包含带 roomId 的完整结算快照。

## 6. 一局共咪百家乐流程

1. HTTP op=38 查询 gameType=1002、playMode=1 的 roomType=58 档位。
2. HTTP op=45 选择 roomIndex=7，取得 roomId=11830934。
3. ROOM_LOGIN、SEND_JOIN_ROOM、GR_GET_ALL_ROOMS_REQ/RES 建立和同步房间。
4. ENTER_RESPONSE 返回 state、庄闲牌面、9 区域总下注、路单和牌靴进度。
5. state=2 开放下注，客户端发送 BET。
6. BET_RESPONSE 确认个人下注，BET_BROADCAST 广播区域总下注。
7. state=3 停止下注，服务端完成发牌。
8. state=4/6 展示 banker、other、showdownPoints 和 winningAreas。
9. state=7 收尾，state=0 切换下一局。

三种档位共用庄闲和 9 区域协议，但房间配置、路单上下文、进入参数和节奏不同。缓存键至少要包含 gameRoomConfigId、playMode、roomIndex 和 roomId。

## 8. 实现建议和限制

- 使用 roomType + gameRoomConfigId + roomIndex + roomId + inning 作为唯一上下文。
- 牌靴字段以服务端为准，不要前端自行计算剩余牌。
- 只有 state=2 且倒计时有效时允许 BET。
- 结算先处理 banker、other、showdownPoints，再处理 winningAreas 和积分。
- allPlayerBets 按 areaId 映射，不依赖数组顺序。
- oddsList 支持多档赔付，不能简化为单一赔率。
- ROOM_LOGIN 中含用户令牌，正式日志必须脱敏。
