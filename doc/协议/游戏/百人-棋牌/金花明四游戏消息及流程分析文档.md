# 金花明四游戏消息及流程分析

## 1. 日志范围

- 日志文件：C:\Users\Administrator\.codex\attachments\7a811111-5008-49bb-9054-dd496f1ff0d5\Pasted text.txt
- roomType=51
- playMode=4
- 百人连接：RoomSocket-222

同一日志还包含 roomType=25 的传统金花桌消息。本文只分析 roomType=51 的百人协议。

## 2. 进入流程

~~~text
ROOM_LOGIN(1105/1205)
 -> ENTER(6105, roomType=51, playMode=4)
 -> MB_REG_ROOMS_REQ(6123)
 -> MB_REG_ROOMS_RES(6224)
 -> MB_REGED_ROOM_INFOS(6227)
~~~

ENTER：

~~~json
{
  "roomType": 51,
  "playMode": 4
}
~~~

6224 返回多个 roomId，客户端需要按 roomId 分开保存局号和状态。

## 3. 核心消息

| 编号 | 消息 | 用途 |
| ---: | --- | --- |
| 6105 | ENTER | 进入百人模式 |
| 6123 | MB_REG_ROOMS_REQ | 注册百人房间 |
| 6224 | MB_REG_ROOMS_RES | 返回监听房间 |
| 6227 | MB_REGED_ROOM_INFOS | 多桌快照 |
| 6228 | MB_SNC_ROOM_STATE | 单桌状态 |
| 6204 | GAME_STATE | 状态和走势 |
| 6207 | PLAYER_NUM_CHANGE | 人数更新 |
| 6212 | DEAL_CARDS_AND_ODDS | 发牌和赔率 |
| 6202 | BET_BROADCAST | 下注总额 |
| 6229 | MB_ROOM_BET_SETTLE | 开牌和结算 |
| 6124/6225 | MB_UNREG_ROOMS_REQ/RES | 取消注册 |
| 6106 | EXIT | 退出 |

## 4. 牌面和下注区

playMode=4 的百人模式使用 8 个下注区，牌面为红方 hong 和黑方 hei 各三张。日志中的开牌结构：

~~~json
{
  "showdownPokers": {
    "hong": [39, 7, 14],
    "hei": [18, 20, 0]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  }
}
~~~

发牌阶段部分牌可能为 -1，表示尚未公开。

房间快照常见字段：

~~~json
{
  "roomType": 51,
  "playMode": 4,
  "state": 2,
  "roomId": 27349581,
  "inning": 25192,
  "playerNum": 348,
  "points": 10129,
  "totalBetsByArea": {
    "1": 12319200,
    "2": 12672300,
    "3": 1545800,
    "4": 5168000,
    "5": 8082200,
    "6": 1649200,
    "7": 3400000,
    "8": 0
  }
}
~~~

areaOdds 每局动态变化，不能写死。

## 5. 状态机

| state | 主要字段 | 阶段 |
| ---: | --- | --- |
| 0 | roomId、inning | 空闲/局间 |
| 1 | dealPokers、areaOdds | 发牌和赔率 |
| 2 | areaOdds、下注总额 | 下注 |
| 3 | 基础字段 | 中间过渡 |
| 4 | showdownPokers、showdownTypes | 红黑开牌 |
| 5 | 结算过渡 |
| 6 | 系统统计、ways | 统计和走势 |
| 7 | 局末 |

日志推断的单局流程：

~~~text
ENTER
 -> MB_REG_ROOMS_REQ/RES
 -> MB_REGED_ROOM_INFOS
 -> state=1/2
 -> DEAL_CARDS_AND_ODDS
 -> BET_BROADCAST
 -> state=4 红黑开牌
 -> MB_ROOM_BET_SETTLE
 -> GAME_STATE / state=6/7
 -> state=0 / 下一局
~~~

## 6. 结算消息

6229 样本：

~~~json
{
  "roomType": 51,
  "roomId": 10988253,
  "showdownPokers": {
    "hong": [7, 51, 1],
    "hei": [8, 24, 48]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  },
  "winningAreas": [1, 3],
  "tieAreas": [],
  "lostAreas": [2, 4, 5, 6, 7, 8],
  "points": -1,
  "realScore": 0,
  "customData": 2
}
~~~

winningAreas、tieAreas、lostAreas 是下注区结果来源；showdownPokers 和 showdownTypes 是最终牌面和牌型。ways 是红黑/牌型走势对象数组，应原样保存。

## 7. 与传统金花的边界

RoomSocket-111 的 roomType=25、ctjh 使用 ZJH_ACTION_BET_PUSH、ZJH_DEAL_DI_PUSH 等传统金花桌消息；RoomSocket-222 的 roomType=51、playMode=4 才是本文件的百人模式。两套 pot、下注和玩家回合字段不能互换。

金花明四百人模式的识别条件为 roomType=51、playMode=4、8 个下注区、hong/hei 各三张牌。实现时应按 roomId + inning 管理多桌，以 6227 保存快照，以 6228/6212 更新牌面和赔率，以 6229 保存中奖区和最终结算。
