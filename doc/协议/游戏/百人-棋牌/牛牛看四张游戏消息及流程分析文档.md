## 3. 连接建立和多房间注册

RoomSocket-222 以 1105 ROOM_LOGIN 登录，1205 ROOM_LOGIN 返回会话信息。随后按以下顺序进入和订阅：

| 编号 | 消息 | 方向 | 关键字段或作用 |
|---:|---|---|---|
| 6106 | EXIT | 客户端 -> 服务端 | roomType=52，清理旧订阅 |
| 6105 | ENTER | 客户端 -> 服务端 | roomType=52、playMode=2 |
| 6123 | MB_REG_ROOMS_REQ | 客户端 -> 服务端 | 注册 roomType=52 的多房间 |
| 6205 | ENTER_RESPONSE | 服务端 -> 客户端 | 返回当前房间快照 |
| 6225 | MB_UNREG_ROOMS_RES | 服务端 -> 客户端 | 取消旧注册 |
| 6224 | MB_REG_ROOMS_RES | 服务端 -> 客户端 | 返回房间编号列表 |
| 6227 | MB_REGED_ROOM_INFOS | 服务端 -> 客户端 | 批量返回多个房间状态 |

本次当前房间示例为 roomId=41532512、inning=2807；日志同时同步其他 roomId。解析时必须使用 roomId 和 inning 隔离状态。

## 4. 消息协议

### 4.1 房间快照

6205 ENTER_RESPONSE 和 6227 MB_REGED_ROOM_INFOS 包含：

- roomType、playMode、roomId、inning：玩法、档位、房间和局号；
- state、countDown、waitingNextRound：阶段和剩余时间；
- playerNum、points：在线人数和玩家积分；
- totalBetsByArea：区域 1 至 6 的累计下注额；
- dealPokers/showdownPokers：四张公开牌或完整结算牌；
- areaOdds：六个下注区域的本局赔率；
- ways、aWinCount、bWinCount、cWinCount：走势图及历史统计；
- hundredParams：玩法名称、赔率和单人最大下注额。

### 4.2 状态和发牌

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、roomType、inning、cardColor | 百人局阶段通知 |
| 6228 | MB_SNC_ROOM_STATE | state、inning、roomId、areaOdds、dealPokers/showdownPokers | 多房间状态同步 |
| 6212 | DEAL_CARDS_AND_ODDS | cardColor、banker、a、b、c、areaOdds、inning、playMode | 推送四张公开牌和赔率 |
| 6208 | SHOWDOWN_POKERS | showdownPokers、showdownTypes、ways、winningAreas、lostAreas | 推送完整开牌结果 |
| 6229 | MB_ROOM_BET_SETTLE | roomId、showdownPokers、showdownTypes、胜负区域、积分 | 完成一局结算 |

日志可见的状态顺序是 state=0 等待换局、state=1 发牌和赔率、state=2 下注、state=3 停止下注过渡、state=4 展示结算、state=5/6/7 统计和下一局切换。该解释按时序归纳，客户端应以服务端消息为准。

### 4.3 下注

6101 BET 请求示例：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 52,
  "roomId": 41532512
}
~~~

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向一个或多个区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points、myBets、myTotalBets、betAreaIds |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播六个区域总下注额 |
| 6210 | PLAYER_BALANCE_UPDATE | 服务端 -> 客户端 | 更新个人积分 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 客户端 | 更新房间人数 |

BET_RESPONSE.code=0 表示成功。myBets 是当前局个人下注，myTotalBets 是累计下注；BET_BROADCAST 的 allPlayerBets 按 areaId=1..6 返回全体区域总额，playerBets=[] 不代表没有区域下注。

### 4.4 结算

6229 MB_ROOM_BET_SETTLE 示例：

~~~json
{
  "roomType": 52,
  "roomId": 41532512,
  "showdownPokers": {
    "a": [3, 20, 27, 25, 34],
    "b": [19, 39, 32, 1, 21],
    "c": [0, 4, 37, 18, 48],
    "banker": [29, 36, 49, 24, 38]
  },
  "showdownTypes": {"a": 3, "b": 6, "c": 0, "banker": 4},
  "winningAreas": [2, 4, 6],
  "tieAreas": [],
  "lostAreas": [1, 3, 5],
  "points": -1,
  "realScore": -400,
  "customData": 2
}
~~~

- a、b、c、banker 是三门和庄家的完整五张牌；
- showdownTypes 是服务端牌型编号，日志不含完整中文字典；
- winningAreas、tieAreas、lostAreas 是六个下注区域的结果；
- areaWinningScores（部分消息出现）记录个人命中区域收益；
- points、realScore 记录本次积分结算；
- ways 和胜负统计只用于走势图。

6208 SHOWDOWN_POKERS 在日志中有 roomId=0 的统一开牌通知，具体房间归属应结合最近的 roomId、inning 和 6229 消息确认。

## 5. 一局游戏流程

1. HTTP op=38 查询 roomType=52 的百人房间列表。
2. HTTP op=45 选择 playMode=2，得到百人域名和入口信息。
3. 发送 ROOM_LOGIN，建立 RoomSocket-222。
4. 执行 EXIT -> ENTER -> MB_REG_ROOMS_REQ，注册多个 roomType=52 房间。
5. 接收 ENTER_RESPONSE、MB_REG_ROOMS_RES 和 MB_REGED_ROOM_INFOS，初始化房间和局号。
6. 房间进入 state=1，接收 DEAL_CARDS_AND_ODDS；四手牌各显示四张，最后一张为 -1。
7. 房间进入 state=2，客户端发送 BET，并通过 BET_RESPONSE 确认，随后接收 BET_BROADCAST。
8. state=3 后停止下注，服务端发送 SHOWDOWN_POKERS 或 MB_ROOM_BET_SETTLE，补齐第五张。
9. 客户端按 winningAreas、tieAreas、lostAreas 更新结果，再处理积分和走势图。
10. 收到 state=0 或下一局 state=1 后，按新的 roomId、inning 重复。

## 6. 与普通抢庄牛牛通道的区别

同一日志的 RoomSocket-111 是 roomType=24、roomType=qznn、gameName=看四张抢庄牛牛(底注0.1)，采用 DEAL_PERFLOP、GRAB_BANKER、CONFIRM_BANKER、BANKER_SELECT、BANKER_SHOW、XIAN_RAISE、RUBBING_CARDS、SETTLE 等状态，以及 QZNN 系列消息。

该通道是有座位的抢庄牛牛流程。百人看四张必须按 RoomSocket-222、roomType=52、playMode=2 以及 BET、DEAL_CARDS_AND_ODDS、MB_ROOM_BET_SETTLE 解析，不能用 QZNN_Settle_PUSH 代替百人结算。

## 7. 实现建议和限制

- 使用 roomType + roomId + inning 作为状态唯一键。
- -1 保留为未知牌，不能转换为有效牌。
- 每局收到 6212 或 6228 时更新 areaOdds。
- 只有 state=2 且倒计时有效时允许发送 BET。
- BET_RESPONSE 非零时记录错误并停止重复提交。
- 结算先更新五张牌，再更新牌型、胜负区域、积分和走势图。
- ROOM_LOGIN 中含用户令牌，正式日志应脱敏。
