# 百人金花服务端实现

更新：2026-10-29。以 `doc/开发规则.md`、五份金花消息分析和 `static/client/2.0.1279` 原版客户端为依据。本说明区分已实现行为与尚未确认的现网参数；旧抓包分析中的德州公共牌描述不适用于金花。

## 1. 入口与模式

大厅入口为 gameType=1000，百人房间 roomType=51。五个模式共用 `game-server/src/games/hundred-zjh`，普通炸金花仍为 `games/zjh`，二者不共用下注协议。

原版大厅“金花”分类使用 `op=38&gameType=1000&roomType=51`，德州使用 roomType=50；服务端必须按 roomType 过滤配置，不能只按父 gameType 返回混合列表。未指定房间类型的“全部”保留混合列表；使用 subGameType 的入口按游戏类型 ID 映射转换为同一 roomType。浏览器验证必须实际点击“金花”分类，并检查列表数量、名称和 `/1000/51/` 背景资源，不能只从“全部”里筛选出一间金花验证进房。

## 3. 公共流程与资金

`core/BairenGame.js` 和 `core/bairen-engine.js` 复用百人德州的进出房、订阅、阶段倒计时、下注、结算、历史消息；具体游戏只提供发牌、规则、遮罩、牌型、赔率和路单适配。`HundredGame` 与 `core/robot.js` 继续统一调度机器人，禁止在金花目录复制机器人循环。

6101/6201 为当前桌下注，6125/6226 为多房下注。校验真实 roomType/roomId、下注阶段、整数金额、最小/最大值和累计单区限额；非法或零赔率区域禁止下注。重复区域行先汇总校验，不能绕过限额。真人和机器人走相同 placeBet；机器人仅使用公开合法区域、赔率和自身模拟余额，不能读取实际暗牌。机器人资金与真人 RPC 隔离，私有回执不得覆盖真人面板。

本局赔率固定保存在 hand 上；结算按中奖净赔率向下取整，返还中奖本金，未中奖扣除本金。逐玩家保留已完成派彩，拒绝或抛错时留在当前结算阶段重试，不开下一局；热更新及重复 tick 不得重新支付已成功玩家或重复记路单。这里的进度保障不代替正式钱包 RPC 的持久化幂等与跨进程恢复。

6208 先发送开牌模型，再发送 6204/state=4；6229 仅发给对应玩家。6227.hundredParams.betAreaOdds 与 6228.areaOdds 为 `{id,odds}` 对象映射，6212.areaOdds 为数字映射，不能混用。路单为 `{1:{max:100,targetValue:[],ways:[{heiHong,paiXing}]}}`，heiHong=true 表示红胜。

## 4. 条件赔率与正式服务边界

帮助说明要求按公开牌和剩余牌实时计算赔率，但没有给出平台返奖率或优势公式。当前实现对公开牌条件下所有不重复红黑三张组合进行精确计数，不使用蒙特卡洛，不读取本局暗牌；全暗组合数为 407170400。开发净赔率为 `(全部组合数−中奖组合数)/中奖组合数`，向下保留三位小数；概率为 0 或 1 时赔率为 0，禁投。

**上述为开发公平赔率，不代表已经复刻现网运营定价。上线前必须确认实际返奖率、赔率限制与舍入、明三遮罩，并经已有配置/RPC 接入；不能擅自添加抽水或把现网赔率样例硬编码为所有局的赔率。**

开发历史复用 `cache/game-server/hundred-history.js`，每房保存最近 100 局、8 小时 TTL，按玩家参与/旁观权限过滤。6121/6221 返回升序局号，6122/6222 返回个人详情，支持上一局/下一局。不同代理、游戏、房间和玩家结果隔离，退房未结算下注保留归属。

生产不加载 cache。正式回顾的 Redis 缓存与 data-center → ES、正式 lottery 发牌及注单持久化，本次沿用既有集成边界，未接入的功能不得声称已上线；game-server 禁止直连 ES。
