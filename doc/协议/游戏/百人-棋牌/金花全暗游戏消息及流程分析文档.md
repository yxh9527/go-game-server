- 日志文件：C:\Users\Administrator\.codex\attachments\2c53e5ea-f356-49e5-a878-2485ecad5c7d\Pasted text.txt

## 2. 进入流程

## 3. 运行态识别

全暗百人模式的识别条件：

~~~text
roomType=51
playMode=5
8 个下注区
发牌阶段 bankerCards/playerCards 全部或大部分为 -1
~~~

房间列表中的对应配置为 gameRoomConfigId=5105。其余同类模式包括 playMode=1、2、3、4。

## 4. 核心消息

| 编号 | 消息 | 作用 |
| ---: | --- | --- |
| 6105 | ENTER | 进入全暗百人 |
| 6123 | MB_REG_ROOMS_REQ | 注册 roomType=51 |
| 6224 | MB_REG_ROOMS_RES | 返回监听房间 |
| 6227 | MB_REGED_ROOM_INFOS | 多桌快照 |
| 6228 | MB_SNC_ROOM_STATE | 单桌状态 |
| 6204 | GAME_STATE | 阶段、走势和统计 |
| 6207 | PLAYER_NUM_CHANGE | 人数变化 |
| 6212 | DEAL_CARDS_AND_ODDS | 暗牌占位和赔率 |
| 6202 | BET_BROADCAST | 8 区下注汇总 |
| 6229 | MB_ROOM_BET_SETTLE | 开牌、中奖区、结算 |
| 6124/6225 | MB_UNREG_ROOMS_REQ/RES | 取消注册 |
| 6106 | EXIT | 退出 |

## 5. 全暗发牌和遮罩

6212 样本：

~~~json
{
  "bankerCards": [-1, -1, -1],
  "playerCards": [-1, -1, -1],
  "areaOdds": {
    "1": 0.99,
    "2": 0.99,
    "3": 15.71,
    "4": 1.67,
    "5": 2.15,
    "6": 12.78,
    "7": 4.4,
    "8": 211.77
  },
  "roomType": 51,
  "inning": 25251,
  "cardColor": 1
}
~~~

在全暗模式的 state=1、state=2 和 6227 快照中，庄方和闲方牌面可能全部为 -1。-1 是规则要求的遮罩，不是解析失败，也不能据此计算牌型。

## 6. 多桌快照

6227 中常见字段：

~~~json
{
  "roomType": 51,
  "state": 2,
  "playerNum": 762,
  "points": 10024,
  "roomId": 14336853,
  "inning": 24389,
  "totalBetsByArea": {
    "1": 4662200,
    "2": 15312700,
    "3": 1350000,
    "4": 10099000,
    "5": 5648000,
    "6": 1435500,
    "7": 2836300,
    "8": 0
  },
  "playMode": 5
}
~~~

应使用 roomId + inning 管理多桌状态；totalBetsByArea 和 areaOdds 的键范围为 1–8。

## 7. 状态机

| state | 主要字段 | 阶段 |
| ---: | --- | --- |
| 0 | roomId、inning | 空闲/局间 |
| 1 | bankerCards/playerCards、areaOdds | 暗牌发放和赔率 |
| 2 | areaOdds、下注总额 | 下注 |
| 3 | 基础状态 | 过渡 |
| 4 | showdownPokers、showdownTypes | 开牌 |
| 5 | 结算过渡 |
| 6 | systemTodayTotalScore、systemInningScore、ways | 统计和走势 |
| 7 | 局末 |

这是按日志字段出现顺序归纳的状态模型，客户端应保留原始 state 数值。

## 8. 开牌和结算

全暗模式只有进入 state=4 或 6229 时才公开牌面：

~~~json
{
  "showdownPokers": {
    "hong": [18, 34, 36],
    "hei": [13, 35, 33]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 3
  },
  "state": 4,
  "roomType": 51,
  "inning": 25242
}
~~~

6229 结算包括：

~~~json
{
  "roomType": 51,
  "roomId": 39244558,
  "showdownPokers": {
    "hong": [41, 23, 44],
    "hei": [46, 34, 25]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  },
  "winningAreas": [2, 3],
  "tieAreas": [],
  "lostAreas": [1, 4, 5, 6, 7, 8],
  "points": -1,
  "realScore": 0,
  "customData": 2
}
~~~

winningAreas、tieAreas、lostAreas 是下注区结果；showdownPokers、showdownTypes 是红黑最终牌面和牌型。全暗阶段不能用发牌消息推断这些字段。

## 9. 下注和走势

6202 BET_BROADCAST 使用 allPlayerBets 广播 8 个下注区的全桌总额。ways 是走势数据，金花模式中通常是包含 heiHong、paiXing 的对象数组；应原样保存，不要转为简单整数数组。

本日志未提供百人个人下注上行请求，RoomSocket-111 的传统金花 ZJH_ACTION_BET_PUSH 不属于全暗百人下注协议。

## 10. 单局流程

~~~text
ENTER(6105, roomType=51, playMode=5)
 -> MB_REG_ROOMS_REQ/RES(6123/6224)
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(state=1, 全暗遮罩)
 -> DEAL_CARDS_AND_ODDS(6212)
 -> MB_SNC_ROOM_STATE(state=2, 下注)
 -> BET_BROADCAST(6202)
 -> state=4 / 公开 hong、hei
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204, state=6/7)
 -> state=0 / 下一局
~~~

## 11. 退出流程

~~~text
MB_UNREG_ROOMS_REQ(6124)
 -> MB_UNREG_ROOMS_RES(6225)
 -> EXIT(6106, roomType=51)
 -> HTTP op=54 查询钱包
 -> HTTP op=38 刷新 roomType=51 列表
~~~

## 14. 结论

金花全暗百人模式的识别字段：

~~~text
roomType=51
playMode=5
gameRoomConfigId=5105
发牌阶段 bankerCards/playerCards 使用 -1 遮罩
~~~

核心协议链：

~~~text
ENTER
 -> MB_REG_ROOMS_REQ/RES
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(6228)
 -> DEAL_CARDS_AND_ODDS(6212)
 -> BET_BROADCAST(6202)
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204)
 -> EXIT
~~~

实现时必须把 -1 视为全暗规则遮罩，以 roomId + inning 管理多桌，以 6229 的 showdownPokers、showdownTypes 和 winningAreas 作为最终开牌结算依据。
