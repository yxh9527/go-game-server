## 5. 消息协议

### 5.1 状态和发牌

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、roomType、inning、走势图 | 通知局阶段 |
| 6228 | MB_SNC_ROOM_STATE | state、inning、roomId、dealPokers/showdownPokers、areaOdds | 多房间状态同步 |
| 6212 | DEAL_CARDS_AND_ODDS | bankerCards、playerCards、areaOdds、inning | 推送初始牌和本局赔率 |
| 6208 | SHOWDOWN_POKERS | showdownPokers、showdownTypes、winningAreas、tieAreas、lostAreas | 公布最终牌面和结果 |
| 6229 | MB_ROOM_BET_SETTLE | 通用百人结算字段 | 本日志目标房间未单独出现 |

本次日志可见的状态顺序：

- state=0：新局切换；
- state=1：发牌和赔率准备；
- state=2：开放下注；
- state=4：进入时已经是结果展示；
- state=5：结果展示过渡；
- state=6：写入总分和走势；
- state=7：本局收尾；
- 下一局重新回到 state=0、state=1、state=2。

状态含义按日志时序归纳，客户端应以服务端最新消息为准。

### 5.2 下注

6101 BET 请求：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 62,
  "roomId": 17780730
}
~~~

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向一个或多个区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points、myBets、myTotalBets、betAreaIds |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播 11 个区域累计下注额 |
| 6210 | PLAYER_BALANCE_UPDATE | 服务端 -> 客户端 | 更新玩家积分 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 客户端 | 更新房间人数 |

本次下注响应：

~~~json
{
  "points": 8607,
  "roomType": 62,
  "code": 0,
  "myBets": [{"areaId": 1, "total": 100}],
  "myTotalBets": [{"areaId": 1, "total": 100}],
  "betAreaIds": [1],
  "roomId": 17780730
}
~~~

BET_RESPONSE.code=0 表示成功。BET_BROADCAST 的 allPlayerBets 按 areaId=1..11 返回总下注额，playerBets=[] 不表示区域没有下注。areaId=6 在某一时刻总额为 0，仍然是有效区域。

### 5.3 结算

6208 SHOWDOWN_POKERS 示例：

~~~json
{
  "roomType": 62,
  "roomId": 0,
  "showdownPokers": {
    "banker": [5, 1],
    "player": [3, 7]
  },
  "showdownTypes": {
    "banker": 15,
    "player": 27
  },
  "winningAreas": [2],
  "tieAreas": [],
  "lostAreas": [1, 3, 4, 5, 6, 7, 8, 9, 10, 11],
  "areaWinningScores": {"1": -100},
  "points": 8607,
  "realScore": -100
}
~~~

- banker、player 是两手最终牌；
- showdownTypes 是服务端结果类型编号；
- winningAreas、tieAreas、lostAreas 是 11 个下注区域的开奖结果；
- areaWinningScores 是玩家在命中或失利区域的积分变化；
- points 是结算后的积分，realScore 是本次实际变动；
- roomId=0 时不能直接用于房间归属，应结合最近的 roomId、inning 和状态消息。

本日志没有看到 roomType=62 的独立 6229 MB_ROOM_BET_SETTLE，目标玩法的实际结算以 6208 SHOWDOWN_POKERS 和后续 GAME_STATE state=5/6 为主。

## 6. 一局游戏流程

1. HTTP op=38 查询 roomType=62、gameRoomConfigId=6201。
2. HTTP op=45 取得入口并选择 roomType=62。
3. RoomSocket-222 发送 ROOM_LOGIN，建立百人会话。
4. 执行 EXIT -> ENTER，并注册多个百人房间。
5. 接收 ENTER_RESPONSE 和 MB_REGED_ROOM_INFOS，初始化积分、局号、赔率和当前结果。
6. 新局进入 state=0、state=1，收到 DEAL_CARDS_AND_ODDS；banker/player 各有一个首牌，隐藏位置为 -1。
7. state=2 开放 11 个区域下注，客户端发送 BET，使用 BET_RESPONSE 确认，并持续接收 BET_BROADCAST。
8. 下注结束后，服务端发送 SHOWDOWN_POKERS，公开 banker/player 两手最终牌和结果区域。
9. state=5/6 更新积分、走势和历史记录，state=7 完成本局收尾。
10. 下一局回到 state=0，按新的 inning 重复。

## 7. 与普通极速麻将房间的区别

同一日志的 RoomSocket-111 是 roomType=26、roomType=jsmj、gameName=极速麻将(底注0.1)，配置为 2 至 4 人座位房间，包含 diFen、opTime、carryMin、玩家座位和观战列表。

该通道是传统四人桌协议；日志中的百人麻将通道则是 RoomSocket-222、roomType=62、11 个下注区域和 banker/player 结果。不能把 roomType=26 的座位消息当作百人麻将下注协议。

## 8. 实现建议和限制

- 使用 roomType + roomId + inning 作为一局唯一键。
- 初始牌数组中的 -1 保留为未知牌，不能参与牌型计算。
- areaOdds 每局可能变化，收到 6212 或 6228 时覆盖旧值。
- 下注仅在 state=2 且倒计时有效时开放。
- BET_RESPONSE 非零时记录错误码并停止盲目重试。
- 结算先处理 banker/player 和 showdownTypes，再处理胜负区域、积分和走势图。
- roomId=0 的 SHOWDOWN_POKERS 需要结合局号和最近房间状态归属。
- ROOM_LOGIN 含用户令牌，正式调试日志必须脱敏。

已确认：roomType=62、gameName=百人麻将、gameRoomConfigId=6201、playMode=1、11 个下注区域、动态赔率、初始牌字段、下注/广播/响应消息、最终牌面和结算字段。
