## 3. 登录、进入和多房间注册

RoomSocket-222 通过 1105 ROOM_LOGIN 登录，1205 ROOM_LOGIN 返回 serverTime、clubId、exchangeRate 和 openHundredGame 等信息。随后执行：

| 编号 | 消息 | 方向 | 关键字段或作用 |
|---:|---|---|---|
| 6106 | EXIT | 客户端 -> 服务端 | roomType=52，清理旧订阅 |
| 6105 | ENTER | 客户端 -> 服务端 | roomType=52、playMode=5 |
| 6123 | MB_REG_ROOMS_REQ | 客户端 -> 服务端 | 注册 roomType=52 的多个房间 |
| 6205 | ENTER_RESPONSE | 服务端 -> 客户端 | 当前房间快照 |
| 6225 | MB_UNREG_ROOMS_RES | 服务端 -> 客户端 | 取消旧注册 |
| 6224 | MB_REG_ROOMS_RES | 服务端 -> 客户端 | 返回可订阅 roomId |
| 6227 | MB_REGED_ROOM_INFOS | 服务端 -> 客户端 | 批量同步多个房间 |

当前进入房间示例为 roomId=33215787、inning=2823；同一日志还包含多个 roomId 的状态。所有缓存和结算关联必须带上 roomId、inning。

## 4. 百人全暗消息协议

### 4.1 房间快照

6205 ENTER_RESPONSE 和 6227 MB_REGED_ROOM_INFOS 包含：

- roomType、playMode、roomId、inning：玩法、档位、房间和局号；
- state、countDown、waitingNextRound：状态、剩余时间和换局等待；
- playerNum、points：在线人数和玩家积分；
- totalBetsByArea：区域 1 至 6 的累计下注；
- dealPokers/showdownPokers：全暗数组或结算完整牌面；
- areaOdds：本局六个区域赔率；
- ways、aWinCount、bWinCount、cWinCount：走势图和三门统计；
- hundredParams：玩法名、赔率和最大下注额。

### 4.2 状态和发牌消息

| 编号 | 消息 | 关键字段 | 作用 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、roomType、inning、cardColor | 通知房间阶段 |
| 6228 | MB_SNC_ROOM_STATE | state、inning、roomId、dealPokers/showdownPokers、ways | 多房间状态同步 |
| 6212 | DEAL_CARDS_AND_ODDS | cardColor、banker、a、b、c、areaOdds、inning、playMode | 通知新局赔率和全暗牌面 |
| 6208 | SHOWDOWN_POKERS | showdownPokers、showdownTypes、ways、胜负区域 | 统一开牌展示 |
| 6229 | MB_ROOM_BET_SETTLE | roomId、showdownPokers、showdownTypes、胜负区域、积分 | 完整结算 |

日志可观察到 state=0 等待换局、state=1 发牌准备、state=2 下注、state=3 停止下注过渡、state=4 开牌展示、state=5/6/7 统计和下一局切换。该映射按时序归纳，正式实现应以服务端状态为准。

### 4.3 下注协议

全暗期间仍然可以按区域下注，6101 BET 请求结构与其他百人档位一致：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 52,
  "roomId": 33215787
}
~~~

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向一个或多个区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points、myBets、myTotalBets、betAreaIds |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播六个区域总下注额 |
| 6210 | PLAYER_BALANCE_UPDATE | 服务端 -> 客户端 | 更新玩家积分 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 服务端 | 更新房间人数 |

BET_RESPONSE.code=0 表示下注成功。由于全暗档位赔率为 1，客户端仍应以服务端返回的 areaOdds 和结算分数为准，不能在前端自行套固定倍数。BET_BROADCAST 的 allPlayerBets 按 areaId=1..6 给出总额，playerBets=[] 只表示没有个人明细广播。

### 4.4 结算协议

6229 MB_ROOM_BET_SETTLE 的全暗结算示例：

~~~json
{
  "roomType": 52,
  "roomId": 33215787,
  "showdownPokers": {
    "a": [14, 30, 5, 24, 19],
    "b": [6, 39, 32, 8, 11],
    "c": [4, 48, 40, 7, 46],
    "banker": [23, 41, 37, 33, 44]
  },
  "showdownTypes": {"a": 0, "b": 4, "c": 3, "banker": 0},
  "winningAreas": [2, 3, 4],
  "tieAreas": [],
  "lostAreas": [1, 5, 6],
  "points": -1,
  "realScore": 0,
  "customData": 2
}
~~~

- a、b、c、banker 是三门和庄家的五张牌；
- showdownTypes 是牌型编号，日志未给出完整中文映射；
- winningAreas、tieAreas、lostAreas 是六个下注区域结果；
- areaWinningScores（部分消息出现）记录个人命中区域收益；
- points、realScore 记录玩家积分结算；
- ways 和胜负次数仅用于走势图。

日志中的 6208 SHOWDOWN_POKERS 可能带 roomId=0，应用时应结合最新的 roomId、inning 和 6229 结算消息做归属。

## 5. 一局游戏流程

1. HTTP op=38 查询 roomType=52 房间档位。
2. HTTP op=45 选择 playMode=5，获取百人域名和入口。
3. 发送 ROOM_LOGIN，建立 RoomSocket-222。
4. 执行 EXIT -> ENTER -> MB_REG_ROOMS_REQ，注册多个同类房间。
5. 接收 ENTER_RESPONSE、MB_REG_ROOMS_RES 和 MB_REGED_ROOM_INFOS，初始化房间状态和积分。
6. 房间进入 state=1，收到 DEAL_CARDS_AND_ODDS；四手牌全部为 -1，前端只显示牌背或未知状态。
7. 房间进入 state=2，开放六个区域下注；发送 BET 并通过 BET_RESPONSE 确认，持续接收 BET_BROADCAST。
8. 房间进入 state=3，停止下注；不向客户端公开任何牌值。
9. state=4 时收到 SHOWDOWN_POKERS 或 MB_ROOM_BET_SETTLE，服务端一次性公开四手完整五张牌及牌型。
10. 按 winningAreas、tieAreas、lostAreas 更新结果，再处理 points/realScore、走势图和历史记录。
11. 收到 state=0 或新局 state=1 后，使用新的 roomId、inning 重复。

## 7. 与普通抢庄牛牛的区别

同一日志的 RoomSocket-111 是 roomType=24、roomType=qznn、gameName=看四张抢庄牛牛(底注0.1)，使用 DEAL_PERFLOP、GRAB_BANKER、CONFIRM_BANKER、BANKER_SELECT、BANKER_SHOW、XIAN_RAISE、RUBBING_CARDS、SETTLE 和 QZNN 系列消息。

这套有座位抢庄协议不应与百人全暗的 BET、DEAL_CARDS_AND_ODDS、MB_ROOM_BET_SETTLE 混用。分析百人全暗时必须以 RoomSocket-222、roomType=52、playMode=5 为准。

## 8. 实现建议和限制

- 使用 roomType + roomId + inning 作为状态和牌面的唯一键。
- 全暗阶段所有 -1 都保留为未知牌，不能转成有效牌，也不能提前计算牌型。
- 收到 6212 或 6228 时更新 areaOdds，但只在 state=2 开放下注。
- BET_RESPONSE 非零时保留错误码并停止盲目重试。
- 结算先写入 showdownPokers 和 showdownTypes，再处理胜负区域、积分和走势图。
- ROOM_LOGIN 含用户令牌，正式调试日志必须脱敏。
