# 跨游戏快捷投注服务端实现

2026-10-30 用户确认：保留原版跨游戏快捷投注，只修复数据和下注功能。原始 static/client 与 static/hall 不作修改；业务通过常驻进程热更新。

## 原版依据

- BlackJack/index.13d44.js 初始化 BairenMultyBet 为 [58]，即百人二十一点 60 的下方为百家乐。
- Bairen/index.85029.js 的麻将配置初始化为 [50]，即百人麻将 62 的下方为百人德州。
- BairenMultyBet/index.74b50.js 内嵌预制体仅含 58/50/51/52，customData=2；完整 MultyBet 弹窗使用另一注册上下文。
- 58 先发 6126，6230 返回房号后顶层 6123 注册 roomType/roomIds；50 则使用 mulRoomTypeList。6125 发 params/roomType/roomId，不带 customData。

## 公共订阅与隔离

core/hundred-subscriptions.js 管理每个连接各游戏房间及 customData 集合，保留 hundredRoomIds 兼容原字段；旧连接按既有订阅迁移，不重建余额或房间。配置发现和下注目标均按登录所得 agentId 隔离。当前主百人桌、普通宿主和附加快捷房间彼此独立；注册不会改变普通 roomId/gameId 或 hundredRoomId/hundredGameId。

6123 只替换本 customData 下的订阅；有标签的 6124 只清理对应上下文，空 6124 清除附加订阅但保留主桌。6106/断线清理全部百人订阅；未结算投入仍保留其 playerSessions 所有者，结算完成再清理。

6224 注册、6227 快照、6228 状态、6229 个人结果均沿真实目标和注册标签投递。6125 缺少标签时，6226 使用该目标最近有效注册上下文。未订阅、错类型、跨代理返回 95041，不扣款；默认上下文 2 让原版快捷模型能接收失败并重新注册。当前桌必需上下文 2 保留。6204/6208/6212/余额等主桌事件仅投递主桌选择者，不能用跨游戏事件覆盖主画面。

快捷下注回执和跨游戏个人结算后，另用已有 9212 GAME_POINT_UPDATE 同步本人钱包，payload必须为积分数字：原版common_model直接将整个payload赋给可用余额，BlackJack/Bairen也支持数字；不能发{point,points}对象导致共享模型变成对象。原版快捷模型不从6226/6229自动刷新主游戏顶部金额，不能为隔离其他房间的6210而漏掉公共金币同步；也不得将其他房间的牌面/阶段混入主桌。浏览器须断言扣款、派彩后顶部与快捷可用余额都和回执一致。

## 两种卡片的数据

百人德州沿现有公共引擎：6227.hundredParams.betAreaOdds 和 6228.areaOdds 使用 {id,odds}；主桌 6212.areaOdds 使用数字映射。五玩法均可注册，冻结赔率、下注和个人派彩沿原公共逻辑。

百家乐 6227/6228 提供 playMode、roomIndex、剩余毫秒 countDown、hundredParams.maxBet/betAreaOdds、ownBets；赔率值为 {id,oddsList:[净赔率×100]}。客户端枚举明确闲1、庄2、和3、闲对4、庄对5，经典闲净赔1、庄0.95。此前庄闲及对子反向已校正，不能依据旧文档推测编号。当前快捷卡片仅显示闲/庄两区；未实现的特殊边注条件仍关闭，不能宣称百家乐所有边注玩法完成。

路单 ways[1] 使用 {max:104,ways:[{winArea:[...],isLiPai:false,...}]}；ways[9] 无好路时为 {type:16384,roundNum:0}，原版 HundredDef.GoodRouteType.Non=16384。不能发 [] 或 type=0，否则原版会加载 textures/undefined。当前不生成未经确认的好路推荐。

百家乐使用真实截止时间：25秒下注（原版 CLASSIC_TOTAL_COUNT_DOWN）、1秒封盘、6秒开牌、3秒结算、1秒结束、1秒 STARTING 清理，再开下注。非下注阶段时长是开发动画窗口，并非声明精确复现现网。只在阶段转换推送，避免每秒重置原版时钟。新价格从下一局生效；本局配置及余额进度不因热更新重置。

派彩逐用户保存 credited/notified 与 settlementTask，和局闲庄退本金，其他已开放边注独立结算；一次 credit 支付本金加净输赢。失败保留阶段与用户进度，下 tick 重试，成功用户和并发请求不重复派彩。6229 含本人的 realScore、areaWinningScores、points、牌面、点数及路单；机器人使用公共虚拟钱包。编码0是有效A牌，补牌判断不能将0误认为未补第三张。

这里只补齐已存在原版快捷路径，不改其展示成游戏专属面板。正式钱包/data-center、lottery、Redis/ES、注单与跨仓种子仍沿既有边界；不因开发环境测试通过就宣称生产外部服务全部接通。
