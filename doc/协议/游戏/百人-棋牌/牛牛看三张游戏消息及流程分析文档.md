## 2. 玩法识别与配置

大厅通过 HTTP op=38 查询 roomType=52 的百人房间列表，列表包含 playMode=5、4、3、2、1 等档位。随后 HTTP op=45 的编码参数明确选择 playMode=1：

~~~text
gameType=52&smallBlind=0&bigBlind=0&playMode=1&roomType=52&ante=0
~~~

百人 Socket 的 6205 ENTER_RESPONSE 返回：

~~~json
{
  "roomType": 52,
  "playMode": 1,
  "hundredParams": {
    "gameName": "百人牛牛看三张(底注1)",
    "gameRoomConfigId": 102,
    "betAreaOdds": {
      "1": {"id": 1, "odds": 0.75},
      "2": {"id": 2, "odds": 1.10},

      "5": {"id": 5, "odds": 0.90},
      "6": {"id": 6, "odds": 1.81}

~~~

这里以服务端返回的 gameName 和实际 ENTER 参数识别玩法。大厅列表中的其他 playMode 是可选档位，不能因为同为 roomType=52 就当作当前玩法。

### 2.1 看三张的牌面结构

日志的初始房间同步出现：

~~~json
{
  "dealPokers": {
    "a": [4, 15, 44, -1, -1],
    "b": [22, 33, 43, -1, -1],
    "c": [47, 24, 28, -1, -1],
    "banker": [35, 34, 45, -1, -1]
  }
}
~~~

每手牌的前三个位置已经公开，后两个位置为 -1；结算时四手牌会变成完整五张。例如同一局最终为：

~~~json
{
  "a": [4, 15, 44, 37, 21],
  "b": [22, 33, 43, 51, 2],
  "c": [47, 24, 28, 5, 40],
  "banker": [35, 34, 45, 29, 3]
}
~~~

-1 表示该阶段尚未公开或尚未发出，不应当作为牌值参与计算。

## 3. 连接建立和多房间注册

RoomSocket-222 先通过 1105 ROOM_LOGIN 登录，1205 ROOM_LOGIN 返回 serverTime、clubId、exchangeRate 和 openHundredGame 等会话信息。随后执行退出、进入和多房间注册：

| 编号 | 消息 | 方向 | 关键字段或作用 |
|---:|---|---|---|
| 6106 | EXIT | 客户端 -> 服务端 | roomType=52，清理旧订阅 |
| 6105 | ENTER | 客户端 -> 服务端 | roomType=52、playMode=1 |
| 6123 | MB_REG_ROOMS_REQ | 客户端 -> 服务端 | 注册 roomType=52 的多房间列表 |
| 6205 | ENTER_RESPONSE | 服务端 -> 客户端 | 返回当前房间状态、积分和牌面 |
| 6225 | MB_UNREG_ROOMS_RES | 服务端 -> 客户端 | 取消旧的多房间注册 |
| 6224 | MB_REG_ROOMS_RES | 服务端 -> 客户端 | 返回可订阅 roomId |
| 6227 | MB_REGED_ROOM_INFOS | 服务端 -> 客户端 | 批量返回多个百人房间快照 |

本次当前房间示例为 roomId=48719594、inning=2748；日志还同步了 41532512、22697429、43852513、33215787 等房间。多房间状态必须以 roomId 和 inning 隔离。

## 4. 百人牛牛看三张消息协议

### 4.1 房间快照

6205 ENTER_RESPONSE 和 6227 MB_REGED_ROOM_INFOS 的房间记录包含：

- roomType、playMode、roomId、inning：玩法、档位、房间和局号；
- state、countDown、waitingNextRound：房间阶段和剩余时间；
- playerNum、points：在线人数和玩家积分；
- totalBetsByArea：区域 1 至 6 的累计下注额；
- dealPokers/showdownPokers：三张公开牌或结算后的五张牌；
- areaOdds：本局六个下注区域的赔率；
- ways、aWinCount、bWinCount、cWinCount：路单和三门统计；
- hundredParams：玩法名、赔率和最大下注额。

### 4.2 状态、发牌和开牌

| 编号 | 消息 | 关键字段 | 用途 |
|---:|---|---|---|
| 6204 | GAME_STATE | state、roomType、inning、cardColor | 通知当前房间阶段 |
| 6228 | MB_SNC_ROOM_STATE | state、inning、roomId、areaOdds、dealPokers/showdownPokers | 多房间状态同步 |
| 6212 | DEAL_CARDS_AND_ODDS | cardColor、banker、a、b、c、areaOdds、inning、playMode | 推送三张公开牌和本局赔率 |
| 6208 | SHOWDOWN_POKERS | showdownPokers、showdownTypes、ways、winningAreas、lostAreas | 推送完整牌面和开奖结果 |
| 6229 | MB_ROOM_BET_SETTLE | roomId、showdownPokers、showdownTypes、胜负区域、积分 | 完成一局结算 |

日志中可观察到：

- state=0：上一局完成后的等待；
- state=1：发出三张明牌和赔率；
- state=2：下注阶段；
- state=3：停止下注或开牌过渡；
- state=4：完整牌面展示；
- state=5/6/7：结算统计、结果同步和下一局准备。

这些状态解释是根据同一局号的时序字段归纳的，客户端应以服务端状态消息为准，不要依赖固定定时器。

### 4.3 下注

日志中客户端提交 6101 BET 的结构为：

~~~json
{
  "params": [{"areaId": 1, "total": 100}],
  "roomType": 52,
  "roomId": 48719594
}
~~~

| 编号 | 消息 | 方向 | 作用 |
|---:|---|---|---|
| 6101 | BET | 客户端 -> 服务端 | 向一个或多个区域下注 |
| 6201 | BET_RESPONSE | 服务端 -> 客户端 | 返回 code、points、myBets、myTotalBets、betAreaIds |
| 6202 | BET_BROADCAST | 服务端 -> 客户端 | 广播六个区域的总下注额 |
| 6210 | PLAYER_BALANCE_UPDATE | 服务端 -> 客户端 | 更新个人积分 |
| 6207 | PLAYER_NUM_CHANGE | 服务端 -> 客户端 | 更新房间人数 |

BET_RESPONSE.code=0 表示请求成功。myBets 是本局个人下注记录，myTotalBets 是累计下注记录；BET_BROADCAST 的 allPlayerBets 按 areaId=1..6 返回全体玩家下注总额。playerBets=[] 不代表区域没有下注。

### 4.4 结算

日志中的 6229 MB_ROOM_BET_SETTLE 示例：

~~~json
{
  "roomType": 52,
  "roomId": 41532512,
  "showdownPokers": {
    "a": [18, 33, 27, 7, 20],
    "b": [13, 6, 2, 46, 23],
    "c": [40, 21, 17, 45, 34],
    "banker": [38, 14, 36, 25, 35]
  },
  "showdownTypes": {"a": 0, "b": 9, "c": 2, "banker": 2},
  "winningAreas": [2, 4, 6],
  "tieAreas": [],
  "lostAreas": [1, 3, 5],
  "points": -1,
  "realScore": 0,
  "customData": 2
}
~~~

- a、b、c、banker 是三门和庄家的完整五张牌；
- showdownTypes 是服务端牌型编号，日志未包含完整中文映射；
- winningAreas、tieAreas、lostAreas 是六个下注区域的结果；
- areaWinningScores（部分消息出现）记录玩家命中区域的收益；
- points、realScore 反映本次结算积分变化；
- ways 和胜负次数只用于走势图。

日志还出现 6208 SHOWDOWN_POKERS，其中 roomId=0，表示当前播放链路的统一开牌通知。需要结合最近的 roomId、inning 和 6229 结算消息归属具体房间。

## 5. 一局游戏流程

1. HTTP op=38 获取 roomType=52 的房间档位和人数。
2. HTTP op=45 选择 playMode=1，并得到百人域名和入口信息。
3. 发送 ROOM_LOGIN，建立 RoomSocket-222。
4. 执行 EXIT -> ENTER -> MB_REG_ROOMS_REQ，注册同类型多个百人房间。
5. 接收 ENTER_RESPONSE、MB_REG_ROOMS_RES 和 MB_REGED_ROOM_INFOS，初始化房间快照。
6. 某一房间进入 state=1 时，接收 DEAL_CARDS_AND_ODDS；a、b、c、banker 各显示三张牌，剩余两张为 -1。
7. 房间进入 state=2，客户端发送 BET，使用 BET_RESPONSE 确认，随后持续接收 BET_BROADCAST。
8. 房间进入 state=3 后停止接受下注，服务端发送 SHOWDOWN_POKERS 或 MB_ROOM_BET_SETTLE，补齐每手第四、第五张牌。
9. 客户端按 winningAreas、tieAreas、lostAreas 更新结果，再处理 points/realScore、走势图和历史记录。
10. 收到 state=0 或下一局 state=1 后，按新的 roomId、inning 重复。

## 6. 与普通抢庄牛牛的区别

同一日志的 RoomSocket-111 返回 roomType=24、roomType=qznn、gameName=看四张抢庄牛牛(底注0.1)、seeCardNo=4。其状态名为 DEAL_PERFLOP、GRAB_BANKER、CONFIRM_BANKER、BANKER_SELECT、BANKER_SHOW、XIAN_RAISE、RUBBING_CARDS、SETTLE，消息包括 QZNN_Grab_PUSH、QZNN_BankerAnm、QZNN_BetResult_PUSH、QZNN_ShowCard_PUSH 和 QZNN_Settle_PUSH。

这是有座位玩家的抢庄牛牛协议。百人看三张应只按 RoomSocket-222、roomType=52、playMode=1 以及 BET、DEAL_CARDS_AND_ODDS、MB_ROOM_BET_SETTLE 等消息解析。

## 7. 实现和校验建议

- 使用 roomType + roomId + inning 作为一局唯一键。
- -1 代表未知牌，显示层可显示牌背，逻辑层不得将其转为有效牌。
- 每局收到 6212 或 6228 时更新 areaOdds，不能永久复用登录时赔率。
- 只有 state=2 且倒计时有效时允许发送 BET。
- BET_RESPONSE 非零时保留错误码并停止本次重试，避免重复扣分。
- 结算先更新五张牌和牌型，再更新胜负区域、积分和走势图。
- ROOM_LOGIN 含用户令牌，正式日志必须脱敏。
