# 金花明三游戏消息及流程分析

## 1. 分析范围

- 日志文件：C:\Users\Administrator\.codex\attachments\1ca67e9c-51ce-47f8-95b0-7259679d51c5\Pasted text.txt
- 用户命名：金花明三
- 百人房间：roomType=51
- 进入模式：playMode=3
- 百人消息连接：RoomSocket-222
- 同日志中的 RoomSocket-111：roomType=25 传统金花桌，属于另一套桌内协议

本日志的百人部分使用红方 hong、黑方 hei 各三张牌和 8 个下注区。本文以 roomType、playMode、牌面结构和百人消息行为识别玩法。

## 2. 进入流程

大厅 op=45 参数包含：

~~~text
gameType=51
playMode=3
roomType=51
openHundredGame=true
~~~

百人连接流程：

~~~text
ROOM_LOGIN(1105/1205)
 -> ENTER(6105, roomType=51, playMode=3)
 -> MB_REG_ROOMS_REQ(6123)
 -> MB_REG_ROOMS_RES(6224)
 -> MB_REGED_ROOM_INFOS(6227)
~~~

ENTER 请求：

~~~json
{
  "roomType": 51,
  "playMode": 3
}
~~~

6224 返回多个 roomId，客户端需要为每张桌维护独立 inning、state、赔率和下注数据。

## 3. 核心消息

| 编号 | 消息 | 作用 |
| ---: | --- | --- |
| 6105 | ENTER | 进入百人模式 |
| 6123 | MB_REG_ROOMS_REQ | 注册 roomType=51 房间 |
| 6224 | MB_REG_ROOMS_RES | 返回监听房间 |
| 6227 | MB_REGED_ROOM_INFOS | 多桌快照 |
| 6228 | MB_SNC_ROOM_STATE | 单桌状态 |
| 6204 | GAME_STATE | 状态、统计和走势 |
| 6205 | ENTER_RESPONSE | 当前进入响应 |
| 6207 | PLAYER_NUM_CHANGE | 房间人数变化 |
| 6212 | DEAL_CARDS_AND_ODDS | 发牌、牌面和赔率 |
| 6202 | BET_BROADCAST | 下注总额广播 |
| 6229 | MB_ROOM_BET_SETTLE | 中奖区和最终牌面结算 |
| 6124 / 6225 | MB_UNREG_ROOMS_REQ/RES | 取消监听 |
| 6106 | EXIT | 退出百人连接 |

## 4. 百人快照字段

日志中的 6205/6227 快照包含：

~~~json
{
  "roomType": 51,
  "state": 2,
  "playerId": 49380451,
  "playerNum": 215,
  "points": 9893,
  "roomId": 55217563,
  "inning": 2925,

    "1": 5963900,

    "4": 12672800,
    "5": 275400,
    "6": 844900,
    "7": 41000,
    "8": 49700

  "playMode": 3

~~~

字段含义：

- roomId：百人桌 ID；
- inning：当前局号；
- state：当前阶段；
- playerNum：百人房间人数；
- points：当前账号积分；
- totalBetsByArea：8 个下注区的累计下注；
- countDown：阶段倒计时；
- ways：红黑和牌型走势；
- areaOdds：本局动态赔率。

## 5. 牌面结构

金花明三的百人牌面使用红方和黑方两组牌，每组 3 张：

~~~json
{
  "showdownPokers": {
    "hong": [16, 30, 35],
    "hei": [19, 27, 24]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  },
  "state": 4,
  "roomType": 51,
  "inning": 2953
}
~~~

发牌阶段牌面可能被 -1 遮罩，开牌阶段由 hong、hei 和 showdownTypes 提供结果。不要把两组牌解释为德州扑克的庄家、闲家和公共牌。

## 6. 下注区和走势

本日志每局使用 8 个下注区，赔率通过 areaOdds 动态下发。ways 的数据是对象数组：

~~~json
{
  "max": 100,
  "targetValue": [],
  "ways": [
    {"heiHong": true, "paiXing": 1},
    {"heiHong": false, "paiXing": 2},
    {"heiHong": true, "paiXing": 3}
  ]
}
~~~

heiHong 表示红黑侧，paiXing 是牌型枚举。完整牌型映射未在日志中直接声明，应保留原始数值。

如果收到 6202 BET_BROADCAST，使用 allPlayerBets 更新区域总额；本日志的个人下注字段可能为空，不能假设每条广播都包含个人下注。

## 7. 状态机

日志上下文可归纳：

| state | 主要内容 | 阶段 |
| ---: | --- | --- |
| 0 | roomId、inning、cardColor | 空闲/局间 |
| 1 | dealPokers、areaOdds | 发牌与赔率 |
| 2 | areaOdds、下注总额 | 下注 |
| 3 | 基础状态字段 | 中间过渡 |
| 4 | hong/hei 开牌 | 结果展示 |
| 5 | 结算过渡 | 等待统计 |
| 6 | systemTodayTotalScore、systemInningScore、ways | 统计和走势 |
| 7 | 局末 | 进入下一局 |

解析器应保留原始 state，不要只依赖中文推断。

## 9. 典型流程

~~~text
ENTER(6105, roomType=51, playMode=3)
 -> MB_REG_ROOMS_REQ/RES(6123/6224)
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(state=1/2)
 -> DEAL_CARDS_AND_ODDS(6212)
 -> BET_BROADCAST(6202)
 -> MB_SNC_ROOM_STATE(state=4, hong/hei开牌)
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204, state=6/7)
 -> state=0 / 下一局
 -> MB_UNREG_ROOMS_REQ/RES
 -> EXIT(6106)
~~~

多桌并发时，不能用一个全局 state 覆盖所有房间，必须用 roomId 和 inning 作为索引。

## 10. 与传统金花的边界

RoomSocket-111 的 roomType=25、玩法标识 ctjh，使用 ZJH_ACTION_BET_PUSH、ZJH_DEAL_DI_PUSH、ZJH_ZHUANG_PUSH 等传统金花桌消息。RoomSocket-222 的 roomType=51 才是本文件分析的百人模式。

传统金花的玩家 pot、底注和操作轮次不能直接映射为百人下注区金额。该日志没有捕获百人个人下注上行消息。

