## 4. 牌面结构

金花明一不是庄家/闲家/公共牌结构，而是红方和黑方各三张牌：

~~~json
{
  "dealPokers": {
    "playerCards": [-1, -1, -1],
    "bankerCards": [11, 38, 7]
  },
  "state": 1,
  "roomType": 51,
  "inning": 25515,
  "areaOdds": {
    "1": 0.798,
    "2": 1.252,
    "3": 0.34,
    "4": 4.91,
    "5": 29.3,
    "6": 19.09,
    "7": 459.6,
    "8": 427.46
  },
  "roomId": 48137188,
  "cardColor": 1,
  "customData": 2
}
~~~

日志中的字段名仍然使用 playerCards/bankerCards，但结算时实际使用 hong/hei：

~~~json
{
  "showdownPokers": {
    "hong": [7, 51, 1],
    "hei": [8, 24, 48]
  },
  "showdownTypes": {
    "hong": 1,
    "hei": 1
  },
  "state": 4,
  "roomType": 51
}
~~~

因此客户端应以 hong/hei 作为金花业务语义，不能把 banker/player 当作德州扑克庄闲。

## 7. 走势 ways 与牌型

金花明一的 ways 不再是简单整数路单，而是对象数组：

~~~json
{
  "1": {
    "max": 100,
    "targetValue": [],
    "ways": [
      {"heiHong": true, "paiXing": 4},
      {"heiHong": false, "paiXing": 2},
      {"heiHong": true, "paiXing": 1}
    ]
  }
}
~~~

字段含义：

- heiHong：红黑属性；
- paiXing：牌型枚举；
- targetValue：目标值扩展字段；
- max：该下注区路单最大长度。

实现时应保留对象结构，不能按德州暗五的整数 ways 数组解析。

结算字段：

| realScore | 实际结算分 |
| ways | 牌型/红黑走势 |

## 9. 金花明一状态机

~~~text
ROOM_LOGIN
 -> ENTER(6105, roomType=51, playMode=1)
 -> MB_REG_ROOMS_REQ(6123)
 -> MB_REG_ROOMS_RES(6224)
 -> MB_REGED_ROOM_INFOS(6227)
 -> MB_SNC_ROOM_STATE(state=1/2)
 -> DEAL_CARDS_AND_ODDS(6212)
 -> MB_SNC_ROOM_STATE(state=4, hong/hei 开牌)
 -> MB_ROOM_BET_SETTLE(6229)
 -> GAME_STATE(6204, state=6/7)
 -> 下一局
 -> MB_UNREG_ROOMS_REQ/RES
 -> EXIT(6106)
~~~

## 10. 与扑克类百人协议的差异

| 项目 | 金花明一 | 暗五/全暗扑克百人 |
| --- | --- | --- |
| roomType | 51 | 50 |
| gameRoomConfigId | 101 | 100 |
| 牌面 | hong/hei 各三张 | banker/player/board |
| 下注区 | 1–8 | 1–7 |
| ways | heiHong/paiXing 对象数组 | 整数路单数组 |
| 游戏名 | 明牌红1黑1 | 暗五公牌/全暗 |
| 结算字段 | 红黑牌型 | 庄家、公共牌、闲家牌型 |

