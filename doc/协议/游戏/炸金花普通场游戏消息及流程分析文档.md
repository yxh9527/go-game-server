## 3. 登录和进房流程

客户端先调用大厅 `op=45` 获取房间号和域名，然后建立 `RoomSocket-111` 和辅助 `RoomSocket-222` 连接。

客户端发送 `1105 ROOM_LOGIN`，服务端通过 `1205 ROOM_LOGIN` 返回服务端时间和登录上下文。主连接随后执行：

1. `2102 SEND_JOIN_ROOM`：`roomType=25`，申请进入炸金花房间。
2. `2219 DZPK_PUSH_WATCHGAME`：返回观战玩家列表，消息名沿用通用德州命名。
3. `2201 ROOM_TYPE_RESULT`：返回 `ctjhParams`。
4. `2200/2221 COMMON_SWITCH_REQ/RES`：通用开关。
5. `2111 LOGIN_ROOM`：正式进入房间。
6. `2206 ROOM_INFO`：同步座位、玩家、观战者和当前局号。

## 5. 游戏流程

### 5.1 牌局状态

本次普通场日志观察到的状态为：

```text
BET_FRONT
 -> DEAL_PERFLOP
 -> BET_PERFLOP
 -> SETTLE
```

炸金花不使用德州扑克的翻牌、转牌和河牌状态。`3263 BRNN_GAME_STATE_PUSH` 是通用状态消息，具体炸金花业务由 `ZJH_*` 消息承载。

### 5.2 前置下注和发牌

`BET_FRONT` 阶段每名玩家支付底注：

```json
{
  "uid": "<uid>",
  "currentBetScore": 10,
  "totalBetScore": 10,
  "totalBetScoreMen": 0,
  "totalBetScoreNotMen": 0,
  "operation": 1,
  "point": 490,
  "pot": 10
}
```

随后发送 `3727 ZJH_DEAL_DI_PUSH`：

```json
[
  {"uid":"<uid>"},
  {"uid":"<uid>"},
  {"uid":"<uid>"}
]
```

未授权的底牌不会直接出现在该消息中；客户端自己的牌可能以 `[-1,-1,-1]` 占位，之后通过授权或展示消息补齐。

`3731 ZJH_ZHUANG_PUSH` 示例：

```json
{
  "bankerId": "<uid>",
  "smallBlindId": 0,
  "bigBlindId": 0,
  "straddleUid": 0,
  "underTheGunUid": "<uid>",
  "bankerPos": 0
}
```

### 5.3 下注和操作

客户端提交 `3562 ZJH_SEND_ACTION`：

```json
{
  "uid": "<uid>",
  "operation": 3,
  "operationData": 0.2
}
```

服务端通过 `3740 ZJH_ACTION_BET_PUSH` 确认：

```json
{
  "uid": "<uid>",
  "currentBetScore": 20,
  "totalBetScore": 40,
  "totalBetScoreMen": 0,
  "totalBetScoreNotMen": 0,
  "operation": 3,
  "point": 260,
  "pot": 100
}
```

随后通过 `3733 ZJH_OPERATION_PLAYER_PUSH` 指定下一位操作玩家，并通过 `3780 ZJH_PUSH_PRE_OPERATION_PUSH` 推送下一轮按钮可用状态：

```json
[
  {"operation":10,"data":{"score":0,"isEnable":true}},
  {"operation":2,"data":{"score":0,"isEnable":false}}
]
```

本次日志中观察到的操作值：

| operation | 样本表现 | 说明 |
| ---: | --- | --- |
| 1 | 每人投入 10 | 底注 |
| 2 | 当前下注为 0 或结束行动 | 弃牌/结束类动作候选 |
| 3 | 下注从 20 增加到 40 | 加注/跟注类动作 |
| 7 | 下注保持或增加 | 普通下注类动作 |
| 8 | 下注后触发比牌结果 | 比牌类动作候选 |
| 10 | 下一轮可用状态变化 | 弃牌/结束类动作候选 |

具体中文名称应以客户端炸金花操作枚举为准，解析器应保留原始数字。

### 5.4 比牌

`3754 ZJH_PUSH_BIPAI_RESULT_MSG` 示例：

```json
{
  "uid": "<uid>",
  "target": "<targetUid>",
  "winner": "<winnerUid>",
  "isLast": false
}
```

该消息表示主动比牌玩家、目标玩家和胜者。`isLast=false` 表示本次比牌不是牌局最后一个比较事件；最终结果仍以 `3732 ZJH_INNING_RESULT_PUSH` 为准。

### 5.5 亮牌和结算

普通场配置 `forceShowCard=true`，结算前通过 `3741 ZJH_ACTION_SHOWCARD_PUSH` 展示三张牌：

```json
{
  "uid": "<uid>",
  "cardTypeInfo": {
    "pokerEnumList": ["HEART_4", "CLUB_7", "HEART_A"],
    "handCardList": [29,19,26],
    "cardTypeId": 1
  },
  "holeCardList": [29,19,26]
}
```

`3732 ZJH_INNING_RESULT_PUSH` 是玩家数组：

```json
{
  "xiaZhuData": 40,
  "banker": false,
  "cardTypeId": 0,
  "playerStatus": 0,
  "secondCardTypeId": 0,
  "insuranceBet": 0,
  "showCards": [10,46,16],
  "insuranceProfit": 0,
  "winInsurance": 0,
  "isWin": true,
  "raiseMultiple": 0,
  "multipleAnte": 0,
  "totalScore": 0,
  "finallyScore": 0,
  "uid": "<uid>",
  "score": 57,
  "point": 357,

```

炸金花结算与德州结算字段不同：

- `handPais` 是三张牌，不是德州五张组合牌。
- `raiseMultiple`、`multipleAnte` 表示加注倍数和倍数底注。
- `totalScore`、`finallyScore` 是炸金花结算专用字段。
- `playerStatus`、`secondCardTypeId` 表示玩家状态和次级牌型。
- 本房间关闭保险和暴击，因此保险字段保持 0。

## 7. 普通炸金花流程总结

```text
op=45 获取房间
  -> ROOM_LOGIN
  -> SEND_JOIN_ROOM(roomType=25)
  -> ROOM_TYPE_RESULT(ctjh)
  -> LOGIN_ROOM / ROOM_INFO
  -> BET_FRONT（每人支付 ante）
  -> ZJH_DEAL_DI_PUSH（发三张底牌）
  -> ZJH_ZHUANG_PUSH
  -> ZJH_PUSH_ROUND_INFO
  -> ZJH_OPERATION_PLAYER_PUSH
  -> ZJH_PUSH_PRE_OPERATION_PUSH
  -> ZJH_SEND_ACTION / ZJH_ACTION_BET_PUSH
  -> 比牌（可选）
  -> ZJH_ACTION_SHOWCARD_PUSH
  -> ZJH_INNING_RESULT_PUSH
```

## 8. 与德州普通场的差异

| 项目 | 德州普通场 | 炸金花普通场 |
| --- | --- | --- |
| `gameType` | `19` | `25` |
| `roomType` | `19` | `25` |
| 配置对象 | `dzpkParams` | `ctjhParams` |
| 牌局状态 | 翻牌/转牌/河牌 | 轮数和比牌 |
| 手牌 | 两张底牌，最终五张组合 | 三张牌 |
| 核心下注消息 | `DZPK_*` | `ZJH_*` |
| 发牌消息 | `DZPK_DEAL_*` | `ZJH_DEAL_DI_PUSH` |
| 结算消息 | `DZPK_INNING_RESULT_PUSH` | `ZJH_INNING_RESULT_PUSH` |
| 比牌 | 通常不单独比牌 | `ZJH_PUSH_BIPAI_RESULT_MSG` |
| 保险 | 可配置 | 本房间关闭 |
| 暴击 | 可配置 | 本房间关闭 |

## 9. 实现建议

1. 使用 `gameType=25`、`roomType=25`、`roomTypeName=ctjh` 识别炸金花普通场。
2. 按 `ctjhParams` 解析规则，不要复用德州 `dzpkParams` 字段。
3. 以 `3740 ZJH_ACTION_BET_PUSH` 作为下注结果确认，以 `3732` 作为最终结算确认。
4. `3754` 比牌消息只描述一次比牌关系，最终输赢仍由 `3732` 决定。
5. `3741` 展示的是三张牌，牌型解析使用 `cardTypeInfo.pokerEnumList` 和 `cardTypeId`。
6. `3780` 是前置操作列表，客户端应根据 `isEnable` 控制按钮，而不是硬编码可用操作。
7. 处理补分和离座时保留用户积分、座位状态和观战列表。
8. 生产日志不要输出 token、openId、设备 ID、IP 编码值和完整玩家资料。

## 10. 结论

本次日志确认的是传统炸金花普通场：

```text
gameType=25
roomType=25
roomTypeName=ctjh
gameRoomConfigId=2501
playMode=3
ante=10
carryMin=100
maxRounds=8
forceShowCard=true
openInsurance=false

```

核心流程是：底注、发三张牌、轮次操作、下注/弃牌、可选比牌、亮牌和三张牌结算。该流程使用 `ZJH_*` 消息族，与德州扑克的 `DZPK_*` 消息族完全不同。
