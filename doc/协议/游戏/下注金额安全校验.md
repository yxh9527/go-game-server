## 通用约束

所有真正扣减的投注必须是正数、有限数值、合法积分精度，并在 JavaScript 安全整数范围内。负数、NaN、Infinity、小数积分、溢出数值、布尔、数组、对象、空字符串不能转换为有效下注；部分既有接口兼容正常十进制数字字符串。多区域、多张购票均检查请求合计，不能只看单笔金额。

过牌、弃牌、不抢庄、放弃保险等无扣款操作仍按原规则执行。全下与不足完整跟注的合法短筹码跟注，以服务端确认的剩余筹码为上限。

普通棋牌投注以当前桌上可用筹码为上限；筹码已由带入保留规则保证属于账户余额。百人、slots、赌场二十一点等钱包投注使用 availableBalance，即账户余额减去棋牌带入保留额度。生产最终由 data-center 原子校验当前余额和版本，不能只依赖客户端或旧会话快照。

## 各游戏入口

| 范围 | 检查内容 |
| --- | --- |
| 德州普通、暴击、不秀牌及比赛共享引擎 | 加注输入拒绝负数和超出可付范围的目标，不再将超额目标钳制成另一笔下注；FOLLOW 的金额字段沿用积分单位，加注目标沿用显示单位乘 100；实际支付只扣尚欠金额。未知动作不能推动回合。 |
| 普通炸金花 | 跟注、加注、比牌、全下使用服务端合法选项金额，检查当前筹码、合法输入及底池累计范围。 |
| 棋牌牛牛 | 倍率必须在合法选项内，计算出的投注基数必须为正安全整数且不超过当前筹码；最终赔付继续受实际筹码责任上限限制。 |
| 三公暗一 | 1—10 倍整数以及底注乘倍率形成的实际下注，检查当前筹码与底池累计范围。 |
| 常规、赌场二十一点 | 初次下注、追加、分牌、加倍、保险共用实际可付金额检查；赌场可用金额扣除其他棋牌带入保留。放弃保险允许零扣款。 |
| 百人德州、炸金花、牛牛、二十一点、麻将 | 共用 BairenGame 金额校验，检查每区、累计、合计及钱包可用额；按玩法实际资金责任倍率检查扣款额。 |
| 百人百家乐、龙虎斗 | 共用 HundredGame/CardShoeGame，检查各区域、请求合计、单区累计及可用钱包余额；明牌价格按既有本局报价。 |
| 奔驰宝马、森林舞会、飞禽走兽、麻将转了、趣味捕鱼 | 复用公共百人校验；正反区域的合法赔率、最低金额和有效阶段继续校验。 |
| 刮刮乐两款及多台 | 面额必须为正安全整数且属于合法面额；单张、整本和批量购票先检查请求合计可付；已购 SPECIFIED 揭晓不再校验客户端自报面额或重复扣票款。 |
| 麻将三种玩法 | 不接受客户端自报扣款金额；服务端转账金额与预算必须为合法非负整数，按实际筹码限制责任。 |
| 十三水四鬼、八鬼 | 不接受客户端自报下注金额；按服务端牌型、底注和开局筹码计算，验证负分受开局筹码上限限制且资金守恒。 |
| 上庄申请与调整 | 原有金额和次数枚举检查保留，余额比较使用扣除棋牌带入后的可用额。 |

## 验证

test/game-server/wager-security.test.js 对当前 21 个注册游戏实现逐项检查，对百人各模式运行非法金额、合计超额、保留资金不可用以及合法对照下注。目录覆盖断言确保新增游戏必须补充相应安全测试。

gogames/data-center/dao/gogame_cash_amount_test.go 验证负扣款、负带入、负加款、超过余额、超过安全范围以及非整数 RPC 类型均被拒绝，失败不改变余额或带入。复核 lottery 的 Slots/Fruit/Ug5/Luck5 原有负数校验及现有扣款的可用余额约束。
