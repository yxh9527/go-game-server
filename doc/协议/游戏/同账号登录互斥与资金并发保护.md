# 同账号登录互斥与资金并发保护

影响 game-server 与 shared RPC；本地钱包模拟仍位于 cache。服务进程和 WebSocket 监听器不重启。

## 登录互斥

- 使用可信登录资料中的 agentId 与 userId 确定账户。1105 鉴权和余额查询成功后，新登录撤销旧连接权限，发送原版已有的 1203 USER_LOGIN_KICKOUT，再完成旧连接离房及必要带出。失败的登录不驱逐正常玩家。
- 登录提交按账户排队，较早请求的鉴权晚返回时不能替换已经成功的较新登录。关闭中的连接不再接受业务请求，迟到的鉴权不能重新绑定它；同一已认证连接重复发送 1105 不得重置身份、筹码或房间。
- 原版 `static/client/2.0.1279/assets/main/index.88f4e.js` 的 RoomSocketBase.sendLogin 不携带 socket 通道编号；RoomSocket-111 与 RoomSocket-222 使用相同的 userToken、deviceId 和宿主房号。已有正常百人宿主连接（19/25/24/31/26）、凭证/设备/房号一致时，允许一条百人副连接共存；不要求首次打开游戏时 openHundredGame=true，兼容进入普通场后再打开百人浮层。仅允许一对；设备、凭证或宿主房号变化会替换旧组。若这条副连接发送 2102 普通进房请求，则提升为新主连接并踢掉旧组，不能借副连接取得第二个普通桌身份。以上是对原版字段的兼容判定，不新增客户端字段。
- 关闭和退款任务、登录序号以及互斥状态保存在 runtime/session 上，业务热更新复用。旧连接的延迟 close 不能移除替换后的连接或重复带出。

## 资金并发

- 同账户连接绑定共享余额。扣款读取当前账户余额，本地 persist 不允许以旧连接快照覆盖余额；RPC 钱包的迟到余额查询也不能覆盖查询期间已经发生的资金变化。
- 有幂等标识的扣款、退款及派奖按账户、币种、操作类型和业务标识防重。常驻退款/派奖对象可作为操作标识；进行中的操作合并，成功结果保留，相同标识改变金额直接拒绝。没有请求序号的 6101/6125 相同下注仍属于独立合法动作，不按金额或短时间窗口猜测重复请求。
- 百人卡牌派奖在本局结果上保存单一执行任务，多个 tick、直接调用及热更新共用。已经加款而后续保存失败的玩家只重试保存，不再次加款。
- 撤注结果不确定时保留退款操作及原标识，暂停下注、阶段推进和派奖。后续 tick 使用同一标识重试，包括下注倒计时已经结束或模块已热更新的情况；确认退款后才移除实际下注。权威接口必须按同一标识返回原交易结果，不能再次退款。
- 金额必须为非负安全整数。禁止生产环境先修改会话余额、调用占位成功，再以 persistScore 覆盖账户；当前没有正式权威资金写入适配，生产扣款、退款和派奖明确抛出 WALLET_UNAVAILABLE，保留既有未完成业务状态，不伪造成功。

## 验证及边界

测试见 `test/game-server/session-control.test.js`、`wallet/wallet.test.js`、`core/hundred-card-payout.test.js` 和 `core/turntable.test.js`，并回归原有登录、离房、百人、刮刮乐及比赛测试。

登录互斥及本地防重范围为同一个常驻 game-server runtime；未新增跨进程登录协调服务。生产多实例或进程故障恢复必须由现有 data-center/权威资金通道提供持久化流水、交易幂等与账户并发控制，不能用本进程 Map 冒充跨实例事务。当前正式资金接口缺失时保持失败，不修改外部库表或猜造 RPC 协议。
