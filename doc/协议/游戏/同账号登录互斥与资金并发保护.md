# 同账号登录互斥与资金并发保护

本次配套客户端扩展 1105 可选字段 auxiliaryOnly=true，替代旧版只能靠宿主推断的限制：该连接必须附着到相同凭证/房号的主连接，不能新建主登录、推进登录栅栏或驱逐其他登录。RoomSocket2 等待主连接 1205 成功后发出请求，主连接失败/关闭会取消；独立百人连接不误标为辅助。服务端可信房型校验允许主连接已鉴权但首次进房尚未完成的窗口，并用 hasJoined 防止明确离房后再配对。协调版本 native-sockets-6 保留既有 Redis/内存归属，兼容旧客户端原有判定；本文后续“无新增客户端字段”是此前版本描述，以本补充为准。

2026-11-07 带入语义更新：新棋牌带入改为账户余额内的独占保留额度，带入/带出不再收退本金，输赢同步账户与保留值；有效带入排斥其他棋牌桌，百人/slots 只可使用总余额减保留值。五分钟租约、热更新旧账本兼容和生产原子资金接口边界见《棋牌带入保留额度与五分钟租约.md》。本文早先提及的现金带出退款仅适用于旧账本或确实已经扣款的其他业务，不能用于新带入记录重复加钱。

影响 game-server 与 shared RPC；本地钱包模拟仍位于 cache。服务进程和 WebSocket 监听器不重启。

## 登录互斥

- 使用可信登录资料中的 agentId 与 userId 确定账户。1105 鉴权和余额查询成功后，新登录撤销旧连接权限，发送原版已有的 1203 USER_LOGIN_KICKOUT，再完成旧连接离房及必要带出。失败的登录不驱逐正常玩家。
- 登录提交按账户排队，较早请求的鉴权晚返回时不能替换已经成功的较新登录。关闭中的连接不再接受业务请求，迟到的鉴权不能重新绑定它；同一已认证连接重复发送 1105 不得重置身份、筹码或房间。
- 原版 `static/client/2.0.1279/assets/main/index.88f4e.js` 的 RoomSocketBase.sendLogin 不携带 socket 通道编号；RoomSocket-111 与 RoomSocket-222 使用相同的 userToken、deviceId 和宿主房号。已有正常百人宿主连接（19/25/24/31/26）、凭证/设备/房号一致时，允许一条百人副连接共存；不要求首次打开游戏时 openHundredGame=true，兼容进入普通场后再打开百人浮层。仅允许一对；设备、凭证或宿主房号变化会替换旧组。若这条副连接发送 2102 普通进房请求，则提升为新主连接并踢掉旧组，不能借副连接取得第二个普通桌身份。以上是对原版字段的兼容判定，不新增客户端字段。
- 关闭和退款任务保存在 runtime/session 上，业务热更新复用。生产登录归属存 Redis：按代理/玩家维护 30 秒续租、全局登录代次、主/百人副连接组和原子替换；登录尝试序号先行申请，较早的慢鉴权不能覆盖较新的有效登录。每条游戏消息先取 Redis 同账号操作锁，再校验当前租约并完成业务操作；登录接管及旧连接清理复用同一把锁，接管不能插入已准入操作与资金提交之间。替换通过 Redis Pub/Sub 通知所有 game-server 实例踢出旧登录组，关闭旧 lease 时按 loginId/socketId 比较，迟到关闭不能释放新登录。锁租约定期续期，锁存储不可用或获取超时时操作失败关闭；Redis 不可用时生产登录和会话业务按失败关闭处理。
- 本地开发使用共享内存 backend 模拟多 runtime 竞争；生产 BusRpcProd 使用同一 Redis。测试覆盖两个独立 game-server runtime、并发登录、较新有效登录胜出、旧会话消息 fencing、延迟关闭和百人副连接兼容。服务进程/WebSocket listener 不重启。

### 2026-11-07 原版首次入房与公正码查询修正

- 原版首次进入普通德州就自动创建 RoomSocket-111/222，两个 1105 均可带 openHundredGame=false，且 1105 没有 gameId。副连接配对不能依赖 openHundredGame=true，也不能把其缺失 gameId 与主连接进入房间后得到的 gameId 比较；使用服务器已登记的宿主房间类型、相同 roomId 和凭证/设备摘要判定。配对仍只允许一条，副连接发普通 2102 时继续提升为新主连接并驱逐旧主，避免放宽成多个普通游戏连接共存。
- 仅关闭副连接时只移除自己的 socketId，保留主连接和租约原到期时间；副连接随后重建可再次加入。修正了最后一条副连接退出误删整组租约的情况。
- hall op=29 公正码详情使用现有 room-pool JSON 只读通道的 fair-code action，经 validateToken 和 getLoginData 得到可信 agentId 后查询原房间/局号授权。不得发送玩家登录 1105，不占登录组、不加载钱包、不进入房间，关闭查询连接不会导致原玩家 1203、站起或退款。生产数据源未接入仍返回 501。
- 常驻 RPC bus 上的协调器按 coordinationVersion 热替换，监听回调切换到当前业务模块；dev 对旧版私有内存 backend 仅迁移仍经旧 store 验证有效的本机主/副连接，不改桌位、钱包和牌局。生产 Redis 后端保持原记录。
- 验证：test/game-server/session-control.test.js 以实际 handler 复现日志中 openHundredGame=false 且无 gameId 的两次登录；test/hall/fair-code.test.js 保留真实主连接及租约后反复查询含错误凭证/其他代理的公正码，确认无踢人、第二份钱包或座位变化。node test/browser/check-native-login-fair.mjs 在常驻服务原版 Chrome 上验证两条自动登录、打开验码面板、连续三次 op=29 返回 200/52 张记录，1203 和脚本异常均为 0；报告 cache/native-login-fair.json。npm test 全量 923 项通过，未重启服务。

## 资金并发

- 同账户连接绑定共享余额。扣款读取当前账户余额，本地 persist 不允许以旧连接快照覆盖余额；RPC 钱包的迟到余额查询也不能覆盖查询期间已经发生的资金变化。
- 有幂等标识的扣款、退款及派奖按账户、币种、操作类型和业务标识防重。常驻退款/派奖对象可作为操作标识；进行中的操作合并，成功结果保留，相同标识改变金额直接拒绝。没有请求序号的 6101/6125 相同下注仍属于独立合法动作，不按金额或短时间窗口猜测重复请求。
- 百人卡牌派奖在本局结果上保存单一执行任务，多个 tick、直接调用及热更新共用。已经加款而后续保存失败的玩家只重试保存，不再次加款。
- 撤注结果不确定时保留退款操作及原标识，暂停下注、阶段推进和派奖。后续 tick 使用同一标识重试，包括下注倒计时已经结束或模块已热更新的情况；确认退款后才移除实际下注。权威接口必须按同一标识返回原交易结果，不能再次退款。
- 金额必须为非负安全整数。禁止生产环境先修改会话余额、调用占位成功，再以 persistScore 覆盖账户；当前没有正式权威资金写入适配，生产扣款、退款和派奖明确抛出 WALLET_UNAVAILABLE，保留既有未完成业务状态，不伪造成功。

## 验证及边界

测试见 `test/game-server/session-control.test.js`、`wallet/wallet.test.js`、`core/hundred-card-payout.test.js` 和 `core/turntable.test.js`，并回归原有登录、离房、百人、刮刮乐及比赛测试。

登录互斥现在由 Redis 租约协调跨实例，不依赖 data-center 新 RPC、数据库表或本进程 Map。房间状态仍保存在 game-server 本机；多实例部署还须让同一房间的分房请求与玩家 WebSocket 命中拥有该房间状态的实例（例如按分配节点粘性路由），会话互斥本身不会复制或迁移房间。资金记账仍遵循已有权威资金边界，不能用 Redis 登录租约替代正式资金流水、交易幂等或账户并发控制。

## 2026-11-09 普通座位游戏辅助连接补充
