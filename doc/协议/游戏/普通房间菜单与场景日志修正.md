# 普通房间菜单与场景日志修正

2026-11-09，影响 client-web 响应适配、game-server 登录控制和 shared/rpc 会话协调。原 static、常驻服务进程和资金逻辑不修改。

## 报告中的异常与诊断

- BaseBtnsLayer.onShowBtnsClick → init 在房间已经清理、getRoomInfo() 返回 null 时仍读取 disbandRoom。room-ui-response.js 在菜单点击入口验证当前房间；已退出或尚无房间时收起菜单并返回，有效房间仍执行原版初始化、切换菜单及按钮事件。
- 炸金花 inningBeginInfo 的 ---------- 是每局无条件 console.error，百人模块 BairenModule.init 也把正常的 {data,game} 初始化参数用 error 输出。这两处改为普通日志，不修改消息内容，不屏蔽实际异常。
- 1130 是原版 RoomSocket.send 主动禁用的 DATA_REPORT 按钮统计消息，不是本次服务端拒绝退出、也不是网络抛错。其禁用行为保持原样。
- Cocos 读取 undefined 的 [0] 栈发生在压缩资源反序列化 deserialize → parseImport，不是牌局接口字段读取。日志没有给出失败资源 URL，不能仅凭该栈指定某个牌局数据字段或改动 Cocos 引擎兜底吞错。

## 红中血流登录配对根因

按原版菜单退出炸金花、重进牛牛后再进红中血流，原版浏览器实际收到 2201/2206，随后收到 1203，hzxl 场景存在但 model.__roomInfo 仍为空。原因是普通座位游戏的辅助连接配对名单只含 19/24/25/26/31，漏掉 27/28/30/32。红中血流也会自动建立第二条连接，即使没有开启百人面板；第二条连接被误判为替换登录并撤销主连接。

本地 session-control、开发内存协调和生产 Redis Lua 同步覆盖 19/24/25/26/27/28/30/31/32。仍只允许同代理、同账号、同凭证/设备、同房间、已经入房的主连接配对一个辅助连接；不同设备/凭证仍撤销旧组，辅助连接若发送普通入房请求仍按既有逻辑提升为新主连接。没有扩大下注、钱包或跨房权限。

协调版本提升为 native-sockets-3，使用现有热更新接管路径复用常驻 backend、保留有效 loginId 和连接，避免源码更新后继续使用旧配对函数。生产继续使用同一 Redis 记录和租约，不重启服务。

## 退出时取消百人订阅补充

后续日志的“当前无可用房间服”来自 BairenMultyBetHelper.roomSocket：hundredDomain 仍存在，但两个连接的 socketUrl 已清理，原选择器无法匹配连接。旧开发补丁只处理“缺少 hundredDomain”，没有处理这一条路径。

client-web/src/hundred-cleanup-response.js 在原版取消订阅方法上适配：没有可用连接、连接已经关闭时完成本地清理；请求等待期间原连接关闭时也完成清理并释放监听。正常连接仍发送 6124，收到 6225 后才完成，不能用本地成功替代服务端确认。请求只绑定一次选择到的连接，并合并同一个界面对象在该连接上的重复清理。

取消确认回调绑定独立请求对象，避免 NotificationCenter 因界面节点已销毁而跳过回调；监听移除延后到当前分发结束，避免修改正在遍历的监听数组而跳过其他清理。原版 RoomSocket2 在普通房间会丢弃 6225，即使网络已收到确认仍无法结束等待；主脚本响应适配只额外放行该取消订阅确认，其他百人游戏推送仍沿用原过滤规则。

开发补丁同步识别上述两种明确的连接不可用错误；其他协议、编码及业务错误继续抛出。改动仅限客户端退出清理，不变更钱包、下注、手牌、余额或会话互斥，不修改原 static，不重启服务。

新增测试直接执行原版房间服选择器复现同一错误，并覆盖原版连接 2 的确认分发、销毁节点后的确认、关闭前/等待中关闭、正常确认、重复清理、同步确认、其他异常不被吞掉、HTTP 双路由与原文件不变。原生浏览器回归增加 --hundred-cleanup，在退出前等待真实取消确认，退出后再次调用百人退出与取消订阅链路。

百人模型已经释放后到达的 commandExit 也验证 model 是否存在，避免延迟的退出命令再读取空 model.exitRequest。回归区分仍在房间时的异常踢出和主动退出后的辅助连接撤销，不把已退出连接的关闭误报为在房玩家被替换。

最终全量 967 项通过（cache/hundred-cleanup-full-tests.log）。原版浏览器四轮“炸金花 → 牛牛 → 红中血流 → 红中血流”中，退出前正常连接的取消订阅均收到真实 6225 并返回 0；退出后原选择器均出现“当前无可用房间服”，再次执行延迟退出与取消订阅均返回 0，无未捕获异常，页面正常回大厅。日志 cache/hundred-cleanup-browser.log 包含 PASS_CLEANUP_BEFORE_EXIT、PASS_QUEUED_CLEANUP_AFTER_EXIT 和最终 SCRIPT_ERRORS []。常驻 4000 服务已核验返回新适配脚本及 no-store；已有浏览器页面需完整刷新 iframe 脚本，业务热更新不会替换页面已经执行的 JavaScript。
