## 4. 牌局开始和初始化

### 4.1 牌局快照（3851）

3851 是麻将桌面的初始或同步快照：

~~~json
{
  "bankerPos": 0,
  "players": [
    {
      "uid": 49380451,
      "handCards": [8, 26, 21, 2, 12, 10, 24, 17, 5, 2, 18, 26, 10],
      "pos": 2
    },
    {
      "uid": 55702050,
      "cardLen": 14,
      "pos": 0
    }
  ],
  "leftCardLen": 63
}
~~~

字段说明：

- bankerPos：庄家位置；
- players：玩家牌局概要；
- handCards：当前账号可见的手牌；
- cardLen：其他玩家的手牌数量；
- leftCardLen：牌墙剩余牌数。

旁观者通常看不到他人的具体 handCards，只能看到 cardLen；自己的可见数据会按客户端权限返回。

## 5. 摸牌、出牌和操作提示

### 5.1 3852 操作轮次

3852 代表当前操作玩家和倒计时：

~~~json
{
  "opUids": [49380451],
  "opTime": 10000,
  "cursorUid": 49380451
}
~~~

客户端应以 cursorUid 和 opUids 判断当前操作人，不应只按座位顺序推算。

### 5.2 3853 牌局增量事件

3853 是四人麻将最核心的增量消息之一。常见字段：

~~~json
{
  "uid": 49380451,
  "pos": 2,
  "type": 2,
  "card": 0,
  "leftCardLen": 57,
  "ting": false,
  "cardLen": 13,
  "groupCards": [],
  "extend": {
    "outIndex": 9
  }
}
~~~

日志中观察到的事件上下文：

| type | 观察到的上下文 | 协议含义 |
| ---: | --- | --- |
| 1 | opTime、cardLen=14，有时带 card | 轮到玩家操作/摸牌后状态 |
| 2 | 带 card、cardLen 减少、extend.outIndex | 出牌结果 |
| 3 | 带 outCardUid、groupCards.type=3 | 发生副露类操作，具体是吃/碰/杠需结合常量确认 |
| 6 | 带 dianGangUid、groupCards.type=6 | 与点杠/杠类操作相关 |
| 8 | 带 huRecord、score 或 curPointMap | 胡牌/结算事件 |
| 9 | 带 operatorList | 等待玩家选择可执行操作 |

type 数值是服务端枚举，不建议在没有客户端常量表时直接硬编码中文。

## 11. 协议实现注意事项

1. 3851 是全量牌局初始快照，3853 是高频增量事件，不能用一条增量消息覆盖全部桌面状态。
2. 旁观者只能看到自己有权限的 handCards；其他玩家通常只返回 cardLen，牌面要等 3854 或公开事件。
3. 3650 的 type 数值应保留原值，type=2 可由日志确认与出牌相关，但吃、碰、杠、胡的完整映射仍需前端常量表。
4. 3852 的 cursorUid 是操作轮次锚点，3868 的 operatorList 是可执行动作列表，两者需要合并使用。
5. leftCardLen、cardLen、groupCards、handCards 要分别保存，不能把副露牌混入手牌数量。
6. 3853 type=8 的 huRecord 是胡牌明细，3854 是最终玩家结果，3865/3866 是积分汇总，三者用途不同。
7. ROOM_INFO 中 disbandRoom=false 仅表示当前未解散，本日志没有完整房间解散流程。
8. roomType=30、roomType=hzxl 是识别四人麻将玩法的可靠条件，不能只看消息名中的麻将或通用 <game>undefined。

## 13. 结论

四人麻将的核心协议链路为：

~~~text
大厅 op=38 / op=45
 -> ROOM_LOGIN(1105/1205)
 -> SEND_JOIN_ROOM(2102)
 -> ROOM_TYPE_RESULT(2201)
 -> ROOM_INFO(2206)
 -> 3851 初始牌局快照
 -> 3653 / 3862 换三张
 -> 3860 / 3652 / 3863 定缺
 -> 3852 操作轮次
 -> 3650 / 3853 摸牌、出牌、副露、杠、胡
 -> 3854 最终牌局结果
 -> 3865 / 3866 分数汇总
 -> 9212 / 1249 桌内分和历史记录
 -> SEND_LEVEL_OUT / USER_LEVEL_ROOM
 -> HTTP op=54 / op=38
~~~

实现时应以 currentInning 管理牌局，以 uid 和 pos 管理玩家，以 3853 事件流驱动牌桌，以 3854、3865、3866 完成牌局结束和积分结算。
