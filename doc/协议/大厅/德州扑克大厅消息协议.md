# 德州扑克大厅消息协议

## 1. 协议概览

本日志记录的是德州扑克大厅切换、房间配置查询和 MQTT 心跳消息，不包含进入具体牌桌后的下注、发牌、结算等游戏消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | Holdem，德州扑克 |
| `gameType` | `19` |
| `subGameType` | `1` |
| 大厅接口 | `GET /internal/v1/do` |
| 房间配置操作 | `op=38` |
| 其他操作 | `op=63` |
| 房间数量 | 13 个 |
| 响应状态 | `msgCode=200` |

## 2. 大厅切换消息

```json
{
  "type": "changeType",
  "value": {
    "gameType": 19,
    "subGameType": 1
  }
}
```

客户端收到消息后执行：

```text
preloadByChangeType
preloadGameSceneRes
gameCfg: 19
gameName: Holdem
bundle: gameHoldem
```

## 3. 房间配置请求

请求接口：

```text
GET /internal/v1/do
```

请求参数：

```text
op=38
gameType=19
roomClassifications=
forceShowCard=1
```

其中 `param` 是 Base64 编码的查询参数，解码后为：

```text
gameType=19&roomClassifications=&forceShowCard=1&op=38
```

## 4. 房间配置响应

```json
{
  "msgCode": 200,
  "errMsg": null,
  "data": [
    {
      "gameType": 19,
      "roomClassifications": [],
      "roomInfoData": []
    }
  ]
}
```

## 6. 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `roomType` | number | 房间类型，德州扑克为 `19` |
| `gameRoomConfigId` | number | 房间配置唯一编号 |
| `totalPeople` | number | 当前房间人数 |
| `seatInfoList` | array/null | 座位信息，本次大厅配置返回 `null` |
| `winStreakList` | array/null | 连胜信息，本次大厅配置返回 `null` |
| `gameStatus` | number | 房间状态，大厅配置中为 `0` |
| `smallBlind` | number | 小盲金额 |
| `bigBlind` | number | 大盲金额 |
| `straddle` | boolean | 是否开启 Straddle |
| `carryMin` | number | 最低携带金额 |
| `playMode` | number | 玩法模式编号 |
| `roomClassification` | number | 房间分类编号 |
| `ante` | number | 前注金额 |
| `initialBet` | number | 初始下注金额 |
| `seeCardNo` | number | 看牌相关配置，本次为 `3` |
| `aofBet` | number/null | All-in or Fold 下注金额 |
| `roomIndex` | number | 房间列表索引 |
| `privateRoom` | boolean | 是否私人房间 |
| `roomId` | number | 房间实例编号，大厅配置中为 `0` |
| `forceShowCard` | boolean | 是否强制显示牌面 |

## 8. `key` 字段格式

普通模式：

```text
19/{smallBlind}/{bigBlind}/{straddle}/{playMode}/{initialBet}/{roomClassification}/{carryMin}/{aofBet}/{forceShowCard}
```

示例：

```text
19/100/200/false/0/200/2/5000/0/true
```

Straddle 模式示例：

```text
19/100/200/true/8/0/2/100/100/true
```

## 10. MQTT 心跳

本次日志没有 MQTT 业务 `PUBLISH` 消息，只有连接保活：

```json
{
  "protocol": "MQTT",
  "packet": "PINGREQ",
  "flags": 0,
  "remainingLength": 0
}
```

服务端响应：

```json
{
  "protocol": "MQTT",
  "packet": "PINGRESP",
  "flags": 0,
  "remainingLength": 0
}
```

## 11. 通信流程

1. 前端发送 `changeType`，切换到 `gameType=19`、`subGameType=1`。
2. Cocos 客户端预加载 `gameHoldem` 资源。
3. 大厅通过 HTTP `op=38` 获取德州扑克房间配置。
4. 服务端返回 13 个房间配置。
5. 前端根据 `roomInfoData` 刷新大厅房间列表。
6. 客户端通过 MQTT 心跳维持连接。
7. 用户进入具体牌桌后，才会建立对应的 RoomSocket，并使用独立的二进制游戏协议。
