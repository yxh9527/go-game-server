# 百家乐全部大厅消息协议

## 1. 协议概览

本文整理百家乐全部大厅日志中的大厅切换、牌桌配置查询、路单/牌靴状态、状态轮询和 MQTT 心跳消息。本次日志没有进入某一张具体牌桌，也没有采集到下注、发牌、开奖和结算请求；大厅响应中的 `extendInfo` 是各桌当前状态快照。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | บาคาร่า全部大厅 |
| 客户端配置名 | `Hundred` |
| 资源模块 | `bjl` |
| `gameType` | `1002` |
| `subGameType` | `99` |
| 房间配置接口 | `GET /internal/v1/do`，`op=38` |
| 状态轮询接口 | `GET /internal/v1/do`，`op=63` |
| 房间类型 | `58` |
| 房间配置数量 | 50 个（完整快照） |
| 响应状态 | HTTP `200`，业务 `msgCode=200` |
| MQTT 地址 | `wss://mq.wahaowu.top/mqtt` |

## 2. 大厅识别与切换

大厅收到的 Cocos 切换消息：

```json
{
  "type": "changeType",
  "value": {
    "gameType": 1002,
    "subGameType": 99
  }
}
```

客户端随后输出：

```text
preloadByChangeType requestGameType 1002
preloadGameSceneRes !gameCfg 58 Hundred bjl
```

因此可以确认：`gameType=1002`、`subGameType=99` 对应百家乐全部大厅，客户端配置名为 `Hundred`，资源模块为 `bjl`。本次日志中没有出现其他 `subGameType` 或按 `roomType` 筛选的请求。

## 3. 房间配置请求

请求接口：

```text
GET https://alobby.bucoa.top/internal/v1/do
```

`op=38` 请求的 `param` Base64 解码后为：

```text
gameType=1002&roomClassifications=&op=38
```

请求 URL 还携带 `userId`、`clubId` 和 token 等公共参数。完整认证 token 不写入本文。

日志中的 `op=38` 约每 5 秒刷新一次百家乐房间列表；响应中的 `totalPeople`、`extendInfo` 和 `vipTableData` 会随刷新变化。

## 5. 房间配置组织方式

完整快照返回 50 个 `roomType=58` 房间，按 `playMode` 分为 5 组，每组 10 桌：

| `playMode` | 房间数量 | 配置特点 |
| ---: | ---: | --- |
| 0 | 10 | 普通配置 ID，`roomIndex=1..10` |
| 1 | 10 | 普通配置 ID，`roomIndex=1..10` |
| 2 | 10 | 普通配置 ID，`roomIndex=1..10` |
| 3 | 10 | 普通配置 ID，`roomIndex=1..10` |
| 4 | 10 | 配置 ID 均为 `5895`，携带 `vipTableData` |

百人百家乐房间的 `key` 格式为：

```text
{roomType}/0/0/false/{playMode}/0/0/0/0/{roomIndex}
```

例如：

```text
58/0/0/false/2/0/0/0/0/6
```

## 7. `extendInfo` 路单与牌靴状态

`extendInfo` 是字符串形式的 JSON-like 数据，外层对象主要包含：

```json
{
  "showdownPokers": {
    "other": [20, 45, 14],
    "banker": [5, 5, 46]
  },
  "dealCardCount": 189,
  "ways": {
    "1": {
      "max": 104,
      "ways": [
        {
          "liPai": false,
          "winArea": [1, 9]
        }
      ]
    },
    "9": {
      "roundNum": 12,
      "type": 4
    }
  },
  "totalCardsNum": 416,
  "inning": 22790,
  "collectCardCount": 189,
  "remainCardsNum": 227,
  "showdownTypes": {
    "other": 7,
    "banker": 0
  },
  "goodRoadInfo": {
    "roundNum": 12,
    "type": 4
  }
}
```

日志中的 `ways` 数字键部分有未加引号的写法，例如 `1:{...}`，因此这是客户端使用的 JSON-like 字符串，不能直接保证能被标准 `JSON.parse` 解析。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `showdownPokers` | object | 路单统计中的牌值摘要，分 `other` 与 `banker` |
| `dealCardCount` | number | 当前牌靴已发牌数量 |
| `ways` | object | 路单展示数据；日志中 `ways[1].max=104` |
| `ways[1].ways` | array | 路单位置数组；元素含 `liPai`、`winArea` |
| `ways[1].ways[].liPai` | boolean | 该路单位置是否立起/标记 |
| `ways[1].ways[].winArea` | number[] | 该位置对应的胜负区域代码 |
| `ways[9].roundNum` | number | 路单统计局数 |
| `ways[9].type` | number | 路单类型代码 |
| `totalCardsNum` | number | 牌靴总牌数；日志为 `416` |
| `inning` | number | 当前局号/靴内局序快照 |
| `collectCardCount` | number | 已收集牌数量 |
| `remainCardsNum` | number | 剩余牌数量 |
| `showdownTypes` | object | 庄/闲或对应区域的统计数量 |
| `goodRoadInfo` | object | 当前好路信息，含 `roundNum`、`type` |

日志中不同房间的 `inning`、发牌数量、剩余牌数和 `ways` 内容不同，说明这些字段是动态牌桌状态，不是房间固定配置。

## 8. 状态轮询

客户端定时发送：

```text
op=63
param=op=63（Base64 编码：b3A9NjM=）
```

响应：

```json
{
  "msgCode": 200,
  "errMsg": null,
  "data": []
}
```

日志中 `op=63` 多次返回空数组，属于大厅附加状态/通知轮询，不是百家乐下注业务消息。

## 9. MQTT/WebSocket 消息

日志只捕获到 MQTT 协议层心跳：

连接地址：

```text
wss://mq.wahaowu.top/mqtt
```

客户端发送：

```json
{
  "protocol": "MQTT",
  "packet": "PINGREQ",
  "flags": 0,
  "remainingLength": 0
}
```

服务端响应：

```json
{
  "protocol": "MQTT",
  "packet": "PINGRESP",
  "flags": 0,
  "remainingLength": 0
}
```

本次日志没有捕获到可读的 `CONNECT`、`SUBSCRIBE`、`PUBLISH` 或 MQTT 业务 payload，因此无法确认下注、发牌、开奖、结算对应的 topic 和消息结构。`PINGREQ/PINGRESP` 仅表示连接保活。

## 10. 字段说明

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `gameType` | number | 大厅业务类型；本次为 `1002` |
| `subGameType` | number | 子类型；本次为 `99`，表示全部大厅 |
| `roomType` | number | 具体房间类型；本次均为 `58` |
| `gameRoomConfigId` | number | 房间配置 ID；VIP 模式的多个桌位可共用 `5895` |
| `roomIndex` | number | 桌位索引，本次为 `1..10` |
| `totalPeople` | number | 当前房间人数，动态变化 |
| `playMode` | number | 玩法模式代码，本次为 `0..4`；具体产品名称待客户端配置确认 |
| `key` | string | 房间配置组合键，最后一段对应 `roomIndex` |
| `hundredGame` | number | 百人玩法标识；本次为 `1` |
| `hundredMinBet` | number | 最低下注值；本次为 `100` |
| `hundredMaxBet` | number | 最大下注值；本次为 `100000000` |
| `extendInfo` | string | 路单、牌靴、开奖区域和好路状态快照 |
| `vipTableData` | object/null | VIP 桌背景、庄家等信息；普通模式为 `null` |
| `maintenanceInfoMsg` | string | 维护信息 JSON 字符串；本次无维护项目 |
| `privateRoomOpen` | boolean | 是否开放私人房；本次为 `false` |

## 11. 通信流程总结

1. 客户端请求 `op=38`，查询 `gameType=1002` 的百家乐大厅配置。
2. 大厅发送 `changeType(gameType=1002, subGameType=99)`。
3. 客户端预加载 `Hundred/bjl` 资源。
4. 服务端返回 50 个 `roomType=58` 房间配置，按 `playMode=0..4` 各 10 桌组织。
5. 大厅约每 5 秒刷新 `op=38`，更新人数和路单状态。
6. 大厅约每 10 秒请求 `op=63`，当前返回空数组。
7. MQTT 连接发送 `PINGREQ`，服务端返回 `PINGRESP`；当前日志没有业务 `PUBLISH` 消息。

- 本文覆盖大厅 HTTP、客户端切换消息、房间配置、路单状态和 MQTT 协议层心跳。
