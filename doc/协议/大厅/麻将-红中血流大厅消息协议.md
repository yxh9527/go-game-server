# 麻将-红中血流大厅消息协议

## 1. 协议概览

本日志记录的是红中血流麻将大厅的入口、初始化请求和房间配置查询。本次没有进入具体牌桌，因此没有采集到麻将发牌、出牌、碰杠胡或结算等 RoomSocket 游戏消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | 红中血流麻将 |
| `gameType` | `30` |
| `subGameType` | `30` |
| 大厅入口 | `/30/30/` |
| 房间类型 | `roomType: 30` |
| 房间配置接口 | `GET /internal/v1/do`，`op=38` |
| 房间配置数量 | 6 个 |
| 响应状态 | `msgCode=200` |
| 客户端模块 | `hzxl`（配置模块名） |

## 2. 页面入口

```text
https://lb.boyuee.top/30/30/?userToken=...&userId=...&clubId=...&openId=...&gameIp=...&v=2.0.1198&channel=3&plat=2&language=zh_cn&currency=CNY
```

关键路径参数：

| 路径段 | 值 | 含义 |
| --- | ---: | --- |
| 第 1 段 | `30` | 麻将游戏类型 |
| 第 2 段 | `30` | 红中血流子类型 |

客户端运行时输出的参数也验证了：

```json
{
  "gameType": "30",
  "subGameType": "30",
  "isWebHall": "1"
}
```

## 3. 大厅初始化请求

首屏启动阶段出现以下接口：

| 操作 | 解码后的参数 | 作用或结果 |
| --- | --- | --- |
| `op=54` | `op=54` | 查询钱包和门票信息，返回 `ticketNums=0`、`walletAmount=1973423` |
| `op=53` | 自动登录、用户、俱乐部、平台、语言和货币等参数 | 返回大厅、用户和登录配置 |
| `op=8165` | `uid=2223152&clubId=125566&isNew=true&op=8165` | 返回玩家及俱乐部资料 |
| `op=38` | `gameType=30&roomClassifications=&op=38` | 查询红中血流房间配置 |
| `op=62` | `op=62` | 返回空数组 |

这些请求属于大厅初始化。`op=54`、`op=62` 和 `op=63` 在页面运行期间还会重复请求，用于状态或大厅轮询，不属于麻将牌桌操作消息。

## 4. 房间配置请求

请求接口：

```text
GET /internal/v1/do
```

`op=38` 的 `param` Base64 解码后为：

```text
gameType=30&roomClassifications=&op=38
```

请求 URL 还携带用户 token、`userId=2223152` 和 `clubId=125566` 等公共参数。

## 5. 房间配置响应

```json
{
  "msgCode": 200,
  "errMsg": null,
  "data": [
    {
      "gameType": 30,
      "roomClassifications": [],
      "roomInfoData": []
    }
  ]
}
```

本次 `roomInfoData` 返回 6 个 `roomType=30` 房间配置。

## 7. 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `roomType` | number | 房间类型，红中血流为 `30` |
| `gameRoomConfigId` | number | 房间配置唯一编号 |
| `totalPeople` | number | 当前房间人数 |
| `seatInfoList` | array/null | 座位信息，本次为 `null` |
| `winStreakList` | array/null | 连胜信息，本次为 `null` |
| `gameStatus` | number | 房间状态，大厅配置中为 `0` |
| `carryMin` | number | 最低携带金额 |
| `playMode` | number | 玩法模式，本次为 `0` 或 `1` |
| `roomClassification` | number | 房间分类，本次为 `2` 或 `4` |
| `ante` | number | 底注或基础下注金额 |
| `initialBet` | number | 初始下注金额，本次为 `0` |
| `seeCardNo` | number | 看牌相关配置，本次为 `0` |
| `key` | string | 房间配置组合键 |
| `forceShowCard` | boolean | 是否强制显示牌面，本次为 `false` |
| `privateRoom` | boolean | 是否私人房间，本次为 `false` |
| `roomId` | number | 房间实例编号，列表配置中为 `0` |

本次 `dealerBgNo`、`lobbyThumbNo`、`gameStatusStartTime`、`gameStatusDuration`、`serverNow`、`roomIndex` 均为 `0`；`scoreMode`、`aofBet`、`waysJson`、`extendInfo`、`vipTableData`、`domain`、`serviceId`、`shield`、`seatInfoList`、`winStreakList` 均为 `null`；`hundredGame`、`hundredMaxBet`、`hundredMinBet` 为 `0`，`openHundredGame`、`straddle` 为 `false`。

## 9. `key` 字段格式

```text
30/{playMode}/{ante}/{roomClassification}/{carryMin}
```

示例：

```text
30/0/20/4/4000
30/0/50/2/10000
30/1/50/2/10000
```

| 位置 | 含义 |
| ---: | --- |
| 1 | 房间类型，固定为 `30` |
| 2 | `playMode` |
| 3 | `ante` 或底注 |
| 4 | `roomClassification` |
| 5 | `carryMin` |

## 10. 轮询请求

页面运行期间还出现以下重复请求：

```text
op=54  param=op=54
op=62  param=op=62
op=63  param=op=63
```

本次日志中这些请求均返回成功，`op=62` 和 `op=63` 的响应数据为空数组。日志同时出现 `gameHide` 和 `gameShow`，说明页面在切换或生命周期过程中执行了大厅隐藏/显示处理。

## 11. 通信流程与边界

1. 浏览器打开 `/30/30/`，进入红中血流麻将大厅。
2. 大厅请求钱包、登录配置和玩家资料。
3. 大厅通过 HTTP `op=38` 查询 `gameType=30` 的房间配置。
4. 服务端返回 6 档 `roomType=30` 房间配置。
5. 前端根据 `roomInfoData` 刷新大厅房间列表。
6. 页面运行期间通过 `op=54`、`op=62`、`op=63` 进行状态轮询。
7. 用户进入具体牌桌后，才会建立 RoomSocket；本次日志未覆盖麻将游戏阶段。
