# 用户中心战绩、资金与头像

以 static/hall 当前原版用户中心为准，hall/src/user-center.js 处理查询；业务模块热更新，禁止重启常驻服务。

- op=27/51：个人战绩，返回 infoList、totalSize、totalScore、ownScore。
- op=28：房间手牌，返回 infoList、totalInning、ownJoinInning、ownScore、blind。
- op=52：单局；op=30/31：比赛列表/详情；op=39/40：积分/门票明细。
- op=8165：用户资料，返回对象 playerId、name、imageUrl、clubId。原版通过 name/imageUrl 显示用户中心昵称和头像，不能返回默认空数组。资料经统一 gateway 鉴权和 getLoginData 获取；生产 gateway 保留 data-center LoginProfile.userIcon。头像使用现有 userInfoOf 映射及 /avator 静态资源，保留完整远程头像 URL。

上述个人查询必须验证 token/userToken 与 userId/uid；请求携带两个用户编号时必须一致，不能通过修改 uid 查询别人。响应设置 Cache-Control: no-store。日期使用北京时间，分页有上限。

德州和传统金花的手牌卡片分别读取顶层 ownCards/commonCards/winCards/winScore，以及 ownCards/winCards/winScore；只返回 firstGameList 会显示空白。德州底牌两张、金花三张，牌值 0 有效；只展示实际发出的公共牌。firstGameList 用于详细回顾，德州的发底牌阶段为 operateList.gameState=3，翻牌/转牌/河牌为 5/7/9。下注动作不得夹带原始完整底牌；本人取已结算的本人底牌，对手和获胜方仍按 showCards 的逐张公开权限显示。

dev 只读取实际结算产生的内存记录和已有房间回顾，不造战绩、余额或历史时间。旧版用户中心记录如缺少牌面字段，可从同代理、同玩家、同房、同局的真实回顾补读，保留原记录余额与结算时间。既没有真实历史时间、也没有对应结算记录时不能给旧回顾补造时间。prod 通过 data-center 读写，不把内存回顾冒充生产历史；此次未新增资金流水或重启对账机制。
