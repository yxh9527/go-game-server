# 刮刮乐全部大厅消息协议

## 1. 协议概览

本文整理刮刮乐全部大厅日志中的大厅切换、房间配置查询、状态轮询和 MQTT 心跳消息。本次日志没有进入具体房间，因此没有采集到刮奖、开奖、结算或牌桌业务消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | 刮刮乐 |
| gameType | 1004 |
| subGameType | 0 |
| 房间配置接口 | GET /internal/v1/do，op=38 |
| 状态轮询接口 | GET /internal/v1/do，op=63 |
| 房间类型 | 61、63 |
| 房间配置数量 | 2 个 |
| 响应状态 | HTTP 200，业务 msgCode=200 |
| MQTT 地址 | wss://mq.wahaowu.top/mqtt |

## 2. 大厅识别与切换

客户端收到的大厅切换消息：

~~~json
{
  "type": "changeType",
  "value": {
    "gameType": 1004,
    "subGameType": 0
  }
}
~~~

客户端随后输出：

~~~text
preloadByChangeType requestGameType 1004
~~~

本次日志没有输出具体的 Cocos 游戏配置名或资源包名，因此只能确认业务类型为 1004 和子类型 0，不能从该日志确认客户端资源模块名称。

## 3. 房间配置请求

请求接口：

~~~text
GET https://alobby.bucoa.top/internal/v1/do
~~~

op=38 请求中的 param Base64 解码后为：

~~~text
gameType=1004&roomClassifications=&op=38
~~~

请求 URL 还携带 userId、clubId 和 token 等公共参数。完整认证 token 不写入本文。

日志中 op=38 约每 5 秒重复请求，用于刷新房间人数和大厅状态。

## 6. 字段说明

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| gameType | number | 大厅业务类型，本次为 1004 |
| subGameType | number | 子类型，本次为 0 |
| roomType | number | 房间类别，本次为 61 或 63 |
| gameRoomConfigId | number | 房间配置唯一 ID |
| totalPeople | number | 当前大厅人数，随刷新变化 |
| playMode | number | 玩法模式代码，本次为 0 |
| carryMin | number | 最低携带值，本次为 100000000 |
| hundredGame | number | 百人玩法标识，本次为 1 |
| hundredMinBet | number | 最低下注值，本次为 100 |
| hundredMaxBet | number | 最高下注值，本次为 100000000 |
| roomClassification | number | 房间分类，本次为 0 |
| key | string | 房间配置组合键 |
| roomIndex | number | 房间索引，本次为 26 |
| extendInfo | null | 本次为空，没有附加玩法状态 |
| privateRoom | boolean | 是否私人房，本次为 false |
| roomId | number | 房间实例 ID，本次为 0 |

## 7. 状态轮询

客户端定时请求：

~~~text
op=63
param=op=63（Base64 编码：b3A9NjM=）
~~~

响应：

~~~json
{
  "msgCode": 200,
  "errMsg": null,
  "data": []
}
~~~

日志中 op=63 返回空数组，属于大厅附加状态/通知轮询，不是刮奖业务消息。

## 8. MQTT/WebSocket 消息

日志只捕获到 MQTT 协议层心跳。

客户端发送：

~~~json
{
  "protocol": "MQTT",
  "packet": "PINGREQ",
  "flags": 0,
  "remainingLength": 0
}
~~~

服务端响应：

~~~json
{
  "protocol": "MQTT",
  "packet": "PINGRESP",
  "flags": 0,
  "remainingLength": 0
}
~~~

连接地址：

~~~text
wss://mq.wahaowu.top/mqtt
~~~

本次日志没有捕获 CONNECT、SUBSCRIBE、PUBLISH 或业务 payload，因此无法确认刮奖、开奖和结算对应的 MQTT topic 或消息结构。PINGREQ/PINGRESP 仅表示连接保活。

## 9. 通信流程总结

1. 客户端请求 op=38，查询 gameType=1004 的大厅房间配置。
2. 大厅发送 changeType(gameType=1004, subGameType=0)。
3. 服务端返回 roomType=61 和 roomType=63 两个房间配置。
4. 大厅约每 5 秒刷新 op=38，更新人数。
5. 大厅约每 10 秒请求 op=63，当前返回空数组。
6. MQTT 连接发送 PINGREQ，服务端返回 PINGRESP；当前日志没有业务 PUBLISH 消息。

## 10. 采集限制

- 本日志只包含大厅 HTTP、客户端切换消息和 MQTT 协议层心跳。
- roomType=61、63 的具体产品名称或玩法名称需要结合客户端 UI 或游戏资源进一步确认。
- extendInfo 为空，当前无法从大厅配置还原刮奖、开奖、结算等游戏流程。
- 认证 token 未写入文档。
