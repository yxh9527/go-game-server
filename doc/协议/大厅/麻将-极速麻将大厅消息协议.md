# 麻将-极速麻将大厅消息协议

## 1. 协议概览

本文整理极速麻将大厅日志中可以确认的游戏识别信息、房间配置请求和响应结构。本次日志只记录大厅房间列表，没有进入具体牌桌，因此没有采集到发牌、摸牌、出牌、吃碰杠胡或结算等牌桌消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | 极速麻将 |
| 客户端配置名 | `Jsmj` |
| 资源模块 | `gameJsmj` |
| `gameType` | `26` |
| `subGameType` | `26` |
| 房间类型 | `roomType: 26` |
| 房间配置接口 | `GET /internal/v1/do`，`op=38` |
| 房间配置数量 | 6 个 |
| 响应状态 | HTTP `200`，业务 `msgCode=200` |

## 2. 客户端识别

大厅收到的游戏切换消息为：

```json
{
  "type": "changeType",
  "value": {
    "gameType": 30,
    "subGameType": 26
  }
}
```

随后客户端执行：

```text
preloadByChangeType requestGameType 26
preloadGameSceneRes gameCfg 26 Jsmj gameJsmj
```

这说明 `subGameType=26` 对应极速麻将，客户端使用 `Jsmj` 配置和 `gameJsmj` 资源模块。房间配置接口请求中的业务 `gameType` 也是 `26`。

日志中的 token、用户 ID 和俱乐部 ID 属于运行时认证参数，本文不保存完整 token。

## 3. 房间配置请求

请求接口：

```text
GET https://alobby.bucoa.top/internal/v1/do
```

请求 URL 的关键参数：

```text
op=38
param=Z2FtZVR5cGU9MjYmcm9vbUNsYXNzaWZpY2F0aW9ucz0mb3A9Mzg=
```

`param` Base64 解码后为：

```text
gameType=26&roomClassifications=&op=38
```

因此，`op=38` 是按游戏类型查询大厅房间配置的接口，`roomClassifications=` 为空表示本次没有指定房间分类筛选。

## 6. 字段说明

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `msgCode` | number | 业务响应码；本次为 `200` |
| `data[].gameType` | number | 配置所属游戏类型；本次为 `26` |
| `roomClassifications` | array | 房间分类筛选或返回分类；本次为空数组 |
| `roomInfoData` | array | 房间配置列表 |
| `roomType` | number | 房间所属类型；本次均为 `26` |
| `gameRoomConfigId` | number | 房间配置唯一 ID |
| `totalPeople` | number | 当前人数统计 |
| `gameStatus` | number | 房间状态代码；本次为 `0`，枚举含义待确认 |
| `carryMin` | number | 最低携带值 |
| `playMode` | number | 玩法模式代码；本次为 `0` 或 `1` |
| `roomClassification` | number | 房间分类代码；本次为 `2` 或 `4` |
| `ante` | number | 房间底注 |
| `key` | string | 房间组合键，格式为 `{roomType}/{playMode}/{ante}/{roomClassification}/{carryMin}` |
| `maintenanceInfoMsg` | string | 维护信息 JSON 字符串；本次无维护项目 |
| `privateRoomOpen` | boolean | 是否开放私人房；本次为 `false` |
| `roomId` | number | 房间实例 ID；本次为 `0` |

## 7. 通信范围与限制

- 本日志确认了极速麻将的客户端标识：`subGameType=26`、`Jsmj`、`gameJsmj`。
- `op=38` 返回 6 个极速麻将大厅房间配置，业务响应成功。
- 日志没有牌桌连接或牌桌业务消息，因此不能据此整理具体麻将游戏流程。
- `playMode=0/1`、`gameStatus=0` 和房间分类 `2/4` 的枚举名称，需要结合客户端配置文件或进入牌桌后的日志进一步确认。
