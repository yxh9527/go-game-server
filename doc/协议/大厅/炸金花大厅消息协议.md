# 炸金花大厅消息协议

## 1. 协议概览

本日志记录的是炸金花大厅的类型切换、房间配置查询和大厅附加请求。本次没有进入具体牌桌，因此未采集到炸金花下注、看牌、比牌、结算等 RoomSocket 游戏消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | Dzjh，炸金花 |
| `gameType` | `21` |
| `subGameType` | `0` |
| 房间类型 | `roomType: 25` |
| 房间配置操作 | `op=38` |
| 附加操作 | `op=63` |
| 房间配置数量 | 11 个 |
| 响应状态 | `msgCode=200` |

## 2. 大厅切换消息

```json
{
  "type": "changeType",
  "value": {
    "gameType": 21,
    "subGameType": 0
  }
}
```

客户端收到消息后执行：

```text
preloadByChangeType
preloadGameSceneRes
requestGameType: 21
gameCfg: 21
gameName: Dzjh
bundle: gameDzjh
```

## 3. 房间配置请求

请求接口：

```text
GET /internal/v1/do
```

`param` Base64 解码后为：

```text
gameType=21&roomClassifications=&op=38
```

请求 URL 中还携带：

```text
userId=2223152
clubId=125566
```

## 4. 房间配置响应

```json
{
  "msgCode": 200,
  "errMsg": null,
  "data": [
    {
      "gameType": 21,
      "roomClassifications": [],
      "roomInfoData": []
    }
  ]
}
```

本次响应中的 `roomInfoData` 包含 11 个炸金花房间配置。

## 6. 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `roomType` | number | 房间类型，炸金花为 `25` |
| `gameRoomConfigId` | number | 房间配置唯一编号 |
| `totalPeople` | number | 当前房间人数 |
| `seatInfoList` | array/null | 座位信息，本次大厅配置返回 `null` |
| `winStreakList` | array/null | 连胜信息，本次大厅配置返回 `null` |
| `gameStatus` | number | 房间状态，大厅配置中为 `0` |
| `dealerBgNo` | number | 庄家背景编号，本次为 `0` |
| `lobbyThumbNo` | number | 大厅缩略图编号，本次为 `0` |
| `gameStatusStartTime` | number | 游戏状态开始时间，大厅配置中为 `0` |
| `gameStatusDuration` | number | 游戏状态持续时间，大厅配置中为 `0` |
| `serverNow` | number | 服务端当前时间，大厅配置中为 `0` |
| `smallBlind` | number | 小盲金额，炸金花房间中为 `0` |
| `bigBlind` | number | 大盲金额，炸金花房间中为 `0` |
| `straddle` | boolean | 是否开启 Straddle，本次为 `false` |
| `carryMin` | number | 最低携带金额 |
| `playMode` | number | 炸金花玩法模式编号 |
| `roomClassification` | number | 房间分类编号 |
| `ante` | number | 底注或前注金额 |
| `scoreMode` | number/null | 计分模式，本次为 `null` |
| `initialBet` | number | 初始下注金额，通常与 `ante` 相同 |
| `seeCardNo` | number | 看牌相关配置，本次为 `0` |
| `key` | string | 房间配置组合键 |
| `aofBet` | number/null | All-in or Fold 配置，本次为 `null` |
| `roomIndex` | number | 房间列表索引，本次为 `0` |
| `privateRoom` | boolean | 是否私人房间，本次为 `false` |
| `roomId` | number | 房间实例编号，大厅配置中为 `0` |
| `forceShowCard` | boolean | 是否强制显示牌面，本次为 `true` |

## 8. `key` 字段格式

```text
25/{playMode}/{ante}/{roomClassification}/{carryMin}
```

示例：

```text
25/2/100/2/1000
25/3/10/2/100
25/2/2000/4/50000
```

| 位置 | 含义 |
| ---: | --- |
| 1 | 房间类型，固定为 `25` |
| 2 | `playMode` |
| 3 | `ante` 或底注 |
| 4 | `roomClassification` |
| 5 | `carryMin` |

## 10. 通信流程

1. 前端发送 `changeType`，切换到 `gameType=21`、`subGameType=0`。
2. Cocos 客户端预加载 `gameDzjh` 资源。
3. 大厅通过 HTTP `op=38` 请求炸金花房间配置。
4. 服务端返回 11 个 `roomType=25` 房间配置。
5. 前端根据 `roomInfoData` 刷新炸金花大厅房间列表。
6. 客户端随后发送 `op=63` 请求，本次响应为空数组。
7. 用户进入具体牌桌后，才会建立 RoomSocket，并使用独立的二进制游戏协议。
