# 麻将-长沙麻将大厅消息协议

## 1. 协议概览

本文整理长沙麻将大厅日志中能够确认的入口、房间配置请求和响应。日志只包含大厅房间配置及 `op=63` 轮询，没有记录进入具体牌桌后的麻将操作消息。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | 长沙麻将（日志客户端配置名：`Csmj`，资源模块：`csmj`） |
| `gameType` | `28` |
| `subGameType` | `28` |
| 大厅入口 | `/30/28/`（父页面路径） |
| 房间类型 | `roomType: 28` |
| 房间配置接口 | `GET /internal/v1/do`，`op=38` |
| 房间配置数量 | 6 个 |
| 响应状态 | HTTP `200`，业务 `msgCode=200` |

## 2. 页面与客户端识别

日志中的父页面通知大厅切换到以下子游戏：

```json
{
  "type": "changeType",
  "value": {
    "gameType": 30,
    "subGameType": 28
  }
}
```

客户端随后输出 `requestGameType 28`，并按配置名 `Csmj`、资源模块 `csmj` 预加载游戏场景资源。因此，本次大厅配置请求使用 `gameType=28`；入口 URL 的父路径 `/30/28/` 中，第一段 `30` 是宿主大厅路由参数，不应与房间配置请求里的 `gameType=28` 混淆。

日志 URL 中包含用户 token 等认证信息，本文不复写完整值。

## 3. 大厅消息流程

| 顺序 | 操作 | 参数或内容 | 结果 |
| ---: | --- | --- | --- |
| 1 | `changeType` | `gameType=30`，`subGameType=28` | 通知大厅切换到长沙麻将 |
| 2 | 资源预加载 | `requestGameType=28`，`Csmj` / `csmj` | 预加载长沙麻将场景资源 |
| 3 | `op=38` | `gameType=28&roomClassifications=&op=38` | 返回 6 个房间配置 |
| 4 | `op=63` | `op=63` | HTTP `200`，返回 `data=[]`；从本段日志只能确认发生一次请求 |

`op=38` 请求地址为：

```text
GET https://alobby.bucoa.top/internal/v1/do
```

`param` 是 Base64 编码。解码后为：

```text
gameType=28&roomClassifications=&op=38
```

请求 URL 另带有 `userId`、`clubId` 和 token 等公共参数；认证值不属于业务消息结构，且不应写入协议文档。

## 6. 字段说明

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `msgCode` | number | 业务响应码；本次为 `200` |
| `data[].gameType` | number | 房间配置对应的游戏类型；本次为 `28` |
| `roomClassifications` | array | 请求或响应中的房间分类筛选信息；本次为空数组 |
| `roomInfoData` | array | 房间配置列表 |
| `roomType` | number | 房间所属游戏类型；本次均为 `28` |
| `gameRoomConfigId` | number | 房间配置唯一标识 |
| `totalPeople` | number | 当前房间人数统计 |
| `gameStatus` | number | 房间状态字段；本次为 `0`，枚举含义未由本日志证明 |
| `carryMin` | number | 房间最低携带值 |
| `playMode` | number | 玩法模式代码；本次出现 `2`、`4`，具体名称待确认 |
| `roomClassification` | number | 房间分类代码；本次均为 `2` |
| `ante` | number | 房间底注 |
| `key` | string | 房间配置组合键，格式为 `{roomType}/{playMode}/{ante}/{roomClassification}/{carryMin}` |
| `maintenanceInfoMsg` | string | 维护信息 JSON 字符串；本次 `itemList` 为空 |
| `privateRoomOpen` | boolean | 是否开放私人房；本次为 `false` |

## 7. 采集范围与限制

- 本日志证明了大厅切换到 `subGameType=28`、加载 `Csmj/csmj` 资源，以及 `op=38` 获取 6 个房间配置。
- `op=63` 返回空数组；日志未提供该操作更详细的业务语义。
- 本日志没有进入房间，也没有麻将桌内的 WebSocket/RoomSocket 消息，因此不能据此整理发牌、摸牌、出牌、吃碰杠胡或结算协议。
- `playMode` 数值的玩法名称、房间状态枚举等需要客户端配置或实际牌桌通信日志交叉验证。
