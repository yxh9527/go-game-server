## 1. 协议概览

本文整理龙虎斗全部大厅日志中的大厅切换、房间配置查询、龙虎路单状态、状态轮询和 MQTT 心跳消息。当前粘贴文件中的 HTTP 响应行被截断，无法可靠还原每次响应的完整房间数组，因此完整房间数量和全部配置 ID 不在本文中臆测。

| 项目 | 内容 |
| --- | --- |
| 游戏名称 | 龙虎斗 |
| 客户端配置名 | Hundred |
| 资源模块 | lhd |
| gameType | 1003 |
| subGameType | 99 表示全部大厅 |
| 房间类型 | 59 |
| 房间配置接口 | GET /internal/v1/do，op=38 |
| 状态轮询接口 | GET /internal/v1/do，op=63 |
| 响应状态 | HTTP 200，业务 msgCode=200 |
| MQTT 地址 | wss://mq.wahaowu.top/mqtt |

## 2. 大厅识别与切换

大厅收到的 Cocos 切换消息：

~~~json
{
  "type": "changeType",
  "value": {
    "gameType": 1003,
    "subGameType": 99
  }
}
~~~

客户端资源日志：

~~~text
preloadByChangeType requestGameType 1003
preloadGameSceneRes !gameCfg 59 Hundred lhd
~~~

日志还观察到以下子类型切换：

| subGameType | 请求筛选 | 日志确认的 playMode |
| ---: | --- | ---: |
| 99 | 不指定 playMode，查询全部大厅 | 全部类型 |
| 1 | playMode=1 | 1 |
| 3 | playMode=3 | 3 |
| 0 | playMode=0 | 0 |
| 4 | playMode=4 | 4 |

本次日志没有出现 subGameType=2，不能据此确认是否存在 playMode=2 房间。

## 3. 房间配置请求

请求接口：

~~~text
GET https://alobby.bucoa.top/internal/v1/do
~~~

全部大厅请求的 param Base64 解码后为：

~~~text
gameType=1003&roomClassifications=&op=38
~~~

按玩法筛选时出现：

~~~text
gameType=1003&roomClassifications=&playMode=1&op=38
gameType=1003&roomClassifications=&playMode=3&op=38
gameType=1003&roomClassifications=&playMode=0&op=38
gameType=1003&roomClassifications=&playMode=4&op=38
~~~

请求 URL 还携带 userId、clubId 和 token 等公共参数。完整认证 token 不写入本文。

## 6. extendInfo 龙虎路单结构

extendInfo 是字符串形式的 JSON-like 数据，日志中可以确认的结构如下：

~~~json
{
  "showdownPokers": {
    "dragon": [41],
    "tiger": [25]
  },
  "ways": {
    "1": {
      "max": 180,
      "ways": [
        {
          "result": 2,
          "winArea": [2, 13, 15]
        },
        {
          "result": 1,
          "winArea": [1, 12, 15]
        },
        {
          "result": 0,
          "winArea": [3, 14]
        }
      ]
    },
    "9": {
      "roundNum": 7,
      "type": 16
    }
  },
  "inning": 24740,
  "showdownTypes": {
    "dragon": 3,
    "tiger": 13
  },
  "goodRoadInfo": {
    "roundNum": 7,
    "type": 16
  }
}
~~~

日志中的 ways 数字键有未加引号的写法，例如 1:{...}，因此不能保证可直接通过标准 JSON.parse 解析。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| showdownPokers.dragon | number[] | 龙方牌值摘要 |
| showdownPokers.tiger | number[] | 虎方牌值摘要 |
| ways[1].max | number | 路单位置上限，日志为 180 |
| ways[1].ways | array | 路单历史位置数组 |
| ways[1].ways[].result | number | 结果代码，日志出现 0、1、2 |
| ways[1].ways[].winArea | number[] | 该局关联的胜负区域代码 |
| ways[9].roundNum | number | 路单统计局数 |
| ways[9].type | number | 路单类型代码 |
| inning | number | 当前局号/期号 |
| showdownTypes | object | 龙方、虎方统计值 |
| goodRoadInfo | object | 当前好路信息 |

extendInfo 随牌桌刷新变化，属于动态桌面状态，不是固定房间配置。

## 7. 状态轮询

客户端定时请求：

~~~text
op=63
param=op=63（Base64 编码：b3A9NjM=）
~~~

响应：

~~~json
{
  "msgCode": 200,
  "errMsg": null,
  "data": []
}
~~~

op=63 多次返回空数组，属于大厅附加状态/通知轮询，不是龙虎下注业务消息。

## 8. MQTT/WebSocket 消息

日志只捕获到 MQTT 协议层心跳。

发送：

~~~json
{
  "protocol": "MQTT",
  "packet": "PINGREQ",
  "flags": 0,
  "remainingLength": 0
}
~~~

接收：

~~~json
{
  "protocol": "MQTT",
  "packet": "PINGRESP",
  "flags": 0,
  "remainingLength": 0
}
~~~

连接地址为：

~~~text
wss://mq.wahaowu.top/mqtt
~~~

本次日志没有捕获到可读的 CONNECT、SUBSCRIBE、PUBLISH 或业务 payload，因此无法确认下注、发牌、开奖、结算对应的 MQTT topic 和消息结构。PINGREQ/PINGRESP 仅表示连接保活。

## 9. 通信流程总结

1. 客户端请求 op=38，查询 gameType=1003 的龙虎斗大厅。
2. 大厅发送 changeType(gameType=1003, subGameType=99)。
3. 客户端预加载 Hundred/lhd 资源。
4. 服务端返回 roomType=59 房间配置，并在 extendInfo 中携带龙虎路单状态。
5. 用户切换 tab 时，通过 playMode=0、1、3、4 查询对应房间集合。
6. 大厅约每 5 秒刷新 op=38，更新人数和路单状态。
7. 大厅约每 10 秒请求 op=63，当前返回空数组。
8. MQTT 连接发送 PINGREQ，服务端返回 PINGRESP；当前日志没有业务 PUBLISH 消息。

## 10. 采集限制

- 响应日志在当前粘贴文件中被截断，无法可靠统计全部桌位和完整配置 ID。
- playMode 的产品名称、result 和 winArea 的完整枚举，需要结合客户端配置或更完整响应确认。
- extendInfo 是大厅返回的路单状态快照，不等同于完整龙虎斗牌桌消息协议。
- 要整理下注、发牌、开奖和结算协议，需要进入具体房间并继续采集 MQTT PUBLISH 或牌桌 WebSocket 的对象日志。
- 认证 token 未写入文档，敏感用户字段不作为协议内容保存。
