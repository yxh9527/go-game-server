# 智能投注 HTTP 接口（2026-10-30）

## 原版客户端依据

客户端：static/client/2.0.1279/assets/main/index.88f4e.js，模块 smart_net、smart_data、smart_view0、smart_view1。

统一 GET /internal/v1/do（亦兼容 /api/internal/v1/do），op=71（0x47），bizParam 为 JSON 字符串，随其余业务参数一起放入 Base64 param。外层 roomType 与 bizParam.roomType 必须一致。

## 已确认的读请求

- 市场列表：bizType=0，bizParam={roomType,reqType:0}。客户端直接读取 data.overview.participantCount.toString()、data.overview.participantAmount，并遍历 data.marketList。金额为协议分值，展示时除以100。
- 我的投注：bizType=0，bizParam={roomType,reqType:1,betType}。客户端直接读取 data.myTasks。
- 好路详情同样使用 reqType=0，但额外带 goodRoadType，不能误当列表请求处理。
- 任务详情：reqType=1 且携带 taskId，不能误当我的投注列表处理。

没有智能任务时，市场必须返回：

~~~json
{"msgCode":200,"errMsg":null,"data":{"overview":{"participantCount":0,"participantAmount":0},"marketList":[]}}
~~~

我的投注返回：

~~~json
{"msgCode":200,"errMsg":null,"data":{"myTasks":[]}}
~~~

原先 op=71 落入通用 default，返回 data=[]。数组为真值，触发 setSmartList 后，原版 initBase 访问缺失的 overview 导致 participantCount 异常；不是发牌或结算异常。修复在 hall 服务端完成，不修改原版客户端。

## 当前实现边界

项目尚无智能投注任务执行器、市场数据源或已创建任务；这里仅实现正确的空市场、空个人列表及参数校验，不代表自动投注功能已完成，也不生成虚构参与人数或任务。

bizType=1 的 operateType=1/2/3 分别对应客户端购买、停止、删除任务，当前明确返回 msgCode=501，data=null，不扣款、不创建任务、不返回成功。不存在的任务详情返回404；未实现的好路详情返回501。原版详情回调未检查 msgCode，不能向客户端发布虚构市场条目或任务入口；后续接入必须同时实现详情及操作响应再开放。
