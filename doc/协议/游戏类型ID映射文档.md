# 游戏类型 ID 映射文档

## 1. 文档范围

本文汇总大厅客户端配置和现有抓包日志中出现的游戏类型 ID，便于根据大厅入口、房间进入消息和游戏消息定位具体玩法。

数据来源包括：

- `static/hall/_next/static/chunks/pages/_app-08ba50392f8a0af7.js` 中的大厅游戏目录配置；
- `doc/协议/游戏` 下各游戏的 HTTP、WebSocket 和 MQTT 分析文档；
- 已记录的房间进入参数、房间配置和消息体。

客户端版本或服务端配置变化后，应以最新抓包中的字段为准。

## 2. 字段含义

| 字段 | 含义 | 使用位置 |
|---|---|---|
| `gameType` | 顶层游戏业务类型或大厅分类 | 大厅目录、房间配置、部分 HTTP 请求 |
| `subGameType` | 大厅子分类或入口筛选值 | 大厅列表、进入游戏路由；不保证每个游戏协议都发送 |
| `roomType` | 实际房间协议类型 | 房间进入、房间配置、游戏 WebSocket/MQTT |
| `playMode` | 同一 `roomType` 下的具体玩法模式 | 百人游戏、百家乐、龙虎斗、部分麻将 |
| `gameRoomConfigId` | 具体房间/底分/规则配置 ID | `op=38` 房间配置和进入房间参数 |
| `requestGameType` | 捕鱼目录请求时使用的父类型 | 捕鱼大厅请求 |
| `requestSubGameType` | 捕鱼目录请求时使用的子类型 | 捕鱼大厅请求 |
| `forceShowCard` | 德州是否强制显示牌面 | 德州大厅入口筛选；`1` 秀牌，`0` 不秀牌 |

`gameType` 和 `roomType` 数值相同只是一部分游戏的情况，不能据此推断所有游戏。`gameId/subGameId` 不是当前日志中稳定出现的协议字段；本文以实际出现的 `gameType/subGameType` 为准。

### 麻将

麻将大厅父类型为 `gameType=30`，大厅配置中有以下子入口：

| 子入口名称 | 大厅筛选值 | 常见协议 `roomType` | 说明 |
|---|---:|---:|---|
| 红中血流 | 30 | 30 | 麻将父类下的红中血流玩法 |
| 长沙麻将 | 28 | 28 | 四人场、二人场由 `playMode` 和 `gameRoomConfigId` 区分 |
| 极速麻将 | 26 | 26 | 四人场、二人场由 `playMode` 和配置 ID 区分 |

已有日志中还出现 `roomType=csmj` 这种字符串玩法标识。判断长沙麻将时，应同时检查 `roomType`、字符串玩法标识、`playMode` 和 `gameRoomConfigId`。

## 4. 百人棋牌

百人棋牌父类型为 `gameType=1000`。大厅子类型和协议房间类型如下：

| 大厅子类型 | 子类名称 | 协议 `roomType` | `playMode`/规则 |
|---:|---|---:|---|
| 1 | 百人德州 | 50 | 暗五、暗二、暗三、暗四、全暗等模式通常使用 `playMode=1..5` |
| 2 | 百人金花 | 51 | 明一、明二、明三、明四、全暗等模式通常使用 `playMode=1..5` |
| 3 | 百人牛牛 | 52 | 看三张、看四张、看二张、看一张、全暗等模式通常使用 `playMode=1..5` |
| 4 | 百人21点 | 60 | 常见 `playMode=0` |
| 5 | 百人麻将 | 62 | 大厅配置常见 `playMode=0`；已记录的进入日志出现过 `playMode=1`，以实际房间消息为准 |

百人德州、百人金花、百人牛牛的模式编号是根据大厅和已分析日志归纳的常见编号。服务端若返回房间规则描述，应优先使用规则描述而不是只依赖数字。

## 8. 刮刮乐

刮刮乐父类型为 `gameType=1004`。大厅目录将其作为一个类型展示，实际协议房间通过 `roomType` 区分：

| 游戏 | `roomType` | 日志中常见 `gameRoomConfigId` |
|---|---:|---:|
| 麻将胡了 | 61 | 6101 |
| 赏金女王 | 63 | 6301 |

大厅子类型常见为 `subGameType=0`。具体游戏名称也可能在房间配置的 `gameCode`、资源名或 HTTP 返回字段中出现。

## 9. 捕鱼目录

捕鱼合集与百人街机中的趣味捕鱼是两套目录，不能只按名称合并。

| 目录/游戏 | `gameType` | 请求父类型 | `requestSubGameType` |
|---|---:|---:|---:|
| 捕鱼合集 | 200 | 200 | 0 |
| 经典捕鱼 | 201 | 200 | 201 |
| 传统捕鱼 | 202 | 200 | 202 |
| 创意捕鱼 | 203 | 200 | 203 |
| 新品捕鱼 | 204 | 200 | 204 |

捕鱼目录请求通常携带 `requestGameType=200`，具体子游戏通过 `requestSubGameType` 选择。它与百人街机的 `roomType=57` 不同。

## 11. 使用建议

1. 解析大厅列表时，先用 `gameType/subGameType` 判断入口，再读取房间列表中的 `roomType` 和 `gameRoomConfigId`。
2. 解析百人游戏、百家乐、龙虎斗时，必须把 `playMode` 作为玩法的一部分保存。
3. 解析进入房间消息时，以服务端返回的 `roomType`、`gameRoomConfigId` 和规则字段为最终依据；大厅筛选值只能作为候选映射。
4. 日志记录建议同时输出 `gameType`、`subGameType`、`roomType`、`playMode`、`gameRoomConfigId`，不要只输出一个“游戏 ID”。
5. 如果外部接口使用 `gameId/subGameId` 命名，应在适配层明确映射到本文字段，避免把 `subGameType` 直接当成 `roomType`。
