# 异步房间任务完成后对象身份复核

2026-11-18，Asia/Shanghai。继续检查异步准备／周期与房间回收之间的对象归属，修复旧任务可能删除新注册同号房间的问题。保留已有修改，不重启服务、不提交代码。

## 修改

原处理器等待 game.tick 成功后继续执行旧房间 afterRound，并对 table.retired 按 roomId／agentId／gameId 调用 removeTable。如果等待期间 registry 中同一身份已注册为另一个房间对象，旧回收会误删该新对象。

create-handler.js 在异步引擎完成后复核 registry 中仍是原 table 对象，再进行机器人资料同步及后续 afterRound；退休删除前也检查原对象。原智能任务分支在 smartBet.tick、游戏 tick 等待结束后做相同复核，删除前再检查。原房间已被移除／替换时，旧任务不执行这些下一步骤，不创建或删除新房间。

HundredGame.js 对异步 beforeTick 的后续周期也补复核：如果开始时原对象已注册，准备结束后只允许该对象仍注册时推进。准备期间标记 retired 或 closing 且没有原手牌，则不进入新周期；已经关闭但仍有原手牌时，保留原继续周期的能力，不中断已接受结算责任。对没有 registry 的独立调用方不凭空要求注册。

不会取消已经完成的引擎／资金步骤，不回滚真实已确认结果，也不重新判奖或扣派。复核控制的是等待后的后续动作，并非新增房间恢复或替换机制。原 expireRoom 最终移除本来已有对象检查，继续保留。
