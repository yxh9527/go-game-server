# 异步等待后原会话身份复核

2026-11-18，Asia/Shanghai。继续检查请求排队与异步房间操作，修复等待后原连接已经失效但消息继续执行的问题。保留所有已有修改，不重启服务、不提交代码。

## 问题与修复

原 processMessage 在初始认证检查后等待 refreshCarry、roomJoinTask 或 game.afterRound。等待期间连接可能被关闭，session.authenticated 变为 false，或 registry 将该连接换绑为另一会话；部分等待点只复核 superseded，因此旧请求还可能进入后续游戏处理或发送原业务响应。

game-server/src/create-handler.js 现在在消息处理开始时检查原 socket 的 closed 状态，防止排在资金队列里的旧消息（包括登录请求）在连接关闭后启动。取得认证 session 后，后续检查要求 registry 中仍为同一个 session 对象、authenticated 不为 false、未 superseded、原 socket 未 closed。

在带入查询、入房等待、入房 promote、等待原离桌／跨桌离开之后，以及上一局 afterRound 清理之后重新检查。LOGIN_ROOM 的等待结束同样复核，失效时不继续初始化场景。旧会话失效后不从 registry 偷换成新 session 执行旧消息。

这些检查停止尚未进入下一步骤的客户端动作，不取消已提交资金、不撤回已经完成的上一局清理，也不自动重新登录、重试下注、退款或派奖。原断线清理与结算继续沿用。原实例准入名额无论正常结束还是提前返回都释放。
