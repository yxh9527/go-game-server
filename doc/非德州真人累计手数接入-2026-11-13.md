## 行为

牛牛 24、炸金花 25、极速麻将 26、十三水 27、长沙麻将 28、红中血流 30、二十一点 31、三公 32 的真实已结算手，通过原 user-center 投递队列和统一 gateway 进入现有 gg_player_panel_hand。非德州仅保存统计所需的记录身份、代理、玩家、币种、玩法、房间、局号、原结束时间和输赢／有效下注，不复制手牌、参与者资料或动作详情。

真人头像资料中的 totalHands 按代理、目标玩家、币种和 roomType 查询成功保存的累计手数，不再固定返回 --，不使用近七日或当前页条数代替累计值。今日、本周及七日记录继续查询统一 go_gp_settlement 原 log，现有三分钟历史查询缓存不变。机器人仍使用房间资料及实际房间存续记录，不写入真人统计；比赛积分和百人／刮票不进入本统计。

非德州没有已确认的主动入池／翻前加注口径，相关比例继续 --。不把空动作列表当作已知零比例，不伪造统计。数据源失败或累计值格式异常明确失败，真实空计数 0 可以正常返回。

累计手数覆盖本功能启用后已成功保存的记录。此前未累计的非德州旧结算不会自动导入，不将这一数值宣称为包含全部历史的终身总数。报告保存失败由原队列保留并重试，源码应用不代表既有历史已经回填。

## 隔离和兼容

gg_player_panel_hand 新增 room_type，非空、默认 19，使既有德州行继续属于德州。新增 idx_panel_game_account 索引依次为 agent_id、player_id、currency、room_type、ended_at，保留原 idx_panel_account。

德州记录的原唯一键算法不变，省略 roomType 的旧报告仍按 19 处理；非德州在原记录身份中加入 roomType，防止不同玩法使用相同报告 ID 时互相覆盖。既有重复写入不增加手数，所有德州统计和 SQL 记录列表增加 room_type=19 过滤，避免掺入新增其他玩法。

固定内部 playerPanelRead 请求增加可选 roomType；省略时保持德州行为，非德州只返回累计计数，不返回其他 SQL 牌局详情。playerPanelRecords 显式拒绝非德州详情请求；其详情仍走统一注单，不改建第二份权威回放。

playerPanelWrite 返回数量必须与本批投递数量相符，Node 才确认整批已保存；不完整回执报错并由原队列重试，不新增资金幂等流水、恢复队列或 Redis 主数据。
