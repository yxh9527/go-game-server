## 本轮实现

| 清单项 | 本轮结果 |
| --- | --- |
| 比赛延迟报名展示 | 管理列表显示“延迟报名中”、截止盲级和倒计时，支持筛选，使用服务端时间偏差，每秒显示更新、每 5 秒获取管理数据 |
| 人工暂停／恢复 | 用户已确认：本局及动画结束后全场暂停；冻结盲注、延迟报名和复活窗口，拒绝新报名／复活，恢复后继续剩余时长。命令版本和意图保存在原比赛事务，可重试；旧命令不能覆盖新状态；资金端重复校验暂停状态 |
| 比赛删除／归档 | 用户已确认：无报名及资金记录的草稿可删；运行中不可直接删，需先取消／结束；有记录的比赛只归档并保留原记录。生产删除在同一行锁下再次检查运行文档、排期场次和绑定门票；归档不停止原退款或派奖重试 |
| 比赛配置界面 | 新增逐字段表单，含费用、人数、积分、盲注／奖励／门票选择、延迟报名和复活次数。保留高级 JSON；编辑只提交发生变化的字段，已锁定规则不可由表单修改 |
| 排期页面 | 日常／定时赛、运营时区、开赛时间和启用／停用；停用仅影响后续生成，不撤销已生成场次 |
| 门票／比例／奖励页面 | 补齐列表与编辑界面；奖励的多名次、钱和门票组合仍通过高级 JSON 编辑。平台权限与代理比赛权限继续隔离 |
| 运营发券与门票种类停用 | 给指定代理的真人玩家发票；库存及持有记录同一 MySQL 事务提交，原持有表保存请求编号及序号，重试不重发。种类“删除”采用停用，不删除已发权益；已发票的面值、币种、绑定范围不能修改 |
| 退款／派奖视图 | 比赛列表显示待退款、待派奖数量，支持只看待处理；资金进度显示已完成、待处理和错误原因 |
| 正式公正码 | 按用户确认由本项目生成并持久化。先保存不可替换的加密牌序承诺，再发送该局消息；存储失败保留原承诺、退避重试并阻止本房推进。读取只放行本人或已公开牌的解密信息；新连接／房间不会收到旧房缓冲消息 |
| 正式德州逐手回放 | 实际行动顺序、公共牌与每位玩家有权查看的底牌进入独立回放索引；现金桌 19 和比赛桌 101 均支持。列表及详情先 Redis 缓存再经 data-center 查询；比赛积分不进入现金战绩或资金明细。历史上未保存的完整回放不会被编造补齐 |
| 赌场二十一点统一资金 | roomType=31/playMode=1 接入已接受投注和统一派奖，系统庄家及真人庄家均有专项测试。赌场座位只划入已接受投注；结算直接到钱包，座位不留下可重复带出的派奖。真人庄家采用原 carry 保留／释放及 BANKER_NET 原子混合结算 |
| 固定智能投注 | 按用户确认支持固定房间、区域、金额、1—1000 局、停止、止盈、止损。创建任务不扣钱，下注复用 HundredGame 和统一资金；每局一次，停止不撤销已经受理的投注。已停止且无待结算投注才可删除 |
| 原有 Go 前缀用例 | 将写死 `/fg` 的测试改为使用配置的前缀，不更改生产前缀；app/cfgparse 与 app/esindex 全部通过 |

公正码是本项目保存的承诺和选择性验牌数据；没有接入外部区块链、第三方时间戳或外部随机数服务。现有协议中的 blockchain 字段名继续兼容原版客户端。

固定任务入口为 hall 的 `/smart-bet`，用 `POST /internal/v1/smart-bet`。原版跟路面板的长庄、单跳等策略不属于本轮固定策略，未将固定任务伪装为这些策略。固定任务按当前房间连接执行，断开后不再开新注；已受理投注正常结算。进程变化后持久任务显示 interrupted，当前没有跨实例迁移执行或自动恢复机制；必须从任务所属实例操作未完成任务，这一边界仍需多实例验收。
