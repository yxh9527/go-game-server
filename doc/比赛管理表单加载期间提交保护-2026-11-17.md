# 比赛管理表单加载期间提交保护

本轮修复编辑另一场比赛时，旧输入框仍留在页面且保存可点击的问题。打开 B 等待模板请求期间，旧 A 的输入可能与 B 的 ID 一起提交；排期表单同样可能保留上一运营项目的 JSON。

## 修改

match/src/admin-forms.js 在开始加载比赛编辑器时立即清空旧输入框，设置加载状态和提示；模板请求返回、身份及编辑版本仍匹配、字段构建完成后才允许保存。排期及其他运营编辑器先清空旧 JSON，完整生成当前数据后才解除加载限制。

match/src/admin-page.js 增加统一的编辑器保存按钮状态计算，同时检查 data-loading 与原提交锁的 aria-busy。加载未完成时，即使程序主动触发表单 submit 也不会发起修改请求；元数据先返回不能解除仍在进行中的保存，旧保存先结束也不能解锁后来新开的未完成表单。

菜单凭证切换、迟到请求、表单提交锁及编辑版本检查继续保留。打开门票发放表单会结束其前一编辑器的加载状态，但若该表单仍有原保存任务，保存按钮仍受提交锁限制。没有新增服务端资金记录、请求重试或缓存。

元数据读取仍沿用既有按权限可用的处理：代理不能访问的公共模板列表可以为空，原记录引用的模板 ID 继续保留。本轮保护的是异步表单尚未完成时的提交，不改变后端模板和金额校验，也不把界面禁用按钮当作服务端授权。
