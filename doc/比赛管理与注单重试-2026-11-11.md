## 管理入口和盲注

match 服务 `/admin`（本地配置端口 11040）提供管理页面。页面输入管理凭证与代理 ID；令牌仅存当前页面内存，不写 URL 或浏览器存储。页面本身无业务数据，所有管理数据和操作均走既有鉴权 API。

比赛页提供状态筛选、新建、修改、开放报名、取消、终止及运行详情。配置编辑目前为 JSON 表单，尚未逐字段制作运营表单；没有新增比赛物理删除或独立暂停按钮。

盲注页提供列表、新建、修改和删除：

- 平台管理员权限，代理专属凭证无权管理公共模板。
- 名称 1—128 字符；数据必须为非空且不超过 512 项的合法计划。
- 复用实际比赛的 `normalizeTournamentLevels`：正常级别 type=1、中场休息 type=3；暂不支持 type=2。积分为非负安全整数，正常级别小盲大于零，大盲不少于小盲，需要计时的级别有正时长，开始和结束必须是正常级别。
- `DELETE /admin/v1/blinds/:id` 禁止删除任何比赛或排期引用的模板，包含历史及停用排期。
- 生产删除由 data-center 的同一 MySQL 事务锁定模板并检查引用；创建／修改比赛、排期及生成场次时同样锁定对应模板，避免并发发布悬空引用。未做真实 MySQL 并发验收。
- 元数据增改删广播 Redis `match`，大厅内存移除删除项。已冻结的比赛盲注计划不被模板编辑覆盖。

## 注单和资金流水写入

本次修改针对 lottery 统一接口、旧接口和 data-center 原有注单消费者：

- ES 批量 HTTP 错误和 HTTP 200 内的逐项失败、缺失响应均作为失败返回。
- 写入消费者仅在整批确认成功后清空批次。失败或写入函数 panic 保留本批，按原有 10 秒周期重试，暂停读取后续项。
- 注单沿用 `agentId|userId|roundID` 哈希文档 ID；资金流水使用 `agentId|userId|flowingWaterOn` 哈希文档 ID。重试已成功的部分覆盖同一文档，避免增加重复流水文档。
- 每批 ES 调用最多 10 秒。沿用原有有界通道，不新增无限溢出队列、幂等流水表、未结算记录或启动对账任务；日志记录失败、批次及排队数量，不输出整批玩家数据。

边界：仍是原有内存异步队列，进程退出会丢失未写入数据；ES 长时间不可用、队列装满时上游仍会受到背压。因此不能据此宣称实现跨进程故障零丢失，也未验证线上注单检索和统计。注单与资金流水写 ES；比赛运行事务写 MySQL，未将全部逐手牌谱改成 MySQL 存储。
