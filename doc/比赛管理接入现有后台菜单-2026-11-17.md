## 管理入口与权限

两个前端新增 `/match-management` 路由，菜单标题为“比赛管理”，内容为同源 `/gogame-match/admin` 页面。平台端沿原路由权限系统，仅 administrator／operation 角色显示该入口；代理端沿其既有登录与路由保护，比赛资源权限仍由 match 校验。

后台原登录凭证与 match 管理凭证目前是两套机制。本轮不将原 Go token 填入 match，也不做自动登录：管理员进入比赛页后，继续使用 match 已配置的管理凭证。平台管理员选择目标代理，代理凭证只能操作自身比赛，共享盲注／门票／奖励模板仍要求平台权限。

前端组件不读取父页面的 Cookie、Vuex、localStorage 或 sessionStorage，不通过 URL、postMessage 或父页面自动传递凭证。刷新／离开菜单后 iframe 会重新加载，凭证不在前端组件中持久保存。加载失败、返回登录页或代理错误页时显示错误，可重新加载或独立打开。

本次是菜单及同源嵌入接入，不是现有管理后台的单点登录。按钮、表单和比赛状态均复用已有页面，不另建第二份比赛数据与操作规则。

## 比赛页面路径修复

match/src/admin-page.js 的 API 根地址原来固定为 /admin/v1。通过 /gogame-match/admin 嵌入后，这会请求父后台根路径，无法到达 match。

现改为从当前页面 pathname 取得 API 前缀：直接访问 /admin 或 /admin/ 时仍请求 /admin/v1；通过 /gogame-match/admin 或其尾斜线地址访问时，请求 /gogame-match/admin/v1。凭证仍只放在 X-Admin-Token，查询串不参与 API 前缀生成。

## 开发代理与生产转发

两端 vue.config.js 均新增 ^/gogame-match 代理，默认目标 http://127.0.0.1:11040，可通过 VUE_APP_MATCH_PROXY 指定本机测试 match 地址，转发时移除 /gogame-match 前缀。平台端原 /global 代理保留；代理端原字符串代理改为对象，/api 继续转发到原后端地址。

菜单地址 /match-management 与转发前缀分开，防止前端页面导航本身被开发代理拦截。

生产 Vue 构建不会带上开发代理，需在两个后台域名的现有网关配置同源转发，例如 match 与网关同机时：

```nginx
location ^~ /gogame-match/ {
    proxy_pass http://127.0.0.1:11040/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 30s;
}
```

此规则应与现有 SPA 回退规则共同配置；match 在其他机器时使用实际内部地址。本轮只准备说明，没有修改或重载现有网关配置，也没有发布构建产物。
