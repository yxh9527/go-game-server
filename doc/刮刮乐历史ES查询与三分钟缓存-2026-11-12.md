## 当前实现

- 刮刮乐原注单仍通过已有终态快照写统一 ES 结算索引，不新增另一份历史落库链路。正式查询经 Node gateway.getScratchHistory → data-center scratchHistory → esindex.Settlement()（当前 go_gp_settlement）；Node 不直连 ES。其他已存在显示索引继续服务其原页面，本次历史查询不依赖它们。
- 原 6121／6221 协议不变，当前房间近 31 天最近 100 条，按旧到新返回。代理、玩家、币种来自已认证会话，玩法、房间来自可信桌，不采用客户端传入的其他身份或任意过滤字段。
- 结果缓存 key 为 scratch-history:v3: 加规范化参数 JSON 的 SHA-256，参数覆盖代理、玩家、币种、映射后的资金游戏编号、玩法、房号、gameRoomId、页码、大小、相对时间窗口及排序。原请求无明确时间范围，使用固定相对窗口作为键，避免当前毫秒变化导致每次生成新键；v3 同时隔离旧显示索引查询缓存。
- Redis 只写查询结果，固定 EX 180 秒；缓存读取不续期。空结果也仅保留三分钟；错误结果不写缓存。相同 key 的并发请求共用一个进行中的查询，完成后移除 Promise，不长期保留本地历史列表。
- 缓存不可用时仍可查询 ES；ES 不可用且无有效缓存时明确失败，不回退读取 lottery 的持久历史列表。新记录可见性服从 ES 投影和三分钟缓存窗口，不将兑奖成功宣称为 ES 查询立即可见。
- data-center 按原账户、代理、资金游戏编号、币种、complete=true 及 playedDate 时间范围查询统一金融注单，按 playedDate 与 hash 排序，解析原 log 校验原购票房间。Node 再核对身份、图案、倍率及净输赢，去重并转换原客户端格式；init 不作为详情后备，测试中故意放入矛盾 init 验证不会采用。
- 旧注单的房间字段在 log 字符串中，需要逐页检查；每页 100 条，最多检查现有 ES 10000 条结果窗口，整体最多 8 秒。足够当前房间记录或读完即返回；达到上限仍未读完会明确失败，不把被其他房间挤出的记录误报为空，也不静默返回不完整结果。

## Redis 历史移除

- 删除 Go ScratchHistory 查询及 ScratchAction 的 history operation。
- FinishScratch 仍原子维护待刮移除、原最终标记与累计奖额，重复兑奖仍不会重复派奖或累计，但不再写 history Hash、history-order ZSET 或历史 sequence。原 historyRecorded 标记作为兼容的已完成标记保留。
- 原 5 秒清理循环每轮 SCAN 一批旧 gogame:scratch:history* 键，严格只匹配 history:／history-order: 前缀，UNLINK 旧副本。每轮上下文最多 1 秒，保存游标继续扫描，不执行全库 KEYS 或大 Hash 同步 DEL。
- 清理排除待刮、票号归属、累计额、资金快照及新 scratch-history:v2 查询缓存。不在本轮更改它们的业务期限。
