# 真人百人庄家统一资金接入

日期：2026-11-11。本批接入现有支持真人普通庄／特殊庄的百家乐 roomType=58 与龙虎斗 59。业务继续在 Node，Go Lottery 增补混合结算原子操作；未重启常驻服务、提交代码、执行数据库迁移或操作真人资金。

## 上庄、下庄与账户责任

开启统一资金的房间，真人上庄资金改为原权威钱包的 carry 保留额度，不从余额先扣一笔再保存在内存。保留部分不能下注或用于其他桌的带入。一个玩家可同时申请普通庄、特殊庄，两个区域合并使用该玩家的一份保留凭证；原每区金额、上限、轮数及按比例分配规则保持。

上庄及调整仍在局间生效。增加金额走原 reserve，减少金额／下庄释放原保留值，不能把本金额外 credit 回钱包。断线、重连、取消和次局调整继续使用现有庄家常驻记录；未完成本局责任时不能提前释放。下庄完成后清除关联 collateral Map 条目，避免历任庄家引用累积。

每局封盘时，将真人庄家作为原 financial round 内的零金额 carry 绑定登记，areaId 记录 banker:本局责任上限。登记不改余额或下注筹码；当前真正上庄者不能再作为该局普通投注玩家。普通投注仍按原 Bet 实际扣除，机器人仍只使用房间模拟钱包，不参与真人资金 RPC。

## 完整牌局结算

原 PrePay 覆盖全部实际真人投注者及庄家。普通玩家预留其真实返还金额；庄家预留正净收益，负净输赢不伪造成正派奖。全部结果摘要在揭示最终牌面前确认，结算沿用同一预留、原下注摘要、结果摘要及 settlementId。

新增 Settlement.mode=BANKER_NET，只允许明确映射为 58/59 的资金游戏：

- 普通玩家：betAmount 为原已扣真实投注，payout 为本局总返还，profit=payout-betAmount，实际余额仅 credit payout。
- 真人庄家：必须有原零金额 carry 登记、同 token/tableKey、当前修订号及登记责任上限。netScore 为真实净输赢，统计 betAmount=abs(netScore)、payout=abs(netScore)+netScore、profit=netScore；实际余额和保留额度只变化 netScore，不能再扣一遍统计下注。
- 完整请求必须包含每个活动账户一次，拒绝遗漏、重复、混入其他账户、币种或带入凭证；真实庄家净额绝对值不得超过原登记责任上限。
- 有庄家登记时，普通 NORMAL 结算被拒绝，不能通过零下注零派奖抹去庄家责任。原整局 VOID_REFUND 路径保留其本来语义，不拿撤注代替庄家净额。

Go 使用既有 cashwallet 的所有账户预校验，在同一 Redis Lua 内更新所有普通玩家真实派彩、庄家真实余额及保留额度、原 finance round 终态、既有 settlement wallet marker，并一次性释放本局 reservation ledger／Q。最后一位凭证或责任额错误，前面账户也不写；其他牌局的预留不会被消费。

相同原请求重试返回原结果；改变内容拒绝。若 Redis 已提交但回执丢失，先读既有 marker，不能要求已经释放的 ledger 再次为 ACTIVE；其后按原请求确认，不重复转账或减 Q。Node 在权威操作和余额／保留额度全部复核前缓存成功消息，确认失败会沿用原账户暂停保护，不另造新编号重放。

资金／保留／本局终态及 Q 的原子边界在同一 Redis 操作。奖池 E/P 统计、异步 ES 记录与其他存储仍保持现有边界，不能把它们声称为一个跨存储事务。

## 发布开关

后端先应用并发布 BANKER_NET，再显式配置 Node：

```yaml
finance:
  provider: lottery
  room_types: [58, 59]
  banker_net: true
```

缺开关时，所选 Lottery 房间仍明确拒绝真人上庄；不会把旧后端接口当成新能力。只有配置中的 room_types 使用该资金提供方。新开关不修改原 dev 配置，原有现金托管责任不得在局中切换到 Lottery；已接纳责任在热更新后继续沿用原对象、编号、额度及模式。

Node 将 stake/carry 的变化交给原钱包，Go 只处理可信资金映射、金额／凭证及原子账务，不增加 Go 牌局调度或机器人逻辑。无新增表或 proto 字段，mode 是原字符串字段的新值。
