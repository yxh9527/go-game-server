# 比赛晚报名接入

日期：2026-11-11。本批继续普通报名的原客户端 op=42/type=2、原权威扣退款及比赛检查点；未重启服务、提交代码、执行数据库迁移或操作真人资金。

## 功能与规则

比赛开始后，只有配置了 delay_register_level 或 delay_register_time 的比赛才允许首次晚报名；都为 0 时仍关闭。等级限制包含配置的最后一档，超过该档关闭；时长按开赛后真实秒数计算（含休息），达到截止时刻关闭；同时设置时先到者生效。未配置额外客户端报名类型或重入功能。

match 先查询签名游戏服状态，再在现有比赛事务内检查代理、状态、等级/时长、人数上限及原报名记录。等级限制必须有可信当前级别；后端实际扣款前再次检查，缺少级别截止时间或快照已经过期时拒绝使用旧级别收费。

已有报名重复点击不另扣款。已经淘汰或完成比赛的玩家仍不允许重入。晚报名与原报名使用同一报名费、服务费、指定门票、币种及初始比赛积分；人数上限包含已参赛但已淘汰的人，不能靠淘汰腾出累计名额突破 5000 人上限。

## 支付和入桌顺序

1. 原比赛事务保存唯一报名尝试；付款通过既有 common.matchPayment，服务端依据持久计划核对真实费用及晚报名配置。
2. 扣款确认后记 registered/late，保存 paidAt，等待下一次全桌牌局检查点；不把新玩家塞入正在发牌或下注的一手。
3. match 将已付款的新玩家及原计划 key 随原 revision 检查点送给 game-server。游戏服校验全名单、初始积分、重复 UID 和容量后，统一在局间加入并按实际人数分桌。
4. 原桌已满时复用同一建桌方法扩桌；淘汰释放的位置重新分配。每位新玩家只增加原配置的初始比赛积分，不调用现金带入或增加钱包余额。
5. 分桌确认后才将新玩家记为 playing 并保存房号。丢回执时保留原检查点和原报名 key；重试同 revision 不重复增加积分，业务热更新保留这些状态。

准备支付后刚好截止，资金端在扣款前拒绝；若钱已确认但 Node 确认时已过期，则用原退款接口全退报名费、服务费并恢复原票据。比赛在未纳入该玩家的检查点上结束时，同样将尚未入桌的晚报名转入原退款流程，不把未入桌玩家加入最终奖励名单。

比赛崩溃仍按用户已确认的异常作废政策处理：不恢复牌桌、全额退款，晚报名记录也受同一流程保护。
