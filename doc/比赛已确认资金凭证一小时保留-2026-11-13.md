## 修复内容

原代码在比赛报名／复活收款、退款或派奖的 MySQL 事务确认后，给原 Redis marker 设置 7 天 TTL，重复请求也会重新设置，可能持续续留。

本轮改为：

- 只在原 MySQL 事务已确认回执后，检查同一 Redis marker 的原请求指纹及回执内容，二者均匹配才处理保留期限。
- 没有 TTL 或原 TTL 大于一小时的已确认 marker，缩短为最多 3600000 毫秒；已有更短 TTL 原样保留，重复请求不续期。
- Redis marker 已过期／删除时不重建；迟到请求沿原比赛事务从 MySQL 取已保存回执，不再调用钱款操作。
- 修改 TTL 的 Lua 再次比较原 marker 字节内容，避免读完后并发替换的凭证被误改。
- 尚未获 SQL 确认的 Redis 原凭证仍没有自动 TTL，不能因期限到了丢失可能已经扣款／派奖的唯一确认依据。
- 保留处理整体最多一秒。此时 SQL 已成功，若 Redis 不可用或回执不符，明确记录日志，不能把保留失败改成付款失败，诱发另一笔资金操作。
- 对已有 7 天 marker，后续相同请求确认 SQL 回执时会缩短；本轮没有后台扫描旧比赛支付，也不声称所有旧 marker 已立即删除。

原回执仍位于既有比赛 MySQL 运行事务中，不新增资金流水表、未结算记录、Redis 归档、补偿队列或启动资金对账。门票库存、原票恢复、报名费／服务费、复活和派奖金额均沿原逻辑。
