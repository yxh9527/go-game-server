## 本轮实现

### 后端资金安全修复

源码在隔离副本验证，并通过 `scripts/build-backend-integration.mjs` 生成到 `doc/待应用/线上后端对接`。当前 manifest 为原目录尚未应用的 6 个文件，包含以下内容：

- Lottery 退款/结算 marker Lua 在实际入账时同步推进 cash_revision，重复 marker 不再推进。先校验余额、修订号、安全整数范围、脏集合类型和 marker 内容，再写余额与 marker。
- 新增 dao/finance_bet.go，将扣款和既有 lottery_finance_rounds 快照在同一 Lua 中提交；未新增独立流水、启动重放或未结算存储。原 betId 重试读取原快照；改变金额、币种、玩家或区域拒绝。
- 原子扣款核对可信 agent/currency、当前余额和棋牌带入保留值，不能消费其他棋牌桌已保留的额度。快照类型错误、余额不足、过期修订号等在首次写入前失败。
- Bet 入口检查最终快照保存错误，不能继续忽略错误返回整体成功。余额入账和快照问题之外的统计/ES 跨存储一致性边界仍存在，不能声称全部存储为同一事务。
- gg_room_config 模型新增可空 finance_level，显式指定资金奖池等级。旧房间保持空值，不能猜测默认等级。

本轮尝试应用时，自动审批因 gpt-5.6-luna 不可用返回 404，命令未执行。上一轮原目录已应用的 26 个文件没有回退；本轮 6 个修复仍需单独应用。

### Node 百人业务调用

- 新增 game-server/src/wallet/round-finance.js：真实 roundId、betId 修订号、资金侧 betDigest、结果摘要、reservationId 和固定 settlementId 随牌局保存。金额通过安全整数/BigInt 转十进制字符串。
- RPC 超时先查询 GetRoundFinanceState，再最多一次使用原编号、原请求重试；查询或重试仍无法确认时暂停相关账户，不生成新编号绕过。此行为依赖先发布本轮原子 Bet 修复。
- 普通预留使用 PrePay 60 秒；仍有效但剩余不超过 40 秒时通过 RenewReservation 续到当前时间后 60 秒。禁止用重复 PrePay 当续期。
- 公共 HundredGame、bairen-engine、hundred-card-payout 覆盖十二种百人玩法：百家乐、龙虎斗、百人德州、金花、牛牛、21 点、麻将及五种街机。
- 所选玩法下注只走 Bet；全部有效账户结算只走 PrePay/Settlement，包括零返奖玩家。完整结果在对客户端公开前确认预留，结算复用已确认的结果摘要和预留编号。
- 支持资金协议允许的整账户撤注，继续使用 CancelBet；部分区域撤注暂时拒绝，不能拿自算退款替代协议未提供的部分退款。
- 成功消息由权威钱包缓存到 RPC 确认后再发送。cashApply 与 Lottery 禁止在同一业务动作内混写；没有完整结算的单独 payout 不得成功。
- 支持按 roomType 选择切换。普通座位桌继续使用现有现金带入链路，不能声称已经迁移到 Lottery。禁止把已有现金下注或庄家托管中的牌局中途切换；已启用房型也不能通过热更新直接改换资金提供方。
- 业务热更新复制钱包属性描述符，保留钱包对象和已接纳的资金局号，避免 getter 属性导致第二次热更新失败。

## 配置与应用顺序

1. 执行 `node scripts/apply-backend-integration.mjs D:/project/gogames` 只读核对；当前为 6 个待应用文件。
2. 在可写的本机终端执行 `node D:/project/gogame/scripts/apply-backend-integration.mjs D:/project/gogames --apply`。脚本核对摘要、备份并拒绝覆盖并发修改；不会重启或执行数据库迁移。
3. 后端编译测试并随正常发布启用；核对数据库实际字段、索引、gp_game 客户端映射和代理各等级奖池。
4. 将准备切换的 gg_room_config.finance_level 填为真实奖池等级，经 data-center listRooms 返回；缺失或 NULL 时拒绝所选玩法的新资金下注。
5. Node 使用实际 data_center 地址及内部存储凭证，并配置 Lottery 固定节点或明确的代理写入归属。不能把同一代理自动故障转移到另一个独立资金写实例。
6. 仅在无在局现金下注或庄家托管责任时，使用显式配置选择适配房型。以下示例只展示结构，地址和等级须使用部署实际值：

```yaml
finance:
  provider: lottery
  room_types: [53]
lottery:
  address: 127.0.0.1:10080
lottery_timeout_ms: 3000
```

该开关用于后续可控发布；本轮没有修改现有开发 YAML 或启动生产资金请求。
