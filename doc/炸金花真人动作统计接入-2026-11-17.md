## 统计口径

新增 shared/native-player-actions.js，从原已完成牌局的 detail.nativeHistory.events 读取炸金花动作。核对原房间、局号、玩家和动作类型，目标玩家原底注须存在且恰好一次，已记录动作的阶段与金额也须合法。缺失／截断／不支持的证据返回未知，不从结果补造操作。

| 原动作 | 主动入池 | 明确加注 |
| --- | --- | --- |
| 底注（ANTE=1） | 否 | 否 |
| 跟注（CALL=3） | 是 | 否 |
| 加注（RAISE=4） | 是 | 是 |
| 全押（ALL_IN=6） | 是 | 不推断为加注 |
| 比牌付费（COMPARE=8） | 是 | 否 |
| 看牌、弃牌、被比下去 | 否 | 否 |

这里的“加注率”只表示该手牌是否发生明确 RAISE 操作；全押不凭金额猜测其是否构成加注。每手最多计一次，动作来自原游戏正常接受的操作，不新增另一份下注或结算流程。

已有 joinPercent 对应主动入池手数／总手数，flipManualBetPercent 对应明确加注手数／总手数，tableJoinPercent 使用当前房间范围。所有已保存手牌都具有可信行为标记时才显示总体比率；夹有旧未知记录时继续 --，但当前房间若证据完整，可单独显示当前房间比率。空数据不造记录。

炸金花动作 ID 与德州不同，本轮不套德州翻前 3B／4B 或翻后 3B 算法，相关不适用字段继续 --。其他非德州玩法也不会误用德州动作码。

## Node 链路

shared/player-panel.js 在生成玩家统计 DTO 时，将原炸金花动作投影为 behaviorVersion=1、countersKnown、voluntary、raised 四个统计事实；不把牌面、完整事件、玩家钱包或完整对局详情复制到 MySQL。完整对局详情仍走原统一注单 go_gp_settlement.log。

开发环境只读取原已结算房间／用户中心内存记录中的真实动作，没有就保持未知。生产 game-server/src/core/player-panel.js 校验 data-center 返回的整数计数及关系，再计算显示比率；旧 data-center 未提供这些字段时继续 --，不会回退假数据。真人备注、机器人按房间随机稳定资料及历史展示规则未改变。
