# 已释放预留凭证清理

当前后端此前最新补丁核验为 0 待应用。本轮处理 lottery:reservation_ledger 中已释放记录的永久积累，并补齐清理后的迟到释放保护。未改下注、派彩、退款金额或统一注单 go_gp_settlement.log。

## 清理规则

- 只处理结构合法、状态 RELEASED、原释放时间已满 3600 秒的凭证；原字段中的 roundId 在 lottery_finance_rounds 中已不存在才允许删除。
- ACTIVE、未满一小时、未来／无效时间、无法解析的原记录，以及仍有原快照的记录保留。已经确认释放与尚未完成的责任不混删。
- 不新增 Redis 归档、索引集合或数据库表。沿用既有 5 秒循环，以进程内游标 HSCAN 原 Hash，COUNT 提示为 100，单轮最多删除 100 项，整体最多 1 秒。
- Redis Lua 在删除时再次比对原字段内容，并核对该局当前仍无快照；若另一实例已更改凭证或恢复原局快照，本轮不删。
- 删除只涉及原已释放凭证字段，不改变 agent_reserved_data、玩家余额、带入、结算 marker、票据或其他局。
- 重复释放只读取原 RELEASED 回执，不更新其原时间，不能通过重复请求让它永久续留。

这不是 Hash 每个字段的原生 TTL；后台分批扫描，Redis 故障或大量积压会延后物理删除。仍有原快照的凭证会等原快照移除后再清理，本轮不承诺所有 Redis 状态均在一小时后无条件消失。

## 迟到释放与旧版补建保护

原兼容路径允许“没有凭证时按传入参数补建并释放”。清理旧凭证后，如果仍无条件允许它，迟到的重复请求可能再次减去汇总占用，侵占其他在局预留。

本轮缺凭证的补建必须同一 Lua 内核对原 Redis 牌局快照：state=RESERVED、reservation.status=RESERVED、相同 reservationId、代理／奖池及原金额。没有原快照或任一身份不符时拒绝，不补建、不改奖池。额度调整所需的旧凭证补建同样沿此证据校验，不根据汇总占用或旧请求参数推断。

已有凭证的释放也核对它的原 roundId、代理／奖池和金额，防止不同身份误用同一凭证。正常首次释放及原请求重试保留原语义。

本轮没有新增资金幂等流水、未结算记录、启动资金对账或自动重结算。未确认支付、未兑奖票据及已有 7 天结算／购票 marker 的保留策略没有一并更改。
