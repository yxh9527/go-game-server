# RPC 业务适配与比赛存储门面可回收加载

2026-11-20，Asia/Shanghai。新增六个可回收模块，范围从 182 扩至 188：shared/rpc/adapters/rpcAdapter.js、tournaments.js，以及 implementations/prod 下的 commonRpcProd.js、gatewayRpcProd.js、lobbyRpcProd.js、dataCenterStore.js。

原 data-center、存储和 lottery 客户端缓存仍由三个常驻 transport 模块管理，不创建第二份网络客户端或缓存。业务更新沿用 refreshDataAccess，在原 runtime 的 commonService／gatewayService／lobbyService 上更新方法或门面；原 bus、会话、订阅、资金 owner 及已发出的请求不替换。

prodDeps.js 保存启动时注入的 Redis，是进程级依赖容器。本批将其明确列为常驻模块，去掉版本参数，避免业务工厂首次导入 BusRpcProd 时取得另一份 redis:null 容器。BusRpcProd 本身没有纳入可回收业务范围，也不通过 refreshDataAccess 重建。

## 验证

新增 test/shared/hot-rpc-access.test.js 四项，验证：

- 原 common／gateway／lobby／bus 对象身份和资金 owner 保持；替换真实源码副本后，原 common 对象能调用新版方法。
- 原等待中的资金调用只发起一次，替换期间不重放，原结果仍返回。
- 数据中心原 callback 事务等待期间替换门面，原回调只执行一次并完成，不创建第二次事务。
- transport 与 Redis 依赖容器去版本复用；释放的业务模块和存储闭包可回收。
