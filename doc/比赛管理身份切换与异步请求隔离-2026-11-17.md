# 比赛管理身份切换与异步请求隔离

本轮继续后台接入验证，修复管理页面切换代理／管理凭证后，旧列表和编辑数据可能被迟到请求重新写回的问题；同时处理管理项目切换时的列表竞态。没有新增比赛资金逻辑、SQL 表、Redis 键或自动重试流程。

## 修改

新增 match/src/admin-requests.js，作为实际管理页和隔离测试共用的请求状态实现，通过现有页面脚本嵌入。它在当前页面内记录管理身份版本，同一 URL 的新 GET 会取消旧 GET，切换身份也会取消原只读请求。收到响应及解析 JSON 后均核对身份版本，迟到旧响应不能更新新身份页面。

凭证及代理 ID 的 input／change 事件，以及自动刷新前的身份同步，会清空上一身份的比赛／盲注／运营列表、资金详情、表单和元数据，并关闭旧编辑器。不读写本地持久缓存，旧凭证不新增到 URL 或日志。

动态列表按钮保存创建时的身份版本。即使旧按钮被保留在 DOM 外，切换身份后点击，也不能用当前凭证提交旧记录操作。元数据、比赛编辑和排期编辑各有加载版本，较慢的旧加载不能在身份切换或关闭编辑后重新填入表单。

切换排期／门票／比例／奖励等管理项目时，新列表有独立版本检查，旧排期响应不能覆盖已选门票列表；打开门票发放时也使之前的异步编辑加载失效。

已发出的 POST／PUT／DELETE 不会因身份切换被当作“没执行”自动重发。它们始终使用提交时的原凭证和代理头，身份改变后结果只停止写入当前新页面。超时和服务错误不自动重试，资金和发票操作继续由原服务确认及防重机制负责。页面销毁取消只读请求并释放其索引，超时定时器在每次请求完成后清除。

这属于前端异步状态隔离；真实比赛权限仍由原 match 管理接口执行，不以隐藏页面或取消 GET 替代服务端授权。

## 测试

新增 test/match/admin-requests.test.js 六项回归：切换代理拒绝旧列表、同身份较新 GET 替换旧 GET 而独立元数据互不取消、JSON 解码中身份变化、修改请求不重发／不转移身份、超时／服务错误无重试且释放索引、页面销毁后的取消与禁止新请求。

管理菜单、盲注及权限专项共 **15 项通过**，日志 cache/admin-identity-scoped-node.log。Node 全量 **1347 项通过**，日志 cache/admin-identity-full-node.log，含生产副本剔除 test/cache 后的加载与 HTTP 检查。

扩展 test/browser/check-match-admin.mjs，新增 --proxy 和 --identity-check。在独立 Chrome profile、隔离 HTTP 服务和开发内存存储中执行：

```powershell
node test/browser/check-match-admin.mjs --proxy --identity-check
```

真实浏览器通过以下检查：

- 所有管理请求保持 /gogame-match/admin/v1 前缀；发布比赛、延迟报名及自动暂停状态展示、排期启停、门票创建和发放、盲注删除、安全文本渲染继续正常。
- 模拟旧列表迟到，即使测试网络替身忽略 AbortSignal，旧身份数据也不会重新出现。
- 身份切换时旧列表、资金详情和编辑器清空，点击保留的旧取消按钮不产生新请求。
- 管理凭证切换后，迟到元数据不能重建旧表单。
- 旧排期列表迟到后，不覆盖当前门票列表。

浏览器检查捕获的未处理异常为 0，日志 cache/admin-identity-proxy-browser.log；原独立路径浏览器流程也通过，日志 cache/admin-identity-browser.log。迟到网络场景使用隔离页面内的测试替身，其他管理流程使用实际隔离 HTTP 接口，不操作真实比赛或余额。截图保留在 test/browser/match-admin-*.png。
