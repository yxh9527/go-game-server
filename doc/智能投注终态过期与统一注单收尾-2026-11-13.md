## 问题与修复

原任务收尾只读 Redis 金融快照，查询失败还会读取 lottery_finance_rounds_archive。它没有即时检查终态一小时期限，可能在后台清理尚未执行时继续使用旧终态；归档已废止后，真正完成但尚未写回任务的结果也会因原快照已删除而无法确认。

现在收尾不再读取归档，Redis 故障明确失败，不把故障当作键不存在。SETTLED／VOIDED 按原 completedAt，EXPIRED 按原 expiresAt，旧终态缺字段时使用原 updatedAt；满 3600 秒视为不可读取，不等待后台物理清理。时间未知或不可信时保留原责任，BETTING 等活跃状态不按一小时误删。此操作不写或延长金融快照。

原快照不存在或终态已过期时，data-center 按既有最终注单文档 ID 规则 md5(agent|user|roundId)，直接读取 go_gp_settlement 中的原账户原局文档。不按余额变化、同时间记录、最近页或显示索引猜测，不扫描整库，不使用 init。单次 ES 请求最多 2 秒，原文限制 2 MiB。

确认必须同时满足：金融 complete=true，原代理、玩家、币种、金融 gameId、level 和 roundID 相符；下注、派奖及余额格式有效；log.completedDisplayReport 中的 taskId、attemptId、原局号、玩家、代理、币种、房间、roomType、净输赢和有效下注都与原任务执行及原注单金额一致。

确认后的任务统计仍在原 SQL 行锁事务中更新并停止，清除 activeAttempt／pendingInning。已有停止回执重试直接返回，不重复计入完成局数、累计下注或输赢。玩家余额、cash_revision、奖池和原下注均不修改，不恢复任务到另一实例继续下注。

## 保留边界

- 本轮 ES 收尾只接受已完成的非零净输赢。旧注单零盈亏可能表示正常和局或全额作废退款，没有足够信息区分时继续保留待确认责任，不能把退款记作有效下注或正常完成一局。
- 尚在期限内的原快照继续使用既有精确撤注／作废全退证据校验，不改变已确认退款规则。
- 缺少原执行登记、旧 executionProtocol、注单未写入、缺少任务引用、源身份不符或查询失败仍不能自动收尾，不补造结算或退款。
- 不新增 Redis 键、缓存、金融快照副本、永久归档、幂等流水或独立重启恢复任务；现金注单和详情仍分别是 go_gp_settlement 与 log。
- 本轮修复一类已完成责任的收尾，不代表执行实例丢失后的所有未知责任都已可恢复。
