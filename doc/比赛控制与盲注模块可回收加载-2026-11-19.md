# 比赛控制与盲注模块可回收加载

2026-11-19，Asia/Shanghai。继续处理游戏服比赛控制的热更新依赖，保留原牌桌、积分、检查点和资金职责。未重启服务、提交代码或操作真实余额。

## 修改

shared/hot-entry-factory.js 新增八个可回收业务模块，白名单由 149 扩至 157：

- game-server/src/core/tournament.js、tournament-blinds.js。
- shared/tournament-control.js、tournament-blinds.js、tournament-registration.js。
- shared/tournament-ranking.js、tournament-idempotency.js、tournament-snapshot.js。

比赛 matches、processId、nextRoomId、原 tables／clock／revision／reentries／最终通知仍保存在 runtime.tournamentRooms 和原桌对象。请求防重 entries／pending／原到期时间仍保存在 runtime.tournamentIdempotency，不创建第二份比赛或资金账户。

原请求缓存的 setInterval 回调在首个业务模块中创建，会让定时器与该版本的执行环境相连。新增 shared/tournament-dedup-timer.js 常驻辅助，由它的定时回调调用 state.sweep；业务替换只更新当前 sweep。既有旧格式定时器首次使用时关闭并迁移一次，不删除原 entries 或 pending，后续复用同一 timer。该辅助加入常驻名单，不计入可回收业务模块数量。

没有改动报名费／服务费、门票抵扣、复活、排名、暂停、派发或异常作废规则，没有新增资金流水、防重业务机制或 Redis key。只迁移原已有请求缓存定时回调的所有者，原一小时 TTL、命中不续期和未完成请求不并发重放仍保留。

## 跨版本验证

新增 test/shared/hot-tournament.test.js 九项，验证：

- 原生产开赛正在等待 getMatch 时，新控制器对同一请求继续等原 pending，不再查询或分配第二场比赛。
- 人工暂停仍等待原手牌及动画结束，原暂停起点、剩余盲注和晚报名延迟跨替换保留；旧／重复恢复不会再次增加窗口。
- 自动暂停点跨替换保留，只能在当前手牌及动画结束后恢复到下一正常级别，不重复触发。
- 同一 revision 检查点只推进一次；原最终奖励通知对象与确认摘要保留，重复不再通知，金额变更拒绝。
- 结束清理仍移除原比赛桌和索引，比赛积分不作为现金带出；没有创建现金钱包替身。
- 原一小时请求缓存、未完成任务及定时器跨替换复用，读取不延长原期限；旧定时器迁移一次，不误删原缓存或待完成任务。
- 原签名可由新模块验证，密钥错误／过期仍拒绝；同分按数值 UID 区分唯一名次，不平分。
- 中间模块和控制器释放后可以回收，同时原比赛、clock、table 与 timer 保留。

原比赛流程、盲注、晚报名、排名、防重缓存与回放持久化测试改用实际工厂入口，原断言保留；管理比赛／盲注回归同时运行。
