## 最终行为

- lottery 的新统一资金和旧游戏入口，注单直接通过 BulkRecordsSave 写 go_gp_settlement，完整对局详情继续在 log；原资金账变通过 BulkBillsSave 写 go_gp_flowing_water。
- 普通下注、撤注、派奖、整局作废退款、座位净额、真人庄家等原快照输出继续使用原固定身份和原余额，ES 确认成功后才更新原投递进度或 billStored。失败重试保存原文，不再扣款、退款、派奖或重新发牌。
- 旧游戏注单和账变沿现有有界输出通道、批量写入及失败批次重试直接投递 ES。新投注的报告可用性不再检查 MySQL 原文表，ES 未配置或原队列已满仍可拒绝新增工作。
- data-center 战绩、现金／比赛回放输出直接调用 ES，ES 未成功时返回失败。Node gateway 要求 indexed=true 和完整数量的原回执，不能把旧版本仅完成 SQL 备份的回执认作成功。
- ES create 返回同 ID 冲突时，读取 ES 原文并核对完整结果；同一原文重试可确认成功，内容改变、原文缺失或读取失败不能伪装成功。没有新建 SQL 冲突记录。
