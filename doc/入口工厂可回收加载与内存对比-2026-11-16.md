# 入口工厂可回收加载与内存对比

> 最新范围已扩大到 30 个模块，新增默认导出支持、游戏目录及 21 个游戏入口；本文件关于“不支持默认导出”和初始白名单的内容保留为当时实现记录，当前实现与验证见《游戏目录与默认导出可回收加载-2026-11-16.md》。

> 后续已将五个无状态依赖纳入白名单，当前默认范围为三个入口及五个依赖，Node 1311 项通过。下文数字保留为扩展前的历史实测；新编解码依赖变化场景及当前验证状态见《无状态依赖可回收加载与编解码验证-2026-11-16.md》。

本轮完成 hall、game-server、match 三个入口工厂的可回收加载路径。普通业务依赖继续使用原生 ESM，因此热更新旧模块完整回收仍未完成。

## 修改范围

新增 shared/hot-entry-factory.js，仅白名单内的 game-server/src/create-handler.js、hall/src/create-app.js、match/src/create-app.js 通过 vm.compileFunction 编译为普通异步工厂。不使用实验性 VM 模块，不要求常驻服务启用 --expose-gc；该参数只用于隔离测试取样。

shared/hot-import.js 在内容版本规范化后选择入口工厂加载器；其他模块沿用原生 import。源码中的 rel 依赖继续按 AST 绑定版本，旧请求保持原依赖。每个入口只强引用最新命名空间，旧版本只保留最多 256 个弱引用地址；正在使用的旧函数及入口自有依赖由正常引用维持生命期，释放后由 GC 回收。相同版本的并发加载合并，成功与失败后均释放 pending。

回收测试曾发现：把执行闭包放在缓存查找的异步作用域中，会间接保留上一次 active 模块，形成版本链。现已将执行作用域独立，300 次源码变化后验证中间旧命名空间及导出函数均可回收，同时主动保留的最早处理函数仍正常执行。

这是针对目前三份入口源码的受限转换，不是通用 ESM 编译器。当前入口静态导入的是稳定的第三方函数、内置函数及常驻加载器；普通业务通过版本绑定的动态加载取得。默认导出、export *、入口之间循环依赖及 import.meta.url 以外的元信息不支持，加载失败仍由原 watcher 保留旧处理器。后续改变这些入口的模块写法时，需要一起核对加载器支持范围。

新增 collectibleHotStats，只返回活跃入口、弱引用、待加载、编译成功与失败的数量，不暴露运行对象或敏感路径。hot-loader 将编译器及源码绑定辅助模块视作常驻加载基础设施。

## 完整入口副本对比

扩展 test/performance/hot-source-change-load.mjs：--entry=handler 会复制真实 57043 字节 create-handler.js，仅重定位依赖路径，并附加临时版本依赖，使每次版本变化都加载完整入口源码。原项目文件不修改，不碰常驻服务、数据库或下注；--loader=native / collectible 可重复比较两种加载方式。

这比此前只修改小型包装模块的测试更重，不能直接拿此前的 6.89 MiB 与本轮数字比较。两组分别顺序运行于独立进程，其他参数相同：

```powershell
node --expose-gc test/performance/hot-source-change-load.mjs --loader=native --entry=handler --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-handler-native-600.json
node --expose-gc test/performance/hot-source-change-load.mjs --loader=collectible --entry=handler --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-handler-collectible-600.json
```

| 项目 | 原生 ESM | 可回收入口 |
| --- | --- | --- |
| 成功源码变化／真实处理器重建 | 600 | 600 |
| 错误源码回退 | 24 | 24 |
| 持续连接 | 128 | 128 |
| 成功心跳 | 80000 | 80000 |
| 退出后的会话／捕获异常 | 0／0 | 0／0 |
| 堆增长 | 154634744 字节，147.47 MiB | 20732640 字节，19.77 MiB |
| 后 300 次的堆增长 | 73.83 MiB | 0.31 MiB |
| 退出后的堆 | 161.86 MiB | 34.05 MiB |
| 运行时间 | 21.87 秒 | 30.06 秒 |
| 事件循环 P99／最大延迟 | 83.23／94.11 ms | 111.67／128.19 ms |

本场景堆增长下降约 86.59%，后半程增长显著收敛；解析及编译入口增加了加载耗时和事件循环延迟，不能宣称性能各项都提升。缓存诊断显示可回收版本的活跃入口为 2（临时入口及其版本依赖），弱引用上限 256、pending 为 0；生产默认白名单是上述三份入口，临时文件只在测试实例中显式选择。

原始数据及日志为 cache/hot-handler-native-600.json／.log、cache/hot-handler-collectible-600.json／.log。没有对已运行的生产进程取堆快照，也没有证明任意业务依赖图变化都能回收；普通业务模块仍受 Node ESM 缓存约束。本次约 30 秒的隔离实测不能替代多日并发及八小时房间生命周期验收。
