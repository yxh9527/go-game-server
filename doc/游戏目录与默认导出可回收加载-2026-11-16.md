# 游戏目录与默认导出可回收加载

本轮补默认导出转换，将真实游戏目录和 21 个游戏入口加入可回收白名单。默认选择范围从 8 个模块扩大到 30 个；业务类、引擎、钱包与其余依赖继续使用原生 ESM，不能据此声称完整业务图已经回收。

## 修改范围

shared/hot-entry-factory.js 新增显式 collectibleGameEntryFiles：games/catalog.js，以及 holdem、baccarat、dragon-tiger、ggl-mjhl、ggl-queen、zjh、niuniu、sss、blackjack、sgay、mahjong、hundred-holdem、hundred-zjh、hundred-niuniu、hundred-blackjack、hundred-mahjong、arcade-bcbm、arcade-slwh、arcade-fqzs、arcade-mjzl、arcade-qwby 的 index.js。只加入已核对的入口，不按目录自动收纳业务文件，不恢复 Luck5。

默认表达式只计算一次并保留当时的值；具名默认函数／类导出其局部绑定；匿名函数、箭头函数、生成器及类保留原生 default 名称，类静态初始化期间也保持该名称。顶层 await、动态导入和 import.meta.url 仍经过原版本绑定与源码复核。默认包装插入与相邻导出共用边界时，先应用较长的编辑，避免破坏合法的无空白相邻声明。

这仍是受控白名单转换，export * 和入口循环不支持。新增入口只导入常驻 rel，再加载原游戏业务模块；没有把资金模块、RPC 连接或房间对象整体改走转换器。

目录继续按原顺序注册全部 21 个游戏和房间类型。相同内容版本必须复用默认游戏实例，尤其是五个街机入口自身执行 new TurntableGame(config) 的情况，不能在每次目录加载或每个请求中重新创建实例。

## 功能与回收验证

test/shared/hot-entry-factory.test.js 增加默认导出与原生模块的对照，覆盖 12 类写法，包括值快照、局部绑定别名、具名函数／类绑定更新、匿名名称、类静态初始化、异步函数、生成器、顶层 await、动态依赖、import.meta.url、表达式副作用和相邻声明。

增加 300 版本的默认游戏对象 GC 验证：释放中间包装模块后，旧命名空间、默认对象、构造器及方法可回收；主动保留的首个实例仍可使用。另复制真实奔驰宝马入口，连续变更 120 次并使用原 TurntableGame 与配置，验证已释放入口及真实默认实例可回收，保留实例的身份和房间类型正常。

这里有明确边界：五个街机入口自行创建的旧实例可以随包装模块释放；其余入口转发原生业务模块的默认值，而这些业务模块仍受 Node ESM 缓存持有。不能把包装模块回收等同于全部历史业务对象都能回收。

新增 test/game-server/hot-catalog.test.js，核对可回收目录与原路由一致、重复加载复用所有 21 个实例、德州 19／101 仍映射同一个游戏，未知房间类型返回空。生产副本烟测确认 30 个已选模块实际各编译一次，并继续检查真实剔除 test/cache 的产物可加载和处理 HTTP 请求。

## 真实目录变化与房间保留实测

test/performance/hot-source-change-load.mjs 新增 --entry=catalog：复制真实目录及完整游戏入口，只重定位路径并附加版本字段；每次实际改变目录源码，由真实 createHandler 重新加载目录。原游戏业务文件和常驻服务不修改。

测试在隔离进程加入一个德州房间、座位及手牌夹具，逐次核对房间／座位／手牌引用、积分、总下注、底池、局号及创建／到期时间。所有游戏实例应保持复用；钱包入口一旦被调用就失败，测试不执行真实带入、下注、结算或数据库操作。结束后清除该测试房间与全部套接字。

```powershell
node --expose-gc test/performance/hot-source-change-load.mjs --loader=collectible --entry=catalog --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-game-catalog-600.json
```

该场景比此前只改变编解码依赖更重，不能直接比较不同批次的堆增量作为改善比例。重载时源码图复核和转换仍有明显成本，P99 约 204 ms 必须如实保留；本次短时、无资金操作的隔离实测不能替代多日、全游戏下注流程或八小时生命周期验收。
