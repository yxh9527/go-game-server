# 无状态依赖可回收加载与编解码验证

本轮在三个入口工厂之外，将五个已核对的无状态依赖纳入可回收白名单。其他业务依赖仍使用原生 ESM，完整业务图回收和长期并发验收继续保持未完成。

## 本轮修改

shared/hot-entry-factory.js 增加 collectibleDependencyFiles，并与原 collectibleEntryFiles 合成 collectibleModuleFiles。默认选择三个入口及以下五个依赖，不按目录自动扩大范围：

| 文件 | 职责与核对结果 |
| --- | --- |
| game-server/src/codec.js | 通信编码／解码函数和大小常量，仅静态依赖内置 zlib |
| hall/src/decode.js | 大厅参数、数字、时间和布尔值转换函数 |
| hall/src/to-client.js | 大厅房间／比赛展示转换；静态函数依赖按内容版本加载，decode.js 同样走可回收路径 |
| match/src/admin-page.js | 比赛管理页面字符串；静态导入的表单模块也纳入同一加载路径 |
| match/src/admin-forms.js | 管理表单 HTML 和浏览器脚本字符串；字符串内的浏览器定时器不会在 Node 模块加载时执行 |

这些模块没有在加载时创建房间、资金责任、连接或 Node 定时任务。钱包、会话、RPC 连接及房间状态不纳入本轮白名单。旧处理器拥有的依赖继续按正常引用保留，释放后才能 GC；相同版本合并、弱引用上限 256、编译失败保留原处理器等沿用上一批实现。

test/game-server/codec.test.js 对原生和可回收两种加载结果运行同样的协议、截断／超长包、压缩包及解压大小保护检查。test/hall/to-client.test.js 改为实际通过可回收路径验证原展示转换行为。生产副本烟测核对三个入口及五个依赖共 8 个模块已实际加载，生产包仍剔除 test/cache。

test/shared/hot-entry-factory.test.js 增加依赖图 GC 验证：复制真实 codec.js，由父模块静态导入并调用其编解码函数，连续变更 120 次，逐次核对真实版本和通信结果；释放后，中间父模块、子模块命名空间及编解码函数均可回收，主动保留的最早处理器仍能按原版本工作。另增加真实编解码副本变化的心跳／错误回退子进程测试。

## 编解码依赖变化实测

test/performance/hot-source-change-load.mjs 新增 --entry=codec：复制完整真实游戏入口，并将其中编解码路径重定向到临时 codec.js 副本；每次改变这个真实副本的版本导出。心跳实际由重建处理器中该版本的编解码函数处理，而不是仅变更未参与请求的计数模块。原业务源码及常驻服务不修改，不连接数据库、不下注。

对照使用 --loader=entries，仅入口可回收、编解码依赖仍走原生 ESM；改后使用 --loader=collectible，两者都可回收。两组分别在独立进程顺序运行，避免把入口加载器差异混入本轮依赖对比。

```powershell
node --expose-gc test/performance/hot-source-change-load.mjs --loader=entries --entry=codec --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-codec-entries-600.json
node --expose-gc test/performance/hot-source-change-load.mjs --loader=collectible --entry=codec --revisions=600 --clients=128 --sample-every=50 --output=cache/hot-codec-collectible-600.json
```

| 项目 | 仅入口可回收 | 入口及编解码依赖可回收 |
| --- | --- | --- |
| 成功源码变化／处理器重建 | 600 | 600 |
| 故意错误并保留原处理器 | 24 | 24 |
| 持续连接／成功心跳 | 128／80000 | 128／80000 |
| 残余会话／捕获异常 | 0／0 | 0／0 |
| 堆增长 | 40916736 字节，39.02 MiB | 26155048 字节，24.94 MiB |
| 后 300 次的堆变化 | 增加 7.44 MiB | 减少 0.13 MiB |
| 退出后的堆 | 53.31 MiB | 39.21 MiB |
| 隔离运行时长 | 31.49 秒 | 30.65 秒 |
| 事件循环 P99／最大延迟 | 115.93／203.69 ms | 110.95／126.42 ms |

本场景堆增长减少约 36.08%。采样仍有 GC 波动，不能用一次端点差值证明所有负载均已稳定；延迟数字也只是本次隔离运行结果，不作为生产保证。原始数据和日志为 cache/hot-codec-entries-600.json／.log、cache/hot-codec-collectible-600.json／.log。

上一批的 147.47／19.77 MiB 来自不同场景：临时小版本依赖变化、完整入口重建；本轮额外改变实际参与心跳处理的编解码源码，两组入口均可回收。因此两批数字不应直接横向比较，也不能将减少比例累加。
