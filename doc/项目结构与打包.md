# 项目结构与打包

完整部署流程、最外层 nginx、生产配置及进程托管见 [部署文档](部署文档.md)；本篇说明目录职责和构建边界。

## 目录职责

| 目录 | 职责 | 生产包 |
| --- | --- | --- |
| hall/、game-server/、match/、client-web/ | 服务源代码；启动配置已集中到根目录 ecosystem.config.cjs | 保留 |
| shared/ | 正式 RPC 门面、生产实现与协议 | 保留 |
| static/ | 原始客户端、大厅和头像资源 | 保留，不修改 |
| test/ | 自动化测试，按服务归类；browser/ 为浏览器回归工具 | 排除 |
| cache/ | 开发用内存模拟、种子、钱包、回顾接口及页面补丁 | 排除 |
| scripts/ | build-prod.js 构建；prod.js 生产启动 | 只保留 prod.js |
| ecosystem.config.cjs | PM2 生产进程配置；四个应用 fork 单实例 | 保留 |
| doc/、tools/ | 文档和开发分析工具 | 排除 |

## 本地开发与测试

要求 Node.js 22.20 或更高版本；所有依赖仍安装在根目录。

~~~sh
npm install
npm run dev
npm test
npm test --workspace=game-server
~~~

test/run.js 递归发现测试文件，新增测试不必修改命令。生产业务不能静态依赖 cache，RpcAdapter 的同步接口在 dev 分支才加载本地类。服务启动器监听对应的本地页面补丁和回顾实现，业务热更新不清除常驻房间和余额状态。

admin/integrations/MatchManagement.vue 是接入外部平台／代理后台的 Vue 组件源文件，不参与 Node 服务生产包。scripts/build-admin-integration.mjs 准备现有两端菜单／页面／开发代理的 6 文件包，apply-admin-integration.mjs 校验哈希、备份及失败回滚后应用；该前端包与 Go 对接包分开。生产还需同源网关转发及沿原前端发布流程构建，使用 match 独立管理凭证。验证与应用状态见《比赛管理接入现有后台菜单-2026-11-17.md》。

2026-11-16：shared/hot-import.js 对 hall/src/create-app.js、game-server/src/create-handler.js、match/src/create-app.js 使用可回收入口工厂，并将 codec.js、大厅 decode.js／to-client.js、比赛 admin-page.js／admin-forms.js 五个已核对的无状态依赖纳入白名单；其余业务依赖继续原生 ESM。编译器与源码绑定辅助模块属于常驻加载基础设施；无需给服务添加实验性 VM 标志或 --expose-gc。实现范围、实测及未完成边界见《入口工厂可回收加载与内存对比-2026-11-16.md》和《无状态依赖可回收加载与编解码验证-2026-11-16.md》。源码改好不代表旧常驻加载器已自动升级，本轮未重启服务。

可回收模块在首次编译时复核源码及依赖图版本；源码已变化则返回 ERR_HOT_SOURCE_CHANGED，保留原处理器，不以当前磁盘内容冒充旧版本。并发依赖等待增加循环检测，缓存与等待图统一模块地址的参数顺序；详见《热更新版本一致性与并发依赖保护-2026-11-16.md》。此复核发生在重载时，会增加源码读取成本。

后续补默认导出支持，并将 games/catalog.js 和已核对的 21 个游戏 index.js 加入显式白名单，默认范围为 30 个模块。相同内容版本复用原游戏实例，房间、座位、手牌、筹码及生命周期时间仍保存在常驻 registry；业务类与引擎继续原生加载。生产副本烟测验证 30 个模块各编译一次，范围和限制见《游戏目录与默认导出可回收加载-2026-11-16.md》。

依赖检查在同一校验周期复用存在／不存在的结果，最多缓存 4096 条；新重载、环境变化、显式失效和源码复核均清空，仍每轮读取源码并核对哈希。实测与边界见《热更新依赖检查去重与重载开销优化-2026-11-16.md》，不将本机短时提速等同于全部旧 ESM 已回收。

默认白名单后续扩大为 54 个模块，新增 17 个具体游戏类和 7 个共享父类，保证所选子类与父类使用同一路径。原生配置静态导入与直接导入共用命名空间；引擎及资金模块仍保持原加载路径，房间／资金状态不迁移。生产副本验证 54 个模块各编译一次，完整范围及限制见《游戏主体类与共享父类可回收加载-2026-11-16.md》。

最新默认范围为 71 个模块，再加入 17 个引擎；常驻环境／RPC 模块统一移除 v、_hot_source、link，静态业务依赖只对有内容版本的模块继承 link，保证与启动代码共享常驻命名空间。生产副本验证 71 个模块各编译一次，范围、实测及延迟限制见《游戏引擎可回收加载与常驻配置一致性-2026-11-16.md》。

源码依赖绑定与入口转换后续改为共享原始 AST，并一次组装源码，避免解析生成后的 JavaScript 和反复拼接文本；没有减少源码版本复核或增加 AST 常驻缓存。实现、参数求值回归及延迟边界见《热更新共享语法树与源码组装优化-2026-11-16.md》。

## 生产构建与部署

2026-11-12：game-server 生产产物同时配置 finance.provider=lottery 并覆盖全部现金房间类型，启动时检查，避免仅 wallet.mode=online 却没有统一最终注单。刮刮乐沿原票务权威，比赛 101 不作现金结算。路由、finance_level 和已有在局资金提供方不能盲目切换，原始开发配置保持不变。详见《全游戏统一注单与历史查询修复-2026-11-12.md》。

~~~sh
npm run build:prod
cd dist/production
npm ci --omit=dev
npm run hall
npm run game-server
npm run match
npm run client-web
~~~

四个服务由进程管理器分别启动。构建包含 static，过滤 .git、日志、临时文件和任何测试文件。test/、cache/、mock-server/、tools/、doc/、node_modules 不进入产物。build-manifest.json 列出产物文件；重复构建仅覆盖由本构建器生成的 dist/production，不删除源文件。

四个服务配置统一维护在根目录 ecosystem.config.cjs：common 为公共依赖，services 为各服务配置，publicProduction/publicDevelopment 为浏览器地址，apps 为 PM2 进程定义。不再生成各服务 config.yaml。构建禁用产物的 env_development，生产配置使用 env: prod、wallet.mode: online，game-server 保留完整现金 finance 配置。部署前只修改产物的集中配置和必要的凭证来源。生产启动器强制 GOGAME_ENV=prod、IS_DEV=0；源根目录仍可用 npm run prod:hall 等对应命令。

生产数据获取、MySQL 读写和比赛事务统一走 gogames data-center；Node 配置仅保留 data_center 地址，不再需要 MySQL 连接配置，也不安装 mysql2。新存储接口需要配置 data_center_token 或环境变量 GOGAME_DATA_CENTER_TOKEN，data-center 同名环境变量设置相同凭证；未配置时明确失败，不回退本地模拟。原有鉴权和 ES 回顾仍沿用现有 data-center 协议。

Node 变更必须与 doc/待应用/data-center 中的 Go 协议、服务注册及表结构配套应用，再按原流程迁移真实数据库。当前自动审批阻止外部文件写入，Go overlay 测试通过不表示 gogames 已更新；不要单独部署本仓库产物。完整应用步骤和正式资金接口限制见 doc/数据中心存取迁移.md。

正式房间、排名、旁观状态和 Redis 回顾缓存属于生产逻辑，不放 cache。生产牌局回顾继续走 data-center；此次整理不新增尚未接通的生产回顾协议。

.npmignore、.dockerignore、.gitattributes 也排除 test/cache，但它们不能替代生产环境配置转换；正式部署使用 build:prod 的产物。测试和本地实现仍提交 Git。

## 验证
