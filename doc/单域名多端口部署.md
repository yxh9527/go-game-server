# 单域名或单 IP、多端口部署

最外层 nginx、生产构建、PM2 和完整验证步骤统一见 [部署文档](部署文档.md)。所有配置已集中到 [ecosystem.config.cjs](../ecosystem.config.cjs)，各服务不再默认读取 YAML。

## 开发机直接访问

在集中配置的 publicDevelopment 修改：

```js
const publicDevelopment = {
  hall_url: 'http://172.21.211.216:11042',
  client_url: 'http://172.21.211.216:4000',
  game_ws_url: 'ws://172.21.211.216:11041',
  hundred_ws_url: 'ws://172.21.211.216:11041/hundred',
};
```

地址替换为实际开发机 IP。使用 npm run dev；服务内部端口分别在 services.hall、services['client-web']、services['game-server']、services.match 修改。公共 Redis、data-center、lottery 在 common 中维护。

```text
http://172.21.211.216:11042/21/0?userId=10001&userToken=dev&openId=10001&v=2.0.1279
```

浏览器只使用同一个 IP，不需要 hosts。iframe 加载 4000，API 走 11042，WebSocket 走 11041 和 /hundred。该开发模式使用内存模拟，不验证真实生产资金。

## 经过最外层 nginx

测试 nginx 可分别监听 10031、10032、10033，转发到 hall:11042、client-web:4000、game-server:11041。集中配置的 publicDevelopment 改为 nginx 的 IP 和上述公开端口，内部 Node 端口不变。模板见 [nginx-test.conf](deploy/nginx-test.conf)。

线上只需同一个域名，集中配置修改 publicProduction：大厅 https 默认 443、资源 https:8444、游戏 wss:8445。TLS 由最外层 nginx 提供；正式模板见 [nginx-production.conf](deploy/nginx-production.conf)。

## client-web 自动多进程

```js
'client-web': {
  server_ip: '0.0.0.0',
  client_web_port: 4000,
  client_web_workers: 'auto',
},
```

一次启动自动创建 worker，共用 4000，不需手动开多个服务或在 nginx 列出 4001 等端口。auto 最多 4 个 worker，也可填 1～64，1 为单进程；PM2 管一个 fork 主进程即可。每个 worker 保留业务热更新，异常退出会补位，连续快速失败有上限，退出会排空请求并关闭 worker。

## 配置生效

集中配置在启动时读取；PM2 将完整配置快照传给对应服务，worker 继承快照。配置变更不自动重启，维护窗口用 ecosystem 文件更新受影响进程并 pm2 save。业务 JS 依然热更新，不得通过重启进程代替，game-server 的房间/连接不会自动迁移。新地址生效后刷新页面，避免缓存旧 _app 脚本。
