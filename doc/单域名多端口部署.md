# 单域名或单 IP、多端口部署

保留 Node hall、client-web、game-server、match。不需要新增服务、不需要静态生成命令。

## 当前测试配置

当前开发机 IP 为 172.21.211.216，hall/config.yaml 已配置：

```yaml
server_ip: 0.0.0.0
server_port: 11042
client_web_port: 4000
# Node 内部连接，保持 hall 与 game-server 的实际网络地址。
game_server: 127.0.0.1:11041
hundred_server: 127.0.0.1:11041
public:
  hall_url: http://172.21.211.216:11042
  client_url: http://172.21.211.216:4000
  game_ws_url: ws://172.21.211.216:11041
  hundred_ws_url: ws://172.21.211.216:11041/hundred
```

保留文件中其他 Redis、wallet、data_center 等字段。hall_url/client_url 不带路径；游戏资源版本由大厅自动拼接。两条游戏连接使用不同路径，避免原生客户端把百人连接与主连接当作同一端点；game-server 已接受任意路径的 WebSocket 升级。

在项目根目录使用现有启动方式 npm run dev，或通过进程管理器分别运行 npm run match、npm run game-server、npm run client-web、npm run hall。不要重复启动已有进程。

浏览器入口：

```text
http://172.21.211.216:11042/21/0?userId=10001&userToken=dev&openId=10001&v=2.0.1279
```

只访问一个 IP，不需要 hosts。浏览器加载 iframe 时使用 4000，进房连接使用 11041；游戏内 HTTP API 请求使用 hall 的 11042，hall 保留现有跨源响应处理。

如果服务不在当前开发机，替换 public 中的 IP；确保浏览器能访问 11042、4000、11041。若 hall 和 game-server 不在同机，还要修改内部 game_server/hundred_server。

## 配置生效与回退

这些 YAML 字段沿用当前启动配置的加载方式，在服务启动时读取。业务代码依然热更新，不因地址修改而自动重启进程。更改已启动服务的配置，应在部署窗口按现有配置发布流程处理，不能把进程重启当作业务热更新；没有自动加入新的进程或配置监听。

已打开的大厅页面应禁用缓存刷新，确认 _app JS 由新版 hall 提供。client-web 首页按请求注入端点桥接，所有游戏适配仍按原方式执行。配置 public.client_url 后不再推导 www.*；未配置 public 时兼容原有路径和域名推导。

## client-web 自动多进程

hall/config.yaml 中设置：

```yaml
client_web_port: 4000
client_web_workers: auto
```

执行一次 npm run client-web 即可自动运行多个工作进程。npm run dev 和生产启动器也使用同一启动逻辑，无需手动开多个终端，也无需为这些进程新增 nginx 分流配置。

auto 按可用 CPU 数选择，最多启动 4 个 worker；也可填 1～64 的整数。填 1 时直接使用单进程。多进程模式还有一个负责分发连接与管理生命周期的主进程，主进程不执行业务。所有 worker 共用 client_web_port，public.client_url 保持一个地址。

每个 worker 独立监听业务源码变更并执行原有热更新；不会因为业务热更新替换整个 worker。worker 异常退出后主进程延迟补位；同一位置连续快速启动失败 5 次会停止整个服务并返回失败，避免端口占用或配置错误时无限重启。

终止主进程时通知所有 worker 停止接收新请求，等待已有 HTTP 请求完成，最长约 10 秒后关闭剩余连接。worker 检测到主进程 IPC 断开也会退出，避免残留后台进程。进程数和端口仍是启动配置，修改后按正常部署流程生效。

多进程共用原 static 目录；每个 worker 都有自己的内存和脚本适配缓存，因此更多进程会增加内存占用，不保证 QPS 按进程数等比例增长。

## 上线使用一个域名

只需将同一个域名解析到服务器，例如 game.example.com。三个入口可以是：

```yaml
public:
  hall_url: https://game.example.com:8443
  client_url: https://game.example.com:8444
  game_ws_url: wss://game.example.com:8445
  hundred_ws_url: wss://game.example.com:8445/hundred
```

example.com 为示例，替换成实际域名。三个端口由 nginx 做 TLS 终止并转发至原有 Node 服务；Node 监听端口不必变更。使用同一域名的证书即可，不需要三个域名。Node 本身仍提供 HTTP/WS，不会因为填写 https/wss 自动启用 TLS。

以下内容放进 nginx 现有 http 块内，证书路径、上游地址需按实际环境替换：

```nginx
map $http_upgrade $game_connection {
    default upgrade;
    '' close;
}

server {
    listen 8443 ssl;
    server_name game.example.com;
    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:11042;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

server {
    listen 8444 ssl;
    server_name game.example.com;
    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 8445 ssl;
    server_name game.example.com;
    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:11041;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $game_connection;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_buffering off;
    }
}
```

nginx 与 Node 跨机器时，将上面 127.0.0.1 改成 Node 的内网 IP。在部署机执行 nginx -t 成功后再 nginx -s reload。正式环境保留真实登录和生产 RPC 配置，使用 env: prod，不使用开发凭证。

## 验证

测试环境大厅应加载 172.21.211.216:4000 的 iframe；进房 WebSocket 地址为 ws://172.21.211.216:11041/，百人连接为 /hundred，握手返回 101；游戏 HTTP API 指向 172.21.211.216:11042/api/internal/v1/do。

上线后浏览器应该只出现 game.example.com 这个主机名，各端口按上述配置区分。线上 TLS 与实际进房需在部署环境验证。
